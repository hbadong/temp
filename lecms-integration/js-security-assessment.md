# 前端 JS 暴露面安全评估与处置报告

> 评估日期：2026-10-25（第二十四轮补丁）
> 问题：「JS 文件在前端显示，会不会暴露该网站系统的核心功能和算法？」

---

## 一、结论（先说答案）

**会暴露——而且是全量暴露。** 本系统的起名算法、字库数据、SEO 策略全部以前端明文 JS 交付，任何访客按 F12 或一条 curl 即可完整获取。**但这不属于「漏洞」，而是纯前端架构的固有属性**：浏览器必须拿到代码才能运行，客观上无法对运行代码保密。已落实的处置是把「可读性」降到最低并阻断源码直读；若要根治需将核心算法服务端化（第五节 L3 方案）。

## 二、实测暴露清单（2026-10-25 线上验证）

| 暴露物 | 位置 | 暴露程度 |
|---|---|---|
| `curl /view/haoiming/js/data.7.js` → HTTP 200 134KB | 字库全量数据 | **完全明文**：704 字（拼音/康熙笔画/五行/吉凶/热度/名字含义）+ 121 姓氏 + 133 成语用字 + 全部寓意文案 |
| `engine.7.js`（110KB） | 起名引擎 | **完全明文 + 131 处注释**：节气表 `JIEQI_TABLE`（八字精确排盘核心数据）、日主强弱模型、五格算法 `wuge()`、音律平仄、谐音黑名单（65 条）、生肖宜忌、热度权重、各模式生成器（八字/诗词/周易/成语/小名/双胞胎） |
| `main.7.js`（198KB） | 全站交互 | **完全明文 + 135 处注释**：21 个页面 init 函数、评分报告逻辑、SEO 策略细节（canonical 集中规则、TDK 公式、noindex 判定条件——**运营策略也可见**） |
| `shuowen.7.js`（147KB） | 说文解字数据 | 完全明文（9833 字头释义） |

**未暴露（已验证）**：数据库密码/加密 KEY（PHP 侧 `config.inc.php`，无 URL 映射）、后台入口逻辑、用户数据、PHP 服务端代码。JS 内无密钥/token/内部地址（唯一命中项 `127.0.0.1|localhost` 正则是正常的本地环境判断代码）。

## 三、风险评级

| 场景 | 等级 | 分析 |
|---|---|---|
| 竞品克隆算法/功能 | **中低** | 抄走代码≠能运营：起名站的核心资产是内容沉淀、收录权重与用户信任，不是算法本身；且整套系统依赖预渲染管线等配套，单独抄 JS 得不到完整能力 |
| 字库/热度数据批量采集 | **中** | 一条 curl 即得全量结构化数据。缓释因素：热度与笔画数据源自公开竞品（卜易居等）非原创；**真正原创的是 755 条四字格言寓意文案与引擎权重逻辑** |
| 恶意利用/攻击 | **低** | 前端无注入面：JS 只读公开数据、不持有任何凭据；用户输入在 PHP 侧有转义（本轮已修降级分支 XSS） |
| 源码直读（未压缩版） | **中** | 源文件 `.7.js` 与压缩版同在 web 根，直读源码可读性极高 → **本轮已处置** |

## 四、已落实处置（L1：压缩混淆 + 源码禁读）

`scripts/minify_js.sh` 一键流水线（terser 5.51）：

| 文件 | 压缩前 | 压缩后 | 降幅 |
|---|---|---|---|
| engine.7.js | 110,679B | 67,921B | **-39%** |
| main.7.js | 197,692B | 145,874B | **-27%** |
| data.7.js | 134,279B | 125,332B | -7%（纯数据，压缩率低属正常） |
| shuowen.7.js | 146,993B | 141,715B | -4%（同上） |

配套措施：
1. **全站 29 个页面引用切换**到 `.min.7.js`（新文件名天然隔离旧缓存，无版本号冲突）
2. **不上传 source map**：`.map` 会还原源码，等于白压缩
3. **生产 Nginx 禁源文件**：`location ~* /view/haoiming/js/(data|shuowen|engine|main|dict)\.7\.js$ { deny all; }`——未压缩源文件只存在于 git 与开发环境
4. **验收脚本已含**：`deploy_check.sh` 检查「源文件 403 + min 文件 200」
5. 验证：node 语法+全局挂载校验、verify_m2（JS 错误 0）、E2E 五项、verify_seo 全量、Lighthouse Performance **97**、总传输 292→264KiB

**L1 的效果边界**：挡住「随手看看」和普通采集者；挡不住专业逆向（压缩代码可被 beautify 还原逻辑结构，变量名可被推断）。这是 industry standard 做法（React/Vue 源码同样可读），不是根解法。

## 五、未落实的分层选项（如需升级）

| 方案 | 做法 | 工作量 | 效果 | 副作用 |
|---|---|---|---|---|
| **L2 数据接口化** | `data.7.js` 改为按需 API（分页/按字查询），前端用后即弃 | 2-3 天 | 采集成本大幅上升（需逐字请求） | 与「静态直链 SEO」策略冲突；工具页首屏渲染延迟；预渲染需等接口 |
| **L3 算法服务端化** | 起名引擎移植为 PHP API（`api/name.php`），前端只传参数收结果 | 5-7 天（111KB 算法移植+接口+回归） | **根治算法泄露**；顺带获得服务端限流/防刷 | 预渲染 Chromium 需调 API（架构兼容但需改造）；PHP 性能要求上升；SEO 无影响 |
| **L4 强混淆** | javascript-obfuscator（控制流平坦化/字符串加密） | 1 天 | 逆向成本高一个量级 | 体积膨胀 2-5 倍、运行时开销、可能触发杀软误报——**性价比最低，不建议** |

**建议路径**：维持 L1 现状；若未来出现真实抄袭/恶意采集证据，再启动 L2/L3。依据：本系统的原创核心（755 条寓意文案、引擎权重）靠抄站无法完整复刻，且内容与收录权重才是起名站的真正护城河。
