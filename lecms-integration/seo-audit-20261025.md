# 好名网 SEO 布局审计报告

**审计日期**：2026-10-25
**审计对象**：好名网智能起名系统（本地环境 127.0.0.1:8090，生产域名 ad6acb5cb3aeb83e6.app.workbuddy.link）
**审计方法**：Lighthouse 12.8.2（SEO/最佳实践/性能三类目，3 个代表页面）+ 爬虫 UA 预渲染验证（Baiduspider，50 个落地页 TDK 扫描）+ 源码与配置检查 + sitemap/robots 分析
**口径说明**：所有 TDK 唯一性数据基于爬虫 UA 实际响应（预渲染后 HTML）；性能数据为本地 http 实验室环境（PHP 内置服务器，无 gzip/缓存），生产环境数值会优于此，但问题项真实存在

## 一、Verdict（总体判断）

**站点 SEO 基础布局健康，处于「优良」档位，但有 1 个必须立即修复的配置事故和 1 个高优先级抓取浪费问题。**

- **好的部分**：Lighthouse SEO 三页全部 100 分；动态落地页（704 单字页）TDK 经预渲染对爬虫完全动态化且 20/20 样本唯一；矩阵页 canonical 权重集中设计正确；内链网络（单字页 35 出口/页）成型；sitemap 1477 URL 抽查 18/18 可访问。
- **头号问题**：`robots.txt` 声明了一个包含 **7131 个外站 URL**（qiming.cn）的 sitemap-dict.xml——这是早期竞品采集的遗留物，会直接损害本站 sitemap 在搜索引擎眼中的可信度，属于配置事故，必须今天处理。
- **次优先级**：`char.html?c=任意无效字符` 返回 HTTP 200 并生成「XX字寓意」页面（软 404），给爬虫开放了无限 URL 空间。

## 三、问题清单与修法（按严重度分级）

### Critical（立即修复）

#### C1. robots.txt 声明外站 sitemap（sitemap-dict.xml）
- **现象**：`robots.txt` 含 `Sitemap: https://.../sitemap-dict.xml`，该文件 7131 个 `<loc>` 全部指向 `https://www.qiming.cn/...`（竞品域名）。
- **影响**：搜索引擎抓取后判定 sitemap 含外站 URL，整份 sitemap 的可信度受损；同时暴露竞品采集痕迹，存在不必要的法务/合规敞口；浪费搜索引擎对本站 sitemap 的信任额度。
- **证据**：`curl robots.txt` + `curl sitemap-dict.xml | head`；文件生成于 10-23（早期竞品分析阶段，生成脚本 scripts/dict_gen.py）。
- **修法**：
  1. 从 `robots.txt` 删除第二行 Sitemap 声明（只保留 sitemap.xml）；
  2. 将 `sitemap-dict.xml` 移出 web 根目录（如移到 `/var/www/lecms/storage/` 或直接删除——内容为竞品 URL 列表，对本站无价值）；
  3. 如该文件曾有内部分析用途，在脚本目录保留副本，不暴露在公网。

### High（本周修复）

#### H1. 软 404：无效字符生成 200 页面
- **现象**：`char.html?c=ZZ`（或任意非汉字/未收录字符串）返回 HTTP 200，标题为「ZZ字寓意_ZZ字起名含义、五行属性与康熙笔画」。
- **影响**：URL 空间无限（?c= 可填任意值），爬虫遍历会抓取海量低质/重复页面，浪费抓取配额、稀释站点质量信号；百度对软 404 敏感。
- **修法**：char.html 的 JS 渲染分支中，当 `c` 不在 `HM_DATA.CHARS`（且不在 IDIOM_CHARS）时：① 保留 HTTP 200 但注入 `<meta name="robots" content="noindex">`，或 ② 更彻底——服务端/prerender 层对未收录 c 返回真 404。推荐方案①（实现最小，预渲染层改 JS 即可）。

#### H2. 静态资源零缓存 + 无文本压缩
- **现象**：22 个静态资源无 Cache-Control/ETag；gzip/br 未启用（首页 584 KiB 可省）。
- **影响**：爬虫每次抓取重新下载 427 KB JS；真实用户 LCP 受损（本地实测 6.4s）；带宽浪费。
- **修法**（生产 nginx，本地 PHP -S 是环境限制）：
  ```nginx
  location ~* \.(js|css|woff2?)$ {
      expires 30d;
      add_header Cache-Control "public, immutable";
  }
  gzip on;
  gzip_types text/css application/javascript application/json;
  ```
  data.7.js 等内容型资源可用 `expires 7d` + 版本号已具备（?v=20261025b）双重保障。

### Medium（本迭代修复）

#### M1. 落地页群缺乏核心入口内链
- **现象**：search/kxzd/naming/baijiaxing 等工具页 0 个 char/surname 落地页链接；首页导航仅 14 个工具页。全站 95% 的 URL（1400+ 落地页）只能经 sitemap + 页间互链被发现。
- **影响**：sitemap 传递的权重远低于内链；落地页收录速度与排名能力受限；爬虫发现深度依赖单一通道。
- **修法**：
  1. `kxzd.html`（康熙字典页）增加「常用起名字 A-Z/热度索引」区块，直链 char.html?c=X；
  2. `search.html` 增加「热门起名用字 Top 50」快捷入口；
  3. 首页增加「热门起名用字」模块（取字库热度 Top 30，直链单字页）；
  4. `surname.html` 主页（?c=X）增加「X姓×五行」矩阵内链（已有内容，补足显式链接）。

#### M2. 渲染阻塞资源 3.68s
- **现象**：CSS/JS 同步阻塞渲染（Lighthouse：Eliminate render-blocking resources，可省 3,680ms）。
- **修法**：非关键 JS 加 `defer`；工具页 CSS 评估关键 CSS 内联（首屏 <14KB）；main.7.js（188KB）按页面拆分为工具页公共包 + 按需模块。

#### M3. 安全响应头缺失
- **现象**：X-Frame-Options / X-Content-Type-Options / Referrer-Policy / CSP 均未设置。
- **影响**：非直接排名因素，但属搜索引擎评估的站点质量信号（Best Practices），且防点击劫持。
- **修法**：nginx 统一加 `add_header X-Content-Type-Options "nosniff"; add_header X-Frame-Options "SAMEORIGIN"; add_header Referrer-Policy "strict-origin-when-cross-origin";`（CSP 需评估内联脚本后配置）。

#### M4. 矩阵页 TDK 重复 + sitemap 提交非规范 URL
- **现象**：605 个 `surname.html?c=X&wx=Y` 与 121 个 `surname.html?c=X` 的 title/desc 完全相同（canonical 已正确指向主页，权重不受影响）；JS 中本有差异化 TDK 分支（`${c}姓五行属${wx}的名字_${c}姓五行缺${wx}怎么取名`，main.7.js:1831）但预渲染未执行到。
- **影响**：canonical 机制下矩阵页不会在搜索独立展示（设计自洽），但：① sitemap 提交 605 个 canonical 到别处的 URL，消耗抓取配额；② 社交分享/站内展示时矩阵页摘要无区分度。
- **修法**：
  1. 排查 main.7.js:1831 分支未生效原因（渲染时机或条件），使矩阵页获得差异化 TDK（title 差异化不影响 canonical 集中的权重）；
  2. 或从 sitemap 只提交 121 个姓氏主页（矩阵页保留内链发现）——与 C1 的 sitemap 精简一并做。

#### M5. 参数顺序变体未规范化
- **现象**：`?wx=木&c=王` 与 `?c=王&wx=木` 均返回 200 且内容相同；prerender canonical 剥离追踪参数但不重排参数顺序。
- **影响**：外链参数顺序不一致时产生重复内容入口（canonical 会指向其中一种顺序，另一种被吸收，风险有限但存在）。
- **修法**：char/surname 页 JS 启动时把 URL 参数规范化为固定顺序（`location.replace` 或 history.replaceState + canonical 输出标准序）。

### Low（排期优化）

#### L1. 结构化数据（JSON-LD）缺失
- **现象**：全站 0 处 JSON-LD。
- **机会**：工具页加 `WebApplication`（起名工具，含 offers/aggregateRating 需真实数据支撑）、`FAQPage`（faq.html 已有问答内容）、`BreadcrumbList`（落地页面包屑）；单字页可加 `DefinedTerm`（汉字释义，schema.org 原生支持）。
- **注意**：只标注页面上真实存在的内容，不虚构评分。

#### L2. JS/CSS 未压缩与未使用代码
- **现象**：JS 可省 62 KiB、CSS 可省 14 KiB；未使用 CSS 64 KiB、JS 140 KiB。
- **修法**：构建期加 terser + 按页面裁剪；data.7.js（131KB）可评估按五行分包懒加载（字库按用户喜用神只加载对应五行段）。

## 四、结构亮点（已验证，保持）

1. **动态 TDK 预渲染管线**：704 个单字页经 prerender 对爬虫 UA 返回完全动态的 title/description（「X字寓意_…」+「详解「X」字的拼音部首、康熙笔画、五行属性与起名寓意…」），这是本站 SEO 布局最核心的资产。
2. **canonical 权重集中**：矩阵页 canonical 剥离 wx 指向姓氏主页，设计正确。
3. **落地页互链网络**：单字页 35 个相关字出口（同音/同部首/同笔画/同五行），支撑爬虫遍历。
4. **OG 卡片动态化**：og:title 跟随页面 title。
5. **技术底座**：lang/charset/viewport/h1 唯一/404 控制台零错误全部达标。

## 六、所用窗口与阈值口径

- TDK 唯一性：sitemap 分层随机抽样（单字 20 + 姓氏 20，seed=42），以爬虫 UA 预渲染响应为准

- 对比基线：v9 字库扩充后状态（字库 704、sitemap 1477）
- 缺失数据（不影响本报告结论，但影响收录/排名判断）：无 Search Console 收录/点击数据、无分析工具流量数据、无外链数据——实际收录率与关键词表现需接入数据后另行评估
