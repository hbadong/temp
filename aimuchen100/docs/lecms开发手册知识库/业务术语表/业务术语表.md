# LECMS 业务术语表（v2.0，30+ 条）

> 本表覆盖 LECMS 框架、业务、插件、主题、部署五大领域的核心术语。
> 阅读主知识库前先扫一遍本文档，避免概念混淆。

---

## A. 框架核心

### A1. runcache
- **定义**：LECMS 的编译缓存目录，存放模板、语言包、控制器的编译后 PHP 文件
- **路径**：`runcache/`
- **子目录**：`lecms_control/`、`admin_control/`、`lecms_model/`、`lecms_view/`、`admin_view/`、`core_lang/`、`lang/`、`cache/`、`runtime_cache/`
- **别名**：运行缓存、编译缓存
- **风险**：开发时修改源码或模板后**必须**清理对应子目录才能生效，是 LECMS 开发中最容易踩坑的地方

### A2. _lecms.php
- **定义**：框架核心类合并文件，位于 `runcache/_lecms.php`
- **生成**：DEBUG=0 时由框架把 11 个核心 lib/db/cache/network 文件通过 `php_strip_whitespace()` 合并生成
- **作用**：减少生产环境 IO；只首次访问或 DEBUG 切换时生成
- **注意**：修改 `lecms/xiunophp/lib/*.php` 等核心文件后必须删除此文件让框架重新生成

### A3. APP_NAME
- **定义**：当前应用标识，区分前台（lecms）与后台（admin）
- **影响**：`RUNTIME_MODEL = runcache/{APP_NAME}_model/`、`RUNTIME_CONTROL = runcache/{APP_NAME}_control/`
- **机制**：前台入口 `index.php` 不定义 `F_APP_NAME`，后台入口 `admin/index.php` 定义 `F_APP_NAME='admin'` 以读取 `debug_admin` 配置

### A4. F_APP_NAME
- **定义**：后台应用标识常量，仅在 `admin/index.php` 定义
- **作用**：xiunophp.php 据此判断用 `debug_admin` 还是 `debug`

### A5. DEBUG
- **取值**：
  - `0` — 生产模式（使用 runcache 缓存）
  - `1` — 调试模式（每次重新编译 + 显示调试信息）
  - `2` — 开发调试（额外显示完整 debug 面板）
- **风险**：DEBUG>0 会暴露绝对路径和表前缀，线上必须为 0

### A6. CODE_COMPRESS
- **定义**：模板输出压缩开关，在 `index.php` 顶部 `define('CODE_COMPRESS', 0/1)`
- **要求**：必须配合规范的 HTML/JS 代码使用，否则会出错
- **生效**：仅 DEBUG=0 时压缩（去除换行、合并连续空格）

### A7. IS_AJAX
- **定义**：判断当前请求是否为 AJAX 请求的常量
- **依据**：HTTP_X_REQUESTED_WITH === 'xmlhttprequest' 或带 `?ajax=xxx` 参数
- **用途**：DEBUG=2 时跳过调试面板输出

### A8. HTTP
- **定义**：当前协议前缀（`http://` 或 `https://`）
- **来源**：`core::http()` 自动判断

### A9. ROOT_PATH / APP_PATH / FRAMEWORK_PATH
- `ROOT_PATH`：网站根目录（带末尾 /）
- `APP_PATH`：应用目录（`ROOT_PATH + APP_NAME + '/'`）
- `FRAMEWORK_PATH`：框架目录（`APP_PATH + xiunophp/'`）

### A10. CONFIG_PATH / CONTROL_PATH / MODEL_PATH / VIEW_PATH / BLOCK_PATH / PLUGIN_PATH / LANG_PATH / LOG_PATH / RUNTIME_PATH
- **定义**：九个绝对路径常量，由 xiunophp.php 在启动时统一声明
- **用途**：业务代码用 `$this->view->display(VIEW_PATH.$theme.'/xxx.htm')` 等方式访问

### A11. core
- **定义**：框架核心类，位于 `lecms/xiunophp/lib/core.class.php`
- **职责**：启动流程（`init_start`）、自动加载、URL 解析、控制器调度、插件钩子注入
- **方法**：`init_start`、`open_ob_start`、`init_set`、`init_misc`、`init_lang`、`init_get`、`init_control`、`init_control`、`model`、`get_original_file`、`get_plugins`、`process_hook`、`process_all`、`process_extends`

### A12. control
- **定义**：控制器基类，位于 `lecms/xiunophp/lib/control.class.php`
- **特殊方法**：`__get` 懒加载（`$this->db` / `$this->{model}`）、`assign / assign_value / display / message`

### A13. model
- **定义**：模型基类，位于 `lecms/xiunophp/lib/model.class.php`
- **封装**：CRUD（create/get/set/update/delete）+ find_fetch 系列 + 二级缓存（cache_db_*）
- **三必填属性**：`$table`、`$pri`、`$maxid`

### A14. view
- **定义**：视图类，位于 `lecms/xiunophp/lib/view.class.php`
- **职责**：模板 9 步编译、block/loop/if 标签解析、变量绑定、HTML 压缩
- **缓存**：`runcache/{APP_NAME}_view/{theme},{file}.php`

### A15. debug
- **定义**：调试类，位于 `lecms/xiunophp/lib/debug.class.php`
- **职责**：`error_handler`、`exception_handler`、`shutdown_handler`、底部调试面板

### A16. log
- **定义**：日志类，位于 `lecms/xiunophp/lib/log.class.php`
- **方法**：`log::write($msg, $file)`、`log::le_log($data, $file)`（仅 DEBUG=1）
- **格式**：所有日志行 `<?php exit; ?>` 开头防止直接访问

## B. 模板与主题

### B1. hook
- **定义**：LECMS 的插件扩展机制，通过在核心代码中预留 `// hook xxx.php` 注释作为挂载点
- **编译时机**：编译期合并插件同名文件到缓存文件
- **查找顺序**：按 `plugin.inc.php` 中 `rank` 升序合并（rank 越大优先级越低 → 先合并）
- **多文件**：插件的 `plugin/{p}/xxx.php` 与 `plugin/{p}/hook/xxx.php` 都生效
- **别名**：钩子、插件钩子

### B2. block
- **定义**：模板数据标签系统，位于 `lecms/block/`
- **文件**：`block_xxx.lib.php` 提供函数 `function block_xxx($config)`
- **两类**：
  - 普通 block → 数据放 `$data`
  - `global_` 前缀 → 数据放 `$gdata`，提升到模板头部（适合页头共用）
- **缓存**：支持 `life` 参数（秒数）
- **别名**：数据标签、模板标签

### B3. 主题
- **定义**：前台模板集合，位于 `view/` 目录下每个子目录
- **当前项目主题**：`game`（默认）、`game955`、`game955m`、`macfkm`
- **元数据**：每个主题根目录必须有 `info.ini`（name/brief/version/update/author）
- **切换机制**：通过后台设置页修改 `cfg.theme` 字段，存 `kv_model` + 清 `runtime->delete('cfg')`
- **别名**：模板主题、view 主题

### B4. inc 模板
- **定义**：可复用模板片段，命名约定 `inc-xxx.htm`（如 `inc-header.htm`、`inc-footer.htm`）
- **引用**：模板内 `{inc:header.htm}` 或 `{inc:user/login.htm}`

### B5. 模板编译缓存
- **文件**：`runcache/{APP_NAME}_view/{theme},{filename}.php`
- **生成**：DEBUG=1 时每次重编译，DEBUG=0 时首次访问生成
- **失效时机**：源码 `view/{theme}/*.htm` 修改后需要清缓存

### B6. 模板变量
- `$cfg` — 全站配置（来自 `runtime->xget('cfg')`）
- `$cfg_var` — 当前页变量（标题、面包屑等）
- `$data` — 当前 block 数据（数组）
- `$gdata` — 全局 block 数据（页面顶部已计算）
- `$_user` / `$_uid` / `$_group` / `$_author` — 用户相关
- `$theme_path` — 当前主题 web 路径
- `$base_url` — 站点基础 URL
- `{$v[url]}` / `{$v[subject]}` — 列表循环字段

## C. 路由与 URL

### C1. 伪静态
- **定义**：URL 重写功能，通过 `lecms_parseurl` 配置项控制
- **默认**：`lecms_parseurl=1`（开启）
- **关闭后**：`index.php?u=cate-index-cid-5.html`
- **开启后**：实际依赖 `parseurl_control` 自定义 URL 解析
- **别名**：SEO_URL、URL 重写

### C2. PATH_INFO
- **定义**：URL 不带 `?u=` 时，通过 `$_SERVER['PATH_INFO']` 传递
- **格式**：`/show-index-cid-5` 等价于 `?u=show-index-cid-5`

### C3. parseurl_control
- **定义**：处理伪静态 URL 反解析为 `$_GET[control]/[action]/参数` 的特殊控制器
- **路由配置**：`config/route.inc.php`（需 `route_open=1` 才会加载）

### C4. URL 三种模式
| 模式 | URL 形式 | 启用条件 |
|---|---|---|
| 默认 | `?u=cate-index-cid-5.html` | `lecms_parseurl=0` |
| PATH_INFO | `/cate-index-cid-5.html` | 服务器支持 PATH_INFO |
| 伪静态 | `/game/csgo-id-5.html` | `lecms_parseurl=1` + 路由规则 |

### C5. URLs 模型
- **定义**：`lecms/model/urls_model.class.php` 提供 URL 生成器
- **方法**：`category_url($cid)`、`content_url($row)`、`tag_url($tag)`、`user_url()`、`so_url()`、`model_url()`
- **作用**：所有前台 URL 通过该模型生成，便于全局修改链接格式

## D. 数据与缓存

### D1. KV 存储
- **定义**：键值对存储，基于 `le_kv` 表实现
- **用途**：存储配置项、计数器等无需表结构变更的数据
- **访问**：`kv_get($k)`、`kv_set($k, $v)` 函数或 `$this->kv->xget/xset/xsave`

### D2. only_alias
- **定义**：别名唯一性检查模型
- **表结构**：`alias`（唯一值）+ `id`（关联 ID）
- **用途**：URL 别名、用户名等需唯一性的字段

### D3. content_model
- **定义**：内容模型（继承自 `custom_model`），LeCMS 核心业务模型
- **特点**：支持自定义字段扩展、按 `mid` 切表
- **mid 默认值**：1（article）、3（game）、6（software）

### D4. 二级缓存
- **定义**：数据库前先读缓存，未命中时回源 DB 并回写
- **启用**：`cache.enable=1`
- **L2**：`cache.l2_cache=1` 启用条件查询结果缓存（按 where/order/limit md5）
- **失效**：find_update/find_delete 命中 > 2000 行会 `cache.truncate(table)`

### D5. l2_cache
- **定义**：条件查询二级缓存，key 为 `md5(serialize([pri, where, order, start, limit]))`
- **默认**：与 enable 联动，需 enable=1 + l2_cache=1
- **适用**：CMS 类只读为主的场景

### D6. runtime 表
- **定义**：运行时配置/缓存表，按 key 存 JSON
- **主键**：单字段 `k`（长度限制 32 字符，否则自动 md5）
- **过期**：通过 `expiry` 时间戳控制
- **访问**：`runtime->xget($key)`、`runtime->xset($key, $value)`

### D7. cache_db_set/get/update/delete
- **定义**：cache + db 封装的快捷方法
- **优先级**：cache 启用时先读 cache，cache miss 时读 db 并回填 cache
- **写入**：同时写 cache 和 db（db 优先以保证持久化）

## E. 业务模型

### E1. mid
- **定义**：内容模型 ID
- **常用**：1（文章）、3（游戏）、6（软件）
- **表命名**：`le_cms_{tablename}`（如 `le_cms_article`、`le_cms_game`）

### E2. cid
- **定义**：分类 ID，关联 `le_category.cid`
- **用法**：内容表 `cid` 字段

### E3. flag（属性标记）
- **定义**：内容属性（荐/热/头/精/幻）
- **存储**：cms_content_flag 表，多选以英文逗号分隔
- **用途**：首页推荐位、热门游戏等

### E4. tag（标签）
- **定义**：内容标签，独立标签库 + 关联表
- **表**：`le_cms_content_tag` + `le_cms_content_tag_data`

### E5. page（单页）
- **定义**：单页分类，可挂评论
- **典型用法**：留言板（`page_message.htm`）
- **版本**：3.0.2+

### E6. 插件 install.php
- **定义**：插件安装脚本
- **调用时机**：后台"插件管理 → 安装"按钮触发
- **可用资源**：`$this->db`（control::__get 注入）、`$_ENV['_config']['db']['master']['tablepre']`
- **规范**：必须 `defined('IN_ADMIN') || exit;` 守护

### E7. plugin.inc.php
- **定义**：插件启用清单
- **结构**：`return array('plugin_name' => array('enable' => 1), ...);`
- **由谁生成**：install/index.php 安装时由 `install/plugin.sample.php` 复制生成

## F. 安全与权限

### F1. form_hash
- **定义**：CSRF 令牌，通过 `form_hash()` 生成
- **验证**：`form_submit()` 或 `check_form_hash()`
- **模板**：`{form_hash()}` 输出隐藏域
- **机制**：基于 `$_ENV['_config']['auth_key']` + session 生成

### F2. GPC 过滤
- **定义**：GET / POST / COOKIE 注入过滤
- **启用**：`MAGIC_QUOTES_GPC` 检测
- **行为**：PHP 7.4+ 默认关闭，由框架 `_stripslashes` 反转义

### F3. auth_key
- **定义**：全局加密 KEY，存于 `config.inc.php`
- **用途**：cookie 防伪、表单 hash、URL hashids
- **安全**：生产环境必须自定义，不可使用默认值

### F4. close_website
- **定义**：站点关闭开关
- **生效**：访问任意页面直接渲染 `close_website.htm`
- **绕过**：管理员登录后绕过（部分版本）

### F5. admin 安全入口
- **建议**：把 `admin/` 目录改名（如 `manage_8a2b/`）
- **作用**：降低被自动化扫描攻击的概率

### F6. install 目录保护
- **定义**：安装完成后必须删除 `install/`
- **原因**：未删除时访问 `install/` 会再次进入安装向导或返回 lock.php

## G. 部署与运维

### G1. DEBUG 模式
- **生产**：必须 `debug=0` 和 `debug_admin=0`
- **风险**：DEBUG>0 暴露绝对路径、表前缀、SQL

### G2. PHP 版本
- **要求**：5.4.0 ≤ PHP < 8.2.0
- **PHP 8.2+**：框架在 `xiunophp.php:8` 硬 exit
- **PHP 8.1**：最高兼容版本（推荐）

### G3. 缓存清理
- **runcache**：可整体清理让框架重新编译
- **runtime**：错误日志目录，按月分目录
- **upload**：上传目录，备份时排除

### G4. 数据库表前缀
- **配置**：`db.master.tablepre`
- **多站点**：用不同前缀隔离同一数据库多站点数据

### G5. 读写分离
- **配置**：在 `db.master` 基础上加 `db.slaves[]`
- **当前状态**：框架未自动启用从库，仅缓存 `$id=$type` 单连接；需自行扩展 `model::load_db()`

### G6. SEO 静态化
- **Apache**：`.htaccess` 提供
- **Nginx**：`nginx.htaccess` 提供
- **必须**：URL 模式选择后保持一致，否则生成 URL 与访问 URL 不匹配

### G7. cron/CLI
- **限制**：很多模型依赖 `$_ENV['_config']`，CLI 脚本需手动加载 `xiunophp.php`
- **建议**：CLI 入口放在 `scripts/`，不要直接 require 控制器的依赖

## H. 扩展与定制

### H1. 自定义路由
- **文件**：`config/route.inc.php`
- **启用**：`config.inc.php` 的 `route_open=1`
- **格式**：正则替换 `$_GET`

### H2. 自定义内容模型
- **后台**：内容模型管理 → 新增模型
- **效果**：自动生成对应的 `cms_{tablename}` 等 4 张表
- **URL 模式**：默认列表/详情 URL 自动生成

### H3. 自定义字段
- **后台**：模型管理 → 字段管理
- **存储**：`cms_content_{x}_data` 大字段表

### H4. Layui 后台二开
- **入口**：`static/admin/admin.js`
- **主题**：layuimini（`static/layui/`）
- **常见扩展**：miniTab、miniMenu、echarts、treetable、dragsort

### H5. UEditor / UMEditor
- **位置**：`static/js/umeditor/`
- **用途**：后台内容编辑器
- **注意**：与 Layui 自带 layedit 不冲突，可共存

### H6. CSS class 混淆（防采集）
- **配置**：`view_original` 配置项
- **机制**：基于 `auth_key` 对 class 名做 md5 前缀
- **作用**：原始 class 不暴露给爬虫

### H7. 移动端模板分离
- **配置**：`open_mobile_view=1` + `mobile_view` 字段
- **机制**：按 UA 切换主题
