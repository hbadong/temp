# LECMS 故障排查手册

> 适用版本：LECMS 3.0.4 + XiunoPHP 1.0.0
> 排查思路：先看日志 → 再开 DEBUG → 最小化复现 → 定位 → 修复 → 验证

---

## 一、通用排查流程

### 1.1 黄金顺序

```
┌─────────────────────────────────────────┐
│ 1. 看 PHP-FPM / Nginx 错误日志         │
│ 2. 看 LECMS runtime/log 错误日志       │
│ 3. 开启 DEBUG=1 + debug_admin=1        │
│ 4. 浏览器 F12 看请求/响应/控制台       │
│ 5. curl 复现（最小化请求）             │
│ 6. 检查 runcache 是否过期              │
│ 7. 检查文件权限                       │
│ 8. 检查数据库连接                     │
│ 9. 复现插件逐一禁用                   │
│ 10. 复现主题切换 default              │
└─────────────────────────────────────────┘
```

### 1.2 关键日志位置

| 日志 | 路径 | 说明 |
|---|---|---|
| PHP-FPM 错误 | `/var/log/php8.1-fpm.log` | PHP 语法错误、致命错误 |
| Nginx 错误 | `/var/log/nginx/error.log` | 502/504 通常是后端问题 |
| LECMS PHP 错误 | `log/php_error.php` | 框架捕获的 PHP 错误 |
| LECMS 404 错误 | `log/php_error404.php` | 404 访问记录（需 `php_error404=1`） |
| LECMS 登录日志 | `log/login_log.php` | 后台登录失败 |
| LECMS 用户登录日志 | `log/user_login_log.php` | 前台用户登录失败 |
| LECMS trace | `log/2024XX/xxx.php` | DEBUG=1 时的追踪日志 |
| MySQL 慢查询 | `/var/log/mysql/slow.log` | 性能问题 |

### 1.3 DEBUG 调试开关

`lecms/config/config.inc.php`：

```php
$_ENV['_config'] = array(
  'debug' => 1,           // 前台调试
  'debug_admin' => 1,     // 后台调试
  'php_error' => 1,       // 写错误日志
  'php_error404' => 1,    // 写 404 日志
);
```

> 修改后必须 `rm -rf runcache/_lecms.php` 让框架重新生成。

## 二、高频故障速查

### F01. 访问首页空白（无任何输出）

**症状**：浏览器空白，控制台无错误，curl 返回空。

**可能原因**：

1. PHP-FPM 没启动：`systemctl status php8.1-fpm`
2. 权限问题：runcache 不可写
3. 配置错误：config.inc.php 语法错误
4. 内存耗尽：OOM

**排查**：

```bash
# 1. 看 PHP-FPM 日志
tail -50 /var/log/php8.1-fpm.log

# 2. 看 Nginx 错误
tail -50 /var/log/nginx/error.log

# 3. 测试 PHP 解析
php -r 'phpinfo();' | head

# 4. 直接运行 index.php
php /var/www/lecms/index.php
# 看输出的最后几行（PHP 错误）

# 5. 检查 runcache 写权限
ls -ld /var/www/lecms/runcache
chown -R www-data:www-data /var/www/lecms/runcache
```

**修复**：根据具体错误修复；通常为权限或 PHP 扩展未装。

---

### F02. 500 Internal Server Error

**症状**：所有页面 500。

**排查**：

```bash
# 1. 看 Nginx 错误
tail -50 /var/log/nginx/error.log
# 常见：FastCGI sent in stderr: "PHP message: ..."

# 2. 看 PHP-FPM 日志
tail -50 /var/log/php8.1-fpm.log

# 3. 开启 display_errors（仅调试时）
# /etc/php/8.1/fpm/php.ini
display_errors = On
display_startup_errors = On
systemctl reload php8.1-fpm
```

**典型错误信息与修复**：

| 错误 | 原因 | 修复 |
|---|---|---|
| `require_once(): Failed opening` | 路径常量错误 | 检查 ROOT_PATH |
| `Class 'cache_xxx' not found` | 缓存驱动未装 | `pecl install memcached` |
| `SQLSTATE[HY000] [2002]` | 数据库连接失败 | 检查 host/port/firewall |
| `SQLSTATE[HY000] [1045]` | 数据库密码错 | 检查 `db.master.password` |
| `SQLSTATE[42S02] [1146]` | 表不存在 | 重新导入 SQL |
| `Cannot redeclare class xxx` | 重复 include | 删除 runcache |
| `Allowed memory size exhausted` | 内存爆 | `ini_set('memory_limit','512M')` |

---

### F03. 404 Not Found

**症状**：访问任何页面都是 404。

**排查**：

```bash
# 1. 检查伪静态规则
ls -la /var/www/lecms/.htaccess
cat /var/www/lecms/.htaccess  # Apache
cat /var/www/lecms/nginx.htaccess  # Nginx 参考

# 2. Nginx 配置检查
nginx -t
grep -r 'rewrite' /etc/nginx/

# 3. 检查 LECMS 伪静态配置
grep 'lecms_parseurl' /var/www/lecms/lecms/config/config.inc.php
```

**典型原因**：

1. Nginx 未配置 `try_files $uri $uri/ /index.php?$query_string;`
2. `lecms_parseurl=1` 但路由规则未配（缺 `route.inc.php`）
3. PATH_INFO 被 PHP 禁用（`cgi.fix_pathinfo=0`）

---

### F04. 安装向导进不去

**症状**：访问 `/install/` 跳转到首页或 404。

**原因**：

- `config.inc.php` 已存在 → 框架跳过 install
- `install/` 目录被删或改名
- 目录权限不足

**排查**：

```bash
ls -la /var/www/lecms/install/
ls /var/www/lecms/lecms/config/config.inc.php
```

**修复**：

- 若 config.inc.php 已存在且是生产配置，**不要重装**
- 若要重装：备份后删除 config.inc.php、清空数据库、重新访问 install/

---

### F05. 后台登录失败

**症状**：账号密码正确但提示"用户名或密码错误"。

**排查**：

```bash
# 1. 检查用户表
mysql -u aimumen100 -p aimumen100 -e "SELECT uid,username,password FROM le_user LIMIT 5;"

# 2. 验证密码 hash（框架用 Xxtea 加密，不是 md5）
# 框架密码算法：
#   $pwd = xxtea_encrypt(md5($raw_pwd . $auth_key), $auth_key)
# 重置密码需要用这个算法，不能用普通 md5

# 3. 看登录日志
tail -20 /var/www/lecms/log/login_log.php
```

**修复**：直接在数据库重置密码：

```php
// scripts/reset_password.php
<?php
require '/var/www/lecms/lecms/xiunophp/xiunophp.php';
$auth_key = $_ENV['_config']['auth_key'];
$raw_pwd = 'NewPassword!';
$encrypted = xxtea_encrypt(md5($raw_pwd . $auth_key), $auth_key);
$db->query("UPDATE le_user SET password='" . $db->escape($encrypted) . "' WHERE username='admin'");
echo "密码已重置为: $raw_pwd\n";
```

### F06. 模板修改不生效

**症状**：改了 `.htm` 模板，前台没变化。

**原因**：模板编译缓存。

**修复**：

```bash
rm -rf /var/www/lecms/runcache/lecms_view/
rm -rf /var/www/lecms/runcache/admin_view/
# 然后刷新页面
```

> 永久方案：开发阶段 `debug=1`。

---

### F07. 控制器修改不生效

**症状**：改了 `control/*.php` 但行为不变。

**修复**：

```bash
rm -rf /var/www/lecms/runcache/lecms_control/
rm -rf /var/www/lecms/runcache/admin_control/
```

---

### F08. 插件启用后页面 500

**症状**：启用某个插件后页面 500。

**排查**：

```bash
# 1. 看错误日志
tail -20 /var/www/lecms/log/php_error.php

# 2. 关闭插件
# 编辑 lecms/config/plugin.inc.php，把对应插件的 enable 改为 0

# 3. 看插件 conf.php 是否存在
ls -la /var/www/lecms/plugin/{plugin_name}/conf.php

# 4. 看插件 hook 文件是否语法错误
php -l /var/www/lecms/plugin/{plugin_name}/xxx.php
```

**修复**：删除出错的插件目录，或修复插件 bug。

---

### F09. 数据库表不存在错误

**症状**：`SQLSTATE[42S02] Base table or view not found: le_xxx doesn't exist`

**排查**：

```bash
mysql -u aimumen100 -p aimumen100 -e "SHOW TABLES;"
```

**修复**：

```bash
# 1. 导入缺失的 SQL
mysql -u aimumen100 -p aimumen100 < /var/www/lecms/install/data/mysql.sql
mysql -u aimumen100 -p aimumen100 < /var/www/lecms/install/data/core_engine.sql

# 2. 插件表的导入
mysql -u aimumen100 -p aimumen100 < /var/www/lecms/plugin/{plugin}/install.php
# 或在后台"插件管理"重新点"安装"
```

---

### F10. 上传文件失败

**症状**：后台附件上传 100% 失败或 413 错误。

**排查**：

```bash
# 1. 检查 PHP 上传配置
php -i | grep -E 'upload_max_filesize|post_max_size'

# 2. 检查 Nginx 限制
grep 'client_max_body_size' /etc/nginx/

# 3. 检查目录权限
ls -ld /var/www/lecms/upload
chown -R www-data:www-data /var/www/lecms/upload
```

**修复**：

```ini
# /etc/php/8.1/fpm/php.ini
upload_max_filesize = 50M
post_max_size = 50M
max_file_uploads = 50

# /etc/nginx/nginx.conf
client_max_body_size 50M;
```

---

### F11. 内存耗尽（Allowed memory size）

**症状**：`Allowed memory size of 134217728 bytes exhausted`

**修复**：

```ini
# /etc/php/8.1/fpm/php.ini
memory_limit = 512M
```

或在代码中临时调大：

```php
ini_set('memory_limit', '512M');
```

---

### F12. 缓存服务连接失败

**症状**：开启 `cache.enable=1` 后页面报错 `Connection refused`。

**排查**：

```bash
# memcached
systemctl status memcached
nc -zv 127.0.0.1 11211

# redis
systemctl status redis
redis-cli ping
```

**修复**：

```bash
systemctl start memcached
systemctl enable memcached
```

---

### F13. cron 脚本执行失败

**症状**：`scripts/` 下脚本执行报错 `Undefined index: _config`。

**原因**：CLI 模式没有走 `index.php`，`$_ENV['_config']` 未初始化。

**修复**：

```php
// scripts/xxx.php 开头加：
<?php
chdir(dirname(__FILE__) . '/..');
define('APP_NAME', 'lecms');
require 'lecms/xiunophp/xiunophp.php';
```

---

### F14. 主题切换无效

**症状**：后台改了主题，前台还是旧主题。

**原因**：运行时 cfg 缓存未清。

**修复**：

- 后台"工具 → 清理缓存"
- 或 `DELETE FROM le_runtime WHERE k='cfg';`

---

### F15. 伪静态后内容页 404

**症状**：开启伪静态后，部分内容页 404。

**排查**：

```bash
# 1. 看 404 日志
tail -50 /var/www/lecms/log/php_error404.php

# 2. 检查 route.inc.php 规则
cat /var/www/lecms/lecms/config/route.inc.php

# 3. 测试 URL 解析
curl -I http://lecms.example.com/xxx.html
```

## 三、性能问题排查

### P01. 首页加载慢

```bash
# 1. 看 SQL 数量
# 开启 DEBUG=2，页面底部 $_ENV['_sqls'] 会显示 SQL 与耗时

# 2. 找出慢 SQL
# 开启 MySQL 慢查询日志
SET GLOBAL slow_query_log='ON';
SET GLOBAL long_query_time=1;

# 3. 缓存命中率
# 编辑 /var/www/lecms/lecms/config/config.inc.php
'cache' => array(
  'enable' => 1,
  'l2_cache' => 1,
  ...
)

# 4. 模板缓存清理
rm -rf /var/www/lecms/runcache/lecms_view/
```

### P02. 后台列表慢

```bash
# 看具体控制器
cat /var/www/lecms/admin/control/content_control.class.php | grep -A 5 'function get_list'
# 通常是没有用分页 + 索引失效
# 修复：加 LIMIT、用 where 子句、确认索引
EXPLAIN SELECT * FROM le_cms_article WHERE cid=5 ORDER BY dateline DESC LIMIT 20;
```

### P03. 数据库 CPU 高

```bash
# 看进程
mysql -u root -p -e "SHOW PROCESSLIST;"
mysql -u root -p -e "SHOW ENGINE INNODB STATUS\G" | head -100

# 找慢查询
mysqldumpslow /var/log/mysql/slow.log | head -20
```

## 四、安全事件应急

### S01. 检测到 SQL 注入攻击

```bash
# 1. 立即检查 Nginx 访问日志
grep -E '(union|select|insert|delete|drop)' /var/log/nginx/access.log | head

# 2. 检查 LECMS 错误日志
tail -100 /var/www/lecms/log/php_error.php

# 3. 检查可疑文件
find /var/www/lecms -name '*.php' -newer /var/www/lecms/lecms/config/config.inc.php

# 4. 检查后台登录日志
tail -50 /var/www/lecms/log/login_log.php
```

### S02. 检测到 webshell

```bash
# 1. 查找可疑文件
find /var/www/lecms -name '*.php' -newer /var/log/lastlog
find /var/www/lecms -name '*.php' -size -1k  # 异常小文件

# 2. 查找 eval/assert/base64_decode
grep -rn 'eval(\|assert(\|base64_decode(' /var/www/lecms --include='*.php' | grep -v 'vendor\|lecms/xiunophp\|static/'

# 3. 对比备份
diff -rq /var/www/lecms /backup/lecms_clean | head

# 4. 重装：从备份还原 + 升级 + 改所有密码
```

### S03. 数据库被误删

```bash
# 立即停止 MySQL 写入
systemctl stop mysql

# 恢复最近备份
gunzip < backup_YYYYMMDD.sql.gz | mysql -u aimumen100 -p aimumen100

# 检查二进制日志
mysqlbinlog /var/log/mysql/binlog.000001 | mysql -u aimumen100 -p aimumen100
```

## 五、运维小工具脚本

### 5.1 一键清理 runcache

```bash
#!/bin/bash
# scripts/clean_runcache.sh
DIR=/var/www/lecms/runcache
[ -d $DIR ] || exit 0
rm -f $DIR/_lecms.php
rm -f $DIR/misc.func.php
rm -rf $DIR/lecms_control/*
rm -rf $DIR/admin_control/*
rm -rf $DIR/lecms_model/*
rm -rf $DIR/lecms_view/*
rm -rf $DIR/admin_view/*
rm -rf $DIR/core_lang/*
rm -rf $DIR/lang/*
echo "runcache cleaned at $(date)"
```

### 5.2 一键检查站点健康

```bash
#!/bin/bash
# scripts/healthcheck.sh
URL=http://lecms.example.com
curl -fsS -o /dev/null -w "%{http_code}\n" $URL || echo "FAIL"
curl -fsS -o /dev/null -w "%{http_code}\n" $URL/admin/ || echo "ADMIN_FAIL"
mysql -u aimumen100 -p"$DB_PASS" -e "SELECT 1" aimumen100 2>/dev/null && echo "DB_OK" || echo "DB_FAIL"
nc -z 127.0.0.1 11211 && echo "CACHE_OK" || echo "CACHE_FAIL"
df -h /var/www | tail -1 | awk '{print "DISK: " $5}'
```

### 5.3 一键重置管理员密码

```php
// scripts/reset_admin.php
<?php
chdir(__DIR__ . '/..');
define('APP_NAME', 'lecms');
require 'lecms/xiunophp/xiunophp.php';

$auth_key = $_ENV['_config']['auth_key'];
$new_pwd = 'NewPass!2026';
$encrypted = xxtea_encrypt(md5($new_pwd . $auth_key), $auth_key);

$db = new db_pdo_mysql($_ENV['_config']['db']);
$db->query("UPDATE le_user SET password='" . $db->escape($encrypted) . "' WHERE username='admin'");

echo "Admin password reset to: $new_pwd\n";
```
