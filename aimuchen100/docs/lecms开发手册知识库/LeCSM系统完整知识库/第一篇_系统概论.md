## 1. 系统概述

### 1.1 什么是 LeCMS

LeCMS 是一个基于 **XiunoPHP 框架**开发的轻量级内容管理系统（CMS）。它采用经典的 MVC（Model-View-Controller）架构模式，通过自研的**编译型模板引擎**实现高性能页面渲染，并使用独特的 **Hook 编译时注入机制**实现非侵入式插件扩展。

LeCMS 的设计理念：
- **约定优于配置**：遵循命名约定，减少配置文件
- **插件优先**：插件文件可覆盖核心文件
- **编译优化**：运行时编译，减少 IO 操作
- **Hook 扩展**：通过注释标记实现扩展
- **单例模式**：数据库和缓存对象单例化

### 设计原则技术细节

#### 高内聚、低耦合

LeCMS 的架构设计严格遵循高内聚（High Cohesion）、低耦合（Low Coupling）原则，具体体现在以下层面：

| 层面 | 高内聚体现 | 低耦合体现 |
|------|-----------|-----------|
| **框架层** | core.class.php 集中管理启动流程、自动加载、编译缓存 | 框架层不依赖业务代码，业务代码可独立升级 |
| **数据层** | model.class.php 封装统一的 CRUD 与二级缓存 | 通过 db_interface 抽象底层存储，可切换 MySQL/MongoDB |
| **表现层** | view.class.php 专注模板编译与变量绑定 | 模板语法独立，与 PHP 代码解耦 |
| **扩展层** | 插件系统自包含，每个插件独立目录 | 通过 Hook 编译时注入实现扩展，不修改核心代码 |
| **业务层** | 控制器按功能模块划分，职责清晰 | 通过 __get 懒加载模型，按需初始化 |

**模块边界规则**：

```
lecms/xiunophp/           ← 框架核心（严禁修改）
lecms/config/             ← 配置文件（独立于框架）
lecms/control/            ← 前台控制器（继承框架 control）
lecms/model/              ← 数据模型（继承框架 model）
lecms/block/              ← Block 标签（独立功能单元）
lecms/plugin/             ← 插件（完全独立，可覆盖任何层）
view/                     ← 模板层（独立于框架和应用）
```

#### 扩展点体系（Hook / Filter / Action）

LeCMS 提供三层扩展机制，从编译时到运行时全覆盖：

| 扩展机制 | 触发时机 | 实现方式 | 性能影响 |
|----------|---------|---------|---------|
| **编译时 Hook** | 模板/控制器/模型编译阶段 | `// hook xxx.php` 标记 + `process_hook()` | 零运行时开销 |
| **运行时 Hook** | 模板中的 `{hook:xxx}` 标签 | 编译时替换为实际代码 | 零额外开销 |
| **Block 标签** | 模板渲染时 | `block_xxx.lib.php` 函数调用 | 可配置缓存（life 参数） |

**扩展点设计原则**：

1. **非侵入式**：核心代码不依赖任何插件，插件可随时卸载
2. **优先级可控**：通过 `rank` 数值控制多个插件的加载顺序
3. **命名隔离**：插件函数/类建议加前缀，避免与核心或其他插件冲突
4. **向后兼容**：扩展点标记（`// hook xxx`）一旦添加，不轻易删除

#### 安全性设计

LeCMS 在架构层面设计了 **6 层安全防护**：

| 安全层 | 防护目标 | 实现机制 |
|--------|---------|---------|
| **入口安全** | 防止直接访问 PHP 文件 | `defined('ROOT_PATH') || exit;` |
| **模板安全** | 防止模板被直接访问 | `defined('APP_NAME') || exit('Access Denied');` |
| **输入安全** | 防止 SQL 注入、XSS | GPC 过滤、参数化查询、htmlspecialchars |
| **输出安全** | 防止 XSS 输出 | `{$var}` 自动转义，`{@expr}` 不转义（需自行负责） |
| **表单安全** | 防止 CSRF 攻击 | `form_hash()` / `check_form_hash()` 令牌机制 |
| **访问安全** | 防止未授权访问 | 后台登录验证、用户组权限控制、安全入口机制 |

**CSRF 防护实现**：

```php
// 生成令牌（在模板中）
{form_hash()}
// 输出: <input type="hidden" name="FORM_HASH" value="a1b2c3d4e5f6...">

// 验证令牌（在控制器中）
if(!form_submit()) {
    $this->message(0, lang('form_invalid'));
}
// form_submit() 内部会校验 $_POST['FORM_HASH'] 与 $_ENV['_config']['FORM_HASH'] 是否一致
```

#### 可观测性设计

LeCMS 在框架层面内置了完整的可观测能力，无需依赖第三方 APM 工具：

| 观测维度 | 实现方式 | 数据输出 |
|----------|---------|---------|
| **执行时间** | `$_ENV['_start_time']` + `microtime(1)` | 页面底部调试面板 |
| **内存使用** | `$_ENV['_start_memory']` + `memory_get_usage()` | 页面底部调试面板 |
| **SQL 查询** | `$_ENV['_sqls'][]` 逐条记录 | 页面底部调试面板 |
| **文件加载** | `$_ENV['_include'][]` 逐条记录 | DEBUG > 1 时输出 |
| **错误日志** | `log::write()` + `log::le_log()` | log/ 目录按月归档 |
| **跟踪日志** | `log::trace()` + `log::trace_save()` | 自定义日志文件 |

#### 可测试性设计

LeCMS 的架构天然支持分层测试：

| 测试层级 | 测试对象 | 方法 |
|---------|---------|------|
| **单元测试** | 工具函数、模型方法、缓存驱动 | 直接调用函数/方法，断言返回值 |
| **集成测试** | 控制器 + 模型 + 视图 | 模拟 HTTP 请求，检查响应 |
| **端到端测试** | 完整业务流程（注册→登录→发布→评论） | 浏览器自动化或 API 调用 |

**测试友好特性**：

- 单例模式便于 Mock：`static $dbs` / `static $caches` 可通过反射重置
- 编译缓存可清理：删除 `runcache/` 子目录即可重置状态
- 配置可覆盖：`C('key', 'value')` 可在测试中动态修改配置
- Hook 可禁用：`plugin_disable = 1` 可快速关闭所有插件

#### 文档优先理念

LeCMS 源码中大量使用行级注释，关键位置都有详细的代码说明：

```php
// ─────────────────────────────────────────────────────────────────
// 第1行: 代码压缩开关（预留功能，当前版本未使用）
// 0 = 关闭压缩, 1 = 开启压缩（对 PHP 源码进行压缩）
// ─────────────────────────────────────────────────────────────────
define('CODE_COMPRESS', 0);
```

这种注释风格被称为 **"折叠注释"（Fold Comment）**，在 IDE 中可折叠，既不影响代码阅读，又提供了完整的上下文信息。

#### XiunoPHP 框架起源

XiunoPHP 是一个受 **ThinkPHP 风格**影响的轻量级 PHP 框架，采用单入口设计模式。它的设计哲学与 LeCMS 高度契合：

- **单入口架构**：所有请求通过 `index.php` 进入，由框架统一分发
- **命名空间约定**：不依赖 PHP 命名空间，而是通过目录结构和类名约定实现自动加载
- **编码风格**：类名采用 `snake_case`（如 `model.class.php`），方法使用 `camelCase`
- **框架版本**：XiunoPHP 1.0.0（定义于 `lecms/xiunophp/xiunophp.php` 第 4 行）

```php
// lecms/xiunophp/xiunophp.php
define('FRAMEWORK_VERSION', '1.0.0');
```

#### LeCMS 对 XiunoPHP 的扩展

LeCMS 在不修改 XiunoPHP 任何核心文件的前提下，在 `lecms/` 目录下进行了大量扩展，新增的目录结构如下：

| 新增目录 | 说明 | 对应 XiunoPHP 核心能力 |
|---------|------|---------------------|
| `lecms/control/` | 前台控制器（17个，含 base_control 基类） | 继承自 XiunoPHP Control 基类 |
| `lecms/admin/` | 后台控制器 | 独立于前台的应用层 |
| `lecms/model/` | 数据模型（18个） | 继承自 XiunoPHP Model 基类 |
| `lecms/block/` | Block 数据标签（41个） | XiunoPHP 内置 block 系统的业务化封装 |
| `lecms/plugin/` | 插件目录 | 使用 XiunoPHP Hook 机制 |
| `lecms/lang/` | 语言包 | 扩展 XiunoPHP 内置语言系统 |
| `lecms/config/` | 配置文件 | 扩展 XiunoPHP 配置系统 |

**核心原则**：LeCMS 不修改 `lecms/xiunophp/` 下的任何文件，所有业务逻辑、控制器、模型、模板均位于 `lecms/` 目录下。这意味着：

1. 升级 XiunoPHP 核心文件不会影响 LeCMS 业务代码
2. 插件系统可以覆盖 `lecms/` 目录下的文件实现扩展
3. 框架核心文件（`xiunophp/`）与业务代码完全解耦

#### PHP 版本兼容性详解

PHP 版本限制：`5.4.0 < PHP < 8.2.0`

**下限 5.4.0 的原因**：
- 使用了 PHP 5.4 引入的 `[\]` 数组短语法
- 使用了 `<?=` 短输出标签（默认开启）
- 部分类使用了 Traits 特性
- SESSION 扩展的早期 API

**上限 8.2.0 的原因**（来源：`lecms/xiunophp/xiunophp.php` 第 8 行）：
```php
version_compare(PHP_VERSION, '8.2.0', '<') || exit('require PHP < 8.2.0 !');
```

PHP 8.2 不兼容的具体原因：
1. `each()` 函数在 PHP 8.0 中已废弃，8.2 中彻底移除
2. `create_function()` 在 PHP 8.0 中已移除
3. 部分动态调用方式（如 `call_user_func_array` 的引用传递行为变更）
4. 某些扩展类库（如 phpmailer 旧版本）不兼容 PHP 8.2

**推荐 PHP 版本**：7.4+ 或 8.1（低于 8.2 的最新稳定版）

#### 数据库引擎推荐

LeCMS 默认使用 **MyISAM** 作为数据库引擎（`'engine'=>'MyISAM'`），配置在 `lecms/config/config.inc.php` 第 30 行。

| 引擎 | 适用场景 | 说明 |
|------|---------|------|
| **MyISAM**（默认） | 读多写少的 CMS 场景 | 全文检索速度快，表级锁，适合内容为主的站点 |
| **InnoDB** | 高并发写入场景 | 行级锁，支持事务，外键约束，适合需要事务保障的业务表 |

建议内容表使用 MyISAM，用户表、配置表等写入频繁的表可切换为 InnoDB。

### 4.1 补充常量详解

#### F_APP_NAME

```php
// lecms/xiunophp/xiunophp.php 第 47-51 行
if( defined('F_APP_NAME') ){
    defined('DEBUG') || define('DEBUG', (int)$_ENV['_config']['debug_admin']);
}else{
    defined('DEBUG') || define('DEBUG', (int)$_ENV['_config']['debug']);
}
```

`F_APP_NAME` 是一个特殊的标识常量，用于区分前台和后台应用。当访问后台入口（`admin/index.php`）时，该常量被定义为 `admin`，框架据此读取 `debug_admin` 配置项作为调试模式。这允许前后台使用不同的调试开关。

#### ADMIN_PATH

```php
// lecms/xiunophp/lib/debug.class.php 第 60 行
if(!defined('ADMIN_PATH')){
    // ... 调试面板内容
}
```

`ADMIN_PATH` 用于标记当前请求是否为后台请求，在调试类中用于区分前后台调试面板的显示逻辑。通常在后台入口文件 `admin/index.php` 中定义。

#### DEBUG 常量三种模式

| DEBUG 值 | 模式 | 行为 |
|---------|------|------|
| **0** | 生产模式 | 使用 `runcache/` 缓存文件，不重新编译；错误不显示（写入日志） |
| **1** | 调试模式 | 每次请求重新编译模板和控制器；页面底部显示调试信息（排除 AJAX） |
| **2** | 开发调试模式 | 同 DEBUG=1，额外显示完整的调试面板（debug_info） |

```php
// lecms/xiunophp/xiunophp.php 第 46-51 行
//后台和前台，调试模式，分三种：
// 0 关闭调试;
// 1 开启调试;
// 2 开发调试
//注意：开启调试会暴露绝对路径和表前缀
```

**重要安全提示**：开启调试模式会暴露网站绝对路径、数据库表前缀等敏感信息，线上环境必须设置为 `0`。

#### RUNTIME_VIEW 相关常量

框架中的视图编译缓存路径由 `RUNTIME_PATH` + `APP_NAME` 动态生成：

| 常量 | 计算方式 | 实际路径示例 |
|------|---------|-------------|
| `RUNTIME_MODEL` | `RUNTIME_PATH + APP_NAME + '_model/'` | `runcache/lecms_model/` |
| `RUNTIME_CONTROL` | `RUNTIME_PATH + APP_NAME + '_control/'` | `runcache/lecms_control/` |
| 视图缓存 | 无独立常量，由 View 类内部计算 | `runcache/lecms_view/` |

`APP_NAME` 的作用是允许多个应用共享同一个 `runcache/` 目录而不会发生文件冲突。

#### APP_NAME 的作用机制

```php
// 默认值
defined('APP_NAME') || define('APP_NAME', 'lecms');
```

`APP_NAME` 影响以下常量的最终值：

```php
RUNTIME_MODEL   = RUNTIME_PATH . APP_NAME . '_model/'    // lecms_model/
RUNTIME_CONTROL = RUNTIME_PATH . APP_NAME . '_control/'  // lecms_control/
```

如果创建第二个应用（如 `app2`），其编译缓存将输出到 `runcache/app2_model/` 和 `runcache/app2_control/`，互不干扰。

**前台/后台区分机制**：

1. 前台入口 `index.php`：不定义 `F_APP_NAME`，使用 `debug` 配置
2. 后台入口 `admin/index.php`：定义 `F_APP_NAME = 'admin'`，使用 `debug_admin` 配置
3. 控制器目录：前台使用 `CONTROL_PATH`（`lecms/control/`），后台使用 `admin/` 目录下的独立控制器

#### VENDOR 常量

LeCMS 不定义独立的 `VENDOR` 常量。第三方类库（如 PHPMailer）直接放在 `lecms/xiunophp/ext/phpmailer/` 子目录中，通过自动加载机制引入。

#### CODE_COMPRESS 常量

```php
// lecms/xiunophp/lib/view.class.php 第 90 行
if(defined('CODE_COMPRESS') && CODE_COMPRESS == 1 && DEBUG == 0) {
    // 生产模式下压缩合并模板输出
}
```

`CODE_COMPRESS` 用于控制是否在输出时压缩 PHP 代码（去除空白和注释），需要在 `config.inc.php` 中定义，仅在非调试模式下生效。

## 5. 核心术语表

| 术语 | 定义 | 别名 |
|------|------|------|
| **runcache** | 编译缓存目录，存放模板、语言包、控制器的编译后 PHP 文件。修改源码或模板后必须清理对应子目录才能生效。包含 lecms_control/、lecms_model/、lecms_view/、lang/ 等子目录 | 运行缓存、编译缓存 |
| **hook** | 插件扩展机制，通过在核心代码中预留 `// hook xxx.php` 注释作为挂载点，启用插件时在编译期将同名文件原样合并进缓存文件。多插件按 conf.php 中 rank 升序合并 | 钩子、插件钩子 |
| **block** | 模板数据标签系统，位于 lecms/block/ 目录，以 block_xxx.lib.php 形式提供。global_ 前缀的 block 数据放在 $gdata 且提升到模板头部，普通 block 数据放 $data | 数据标签、模板标签 |
| **主题** | 前台模板集合，位于 view/ 目录下，每个子目录是一个独立主题。模板文件命名遵循 控制器_方法.htm 规范，共用模板使用 inc- 前缀 | 模板主题 |
| **伪静态** | URL 重写功能，通过 lecms_parseurl 配置项控制。开启后可自定义路由规则，需搭配 route.inc.php 使用 | SEO_URL、URL 重写 |
| **debug 模式** | 调试开关，debug=1 时每次请求都重新编译模板和代码；debug=0 时使用 runcache 缓存。线上环境 debug 必须为 0 | 开发模式 |
