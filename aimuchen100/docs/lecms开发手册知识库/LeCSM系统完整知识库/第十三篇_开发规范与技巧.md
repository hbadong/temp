## 78. 命名规范

### 78.1 文件命名规范

| 文件类型 | 命名格式 | 示例 |
|---------|---------|------|
| 前台控制器 | `{name}_control.class.php` | `index_control.class.php` |
| 后台控制器 | `{name}_control.class.php` | `setting_control.class.php` |
| 模型 | `{name}_model.class.php` | `cms_content_model.class.php` |
| Block 函数库 | `block_{name}.lib.php` | `block_list.lib.php` |
| Hook 文件 | `{location}_{timing}.php` | `admin_admin_control_construct_before.php` |
| 包含模板 | `inc-{name}.htm` | `inc-header.htm` |
| 插件配置 | `conf.php` | `plugin/le_links/conf.php` |
| 语言包 | `{lang}.php` / `{lang}_admin.php` | `zh-cn.php` / `zh-cn_admin.php` |

**命名规则**:
- 全部使用小写字母
- 单词之间使用下划线 `_` 分隔
- 控制器和模型名使用蛇形命名法
- 文件名中的名字部分与类名保持一致

### 78.2 类命名规范

| 类型 | 类名格式 | 示例 |
|------|---------|------|
| 前台控制器 | `{name}_control` | `class index_control extends control` |
| 后台控制器 | `{name}_control` | `class admin_control extends control` |
| 模型 | `{name}`（文件名去掉 `_model` 后缀） | `class site_manager extends model`（文件：`site_manager_model.class.php`） |
| 工具类 | `{name}` | `class debug` |

**继承关系示例**:

```php
// 前台控制器: index_control → base_control → control
class index_control extends base_control { }

// 后台控制器: setting_control → admin_control → control
class setting_control extends admin_control { }

// 模型: cms_content → model
class cms_content extends model { }
```

### 78.3 函数命名规范

| 类型 | 格式 | 示例 |
|------|------|------|
| Block 函数 | `block_{name}($conf)` | `block_list($conf)` |
| 工具函数 | 小写 + 下划线 | `random()`, `form_hash()` |
| 模型方法 | 驼峰命名 | `get_user_by_uid()`, `find_fetch()` |
| 类方法 | 驼峰命名 | `init_start()`, `error_handler()` |

**Block 函数规范**:

```php
/**
 * 内容列表模块
 * @param array $conf 配置参数
 * @return array
 */
function block_list($conf) {
    global $run;  // 必须获取 $run 全局变量
    // ...
}
```

### 78.4 模板命名规范

| 类型 | 格式 | 示例 |
|------|------|------|
| 页面模板 | `{control}_{action}.htm` | `index_index.htm`, `show_show.htm` |
| 包含模板 | `inc-{name}.htm` | `inc-header.htm`, `inc-footer.htm` |
| 独立页面模板 | `{name}.htm` | `about.htm` |

**模板自动匹配规则**:
- 默认匹配: `{control}_{action}.htm`（如访问 `index.php?index-index` → `index_index.htm`）
- `display()` 可指定自定义模板名
- `{inc:xxx}` 标签包含其他模板

**模板标签语法规则（必须带冒号）**:

| 标签 | 正确写法 | 错误写法 |
|------|---------|---------|
| 循环 | `{loop:$arr $v}` | `{loop $arr $v}` |
| 条件 | `{if:$status==1}` | `{if $status==1}` |
| 否则如果 | `{elseif:$status==2}` | `{elseif $status==2}` |
| 变量输出 | `{$site['name']}` | `{$site.name}` |

> [!WARNING]
> **缺少冒号 = 标签不识别**。框架模板引擎通过正则 `#\{(\w+):` 匹配标签，冒号是语法分界线。缺少冒号时标签原样输出到浏览器，不会报错，但会导致页面显示原始标签文本。

### 78.5 插件目录规范

**推荐：平铺模式（对齐 le_links）**

```
plugin/{插件名}/
  conf.php              ← 插件配置文件（返回数组）
  conf_{lang}.php       ← 多语言配置（可选）
  {插件名}_control.class.php   ← 控制器（平铺在根目录，推荐）
  {插件名}_model.class.php     ← 模型（平铺在根目录，推荐）
  header.htm            ← 后台头部模板（可选，供 {inc:header.htm} 引用）
  {控制名}_{动作}.htm   ← 页面模板（平铺在根目录，推荐）
  block_{name}.lib.php         ← Block 函数（可选）
  hook/                  ← Hook 目录
    {location}_{timing}.php
  lang/                  ← 语言包（可选）
    {lang}.php
  static/                ← 静态资源（可选）
    css/
    js/
```

**传统：子目录模式**

```
plugin/{插件名}/
  conf.php
  conf_{lang}.php
  {插件名}_control.class.php   ← 控制器
  {插件名}_model.class.php     ← 模型
  hook/                  ← Hook 目录
    {location}_{timing}.php
  lang/                  ← 语言包（可选）
    {lang}.php
  control/               ← 前台控制器子目录（可选）
    xxx_control.class.php
  model/                 ← 前台模型子目录（可选）
    xxx_model.class.php
  admin/                 ← 后台模块子目录（可选）
    control/
      xxx_control.class.php
    view/
      xxx.htm
  static/                ← 静态资源（可选）
    css/
    js/
```

**插件优先级**: 插件文件 > 核心文件。当插件中有与核心同名的文件时，插件文件优先加载。

## 79. 代码规范

### 79.1 PHP 标签规范

- **必须使用完整标签**: `<?php`
- **禁止使用短标签**: `<?` （除非在 `php.ini` 中启用了 `short_open_tag`）
- **代码结束不加 `?>`**: 防止意外输出空白字符

```php
<?php
// 正确: 以 <?php 开头，不加 ?>
class my_control extends control {
    // ...
}
```

> **原因**: PHP 文件末尾的 `?>` 后如果有换行符或空格，会导致 "Headers already sent" 错误。

### 79.2 安全头规范

所有 PHP 文件的第一行必须是安全头，防止直接访问：

```php
<?php
defined('ROOT_PATH') or exit;
// 或
defined('ROOT_PATH') || exit;
```

**两种写法对比**:

| 写法 | 行为 | 适用场景 |
|------|------|---------|
| `defined('ROOT_PATH') or exit;` | 未定义时执行 `exit` | 框架文件 |
| `defined('ROOT_PATH') || exit;` | 未定义时执行 `exit` | 框架文件（更简洁） |

> **注意**: `exit` 不带分号时的区别：`or exit;` 和 `|| exit;` 在 PHP 中是等价的，因为 `exit` 本身不返回值。

### 79.3 缩进与格式规范

- **缩进**: 使用 Tab 制表符（不使用空格）
- **换行**: 大括号 `{` 放在行尾，`}` 独占一行

```php
// 正确
class my_control extends control {
	public function index() {
		if($condition) {
			// ...
		}
	}
}

// 错误：使用空格缩进
class my_control extends control {
    public function index() {
        if($condition) {
            // ...
        }
    }
}
```

### 79.4 注释规范

- **使用中文注释**
- **文件头部注释**: 说明作者、日期、功能描述
- **函数/方法注释**: 说明功能、参数、返回值
- **行内注释**: 解释复杂逻辑

```php
<?php
/**
 * Author: dadadezhou <zhoudada97@foxmail.com>
 * Date: 2022-10-09
 * Time: 15:21
 * Description: 后台父类控制器
 */

class admin_control extends control {
    public $_uid = 0;   // 用户ID

    /**
     * 构造函数
     */
    function __construct() {
        // hook admin_admin_control_construct_before.php
        $r = $this->user->user_token_check();
        // hook admin_admin_control_construct_after.php
    }
}
```

### 79.5 Hook 标记规范

Hook 标记用于在编译时动态插入插件代码。标记格式：

```
// hook {位置}_{时机}.php
```

**位置命名规则**:

```
{文件}_{函数/方法}_{时机}

示例:
admin_admin_control_construct_before.php    ← admin_control::__construct() 之前
admin_admin_control_construct_after.php     ← admin_control::__construct() 之后
runtime_model_xget_cfg_after.php            ← runtime::xget() 之后
models_model_xadd_after.php                 ← models::xadd() 之后
base_control_construct_after.php            ← base_control::__construct() 之后
```

**完整 Hook 标记示例**:

```php
function __construct() {
    // hook admin_admin_control_construct_before.php
    $r = $this->user->user_token_check();
    // hook admin_admin_control_construct_user_token_check_after.php
    if($r['err']){
        // hook admin_admin_control_admauth_failed.php
    }else{
        // hook admin_admin_control_admauth_success_before.php
        $this->_uid = $r['user']['uid'];
        // hook admin_admin_control_admauth_success.php
    }
    // hook admin_admin_control_construct_after.php
}
```

**Hook 编译原理**: 框架在编译时，会查找所有已启用的插件目录中对应的 hook 文件，将其内容插入到标记位置。

```php
// 编译后效果（示意）
function __construct() {
    // === 插件A的代码 ===
    // do something...
    // === 结束 ===
    $r = $this->user->user_token_check();
    // === 插件B的代码 ===
    // do something...
    // === 结束 ===
}
```

## 79.6 代码风格规范

### PHP 代码风格

LeCMS 采用 **Tab 缩进** 而非空格，遵循以下代码风格规则：

| 规则 | 说明 | 正确示例 | 错误示例 |
|------|------|---------|---------|
| **缩进** | 使用 Tab（4 个空格宽） | `\tclass xxx {` | `    class xxx {` |
| **大括号** | `{` 放行尾，`}` 独占一行 | `if($a) {` | `if($a){\n}` |
| **PHP 标签** | 使用完整标签 `<?php` | `<?php` | `<?` |
| **结束标签** | 不加 `?>` | （文件以 `}` 结束） | `?>\n` |
| **空格** | 运算符两侧加空格 | `$a = $b + 1;` | `$a=$b+1;` |
| **注释** | 使用中文注释 | `// 用户登录验证` | `// user login check` |

**代码示例**:

```php
<?php
defined('ROOT_PATH') or exit;

/**
 * 用户控制器
 * 处理用户注册、登录、个人信息等
 */
class user_control extends base_control {

    public function index() {
        // hook user_control_index_before.php

        // 获取用户 ID
        $uid = R('uid', 'G');

        if($uid) {
            // 查询用户信息
            $user = $this->user->get($uid);
            $this->assign('user', $user);
        }

        // hook user_control_index_after.php
        $this->display('user_index.htm');
    }
}
```

## 80. Layui 后台开发

LeCMS 后台基于 Layui 2.x 框架 + LayuiMini 构建，采用左侧菜单 + 右侧内容的经典布局。

### 80.1 后台页面结构

**入口文件**: `admin/index.php`

```php

define('F_APP_NAME', 'admin');

require ROOT_PATH.'lecms/xiunophp/xiunophp.php';
```

**后台模板结构**:

```
view/admin/
  index.htm              ← 后台主框架（LayuiMini 布局）
```

### 80.2 表格组件

使用 `layui.table.render()` 渲染数据表格：

```javascript
// 后台模板中的 JavaScript
layui.use(['table', 'form'], function(){
    var table = layui.table;
    var form = layui.form;

    // 渲染表格
    table.render({
        elem: '#dataTable',           // 表格元素选择器
        url: 'index.php?content-index-mid-2&isajax=1',  // 数据接口
        method: 'get',
        cellMinWidth: 80,
        cols: [[
            {type: 'checkbox', fixed: 'left'},
            {field: 'id', title: 'ID', width: 80, sort: true},
            {field: 'title', title: '标题'},
            {field: 'cid', title: '分类', width: 100},
            {field: 'dateline', title: '发布时间', width: 170},
            {field: 'views', title: '浏览', width: 80},
            {title: '操作', width: 200, toolbar: '#barTool'}
        ]],
        page: true,                    // 开启分页
        limit: 20,
        limits: [10, 20, 50, 100],
    });

    // 搜索表单提交
    form.on('submit(search)', function(data){
        table.reload('dataTable', {
            where: data.field,
            page: {curr: 1}
        });
        return false;
    });

    // 行工具栏事件
    table.on('tool(dataTable)', function(obj){
        var data = obj.data;
        if(obj.event === 'edit'){
            window.location.href = 'index.php?content-add-mid-2-id-'+data.id;
        } else if(obj.event === 'del'){
            layer.confirm('确定删除？', function(){
                // AJAX 删除
            });
        }
    });
});
```

**后端数据格式**:

```php
// 控制器中返回 Layui table 需要的格式
$page = max(1, (int)R('page'));
$limit = max(1, (int)R('limit'));
$total = $this->cms_content->count();
$list = $this->cms_content->find_fetch(...);

E(0, '', '', array(
    'data' => $list,
    'count' => $total,
    'code' => 0
));
```

## 81. AJAX 交互模式

### 81.1 IS_AJAX 检测

框架提供全局常量 `IS_AJAX` 用于判断请求类型：

```php

define('IS_AJAX',

    || !empty(R('ajax', 'R'))) ? true : false
```

**判断方式**:
1. 检查 `HTTP_X_REQUESTED_WITH` 请求头（jQuery 自动添加）
2. 检查 URL 参数中是否有 `ajax=1`

### 81.2 message() 方法

`control` 基类提供了统一的 AJAX/页面响应方法：

```php
/**
 * 发送消息
 * @param int    $status  状态 (1=成功, 0=失败)
 * @param string $message 消息内容
 * @param string $jumpurl 跳转 URL
 * @param int    $delay   跳转延迟（秒）
 */
public function message($status, $message, $jumpurl = '', $delay = 2, $sys_message_file = '') {
    if(R('ajax','R')) {
        // AJAX 请求: 返回 JSON
        echo json_encode(array('status'=>$status, 'message'=>$message, 'jumpurl'=>$jumpurl, 'delay'=>$delay));
    }else{
        // 页面请求: 渲染跳转页面
        if(empty($jumpurl)) {
            $jumpurl = empty($_SERVER['HTTP_REFERER']) ? '' : $_SERVER['HTTP_REFERER'];
        }
        if($sys_message_file && is_file($sys_message_file)){
            include $sys_message_file;
        }else{
            include FRAMEWORK_PATH.'tpl/sys_message.php';
        }
    }
    exit;
}
```

### 81.3 请求/响应流程

```
AJAX 请求
  │
  ├── 控制器调用 $this->message(1, '操作成功')
  │       │
  │       └── IS_AJAX = true
  │           └── echo json_encode({status:1, message:'操作成功', jumpurl:'', delay:2})
  │
  └── 页面请求调用 $this->message(1, '操作成功', 'index.php?index-index')
          │
          └── IS_AJAX = false
              └── 渲染跳转页面（2秒后跳转到指定 URL）
```

## 83. 缓存管理技巧

LeCMS 采用三级缓存体系：运行时缓存（数据库） + 文件缓存 + 可选的外部缓存（Memcache/Redis）。

### 83.1 运行时缓存

运行时缓存存储在数据库 `runtime` 表中，用于缓存配置、导航菜单等频繁访问的数据。

**源码位置**: `d:\phpstudy_pro\WWW\aimuchen100.com\lecms\model\runtime_model.class.php`

```php

class runtime extends model {
    public $table = 'runtime';     // 表名
    public $pri = array('k');      // 主键
}
```

**核心方法**:

```php
// 读取缓存
$data = $this->runtime->get($k);
// 内部逻辑: 自动 JSON 解码，检查过期时间
// 主键超过 32 字符时自动 MD5 截短

// 写入缓存
$this->runtime->set($k, $s, $life = 0);
// $life: 过期时间（秒），0 表示永不过期

// 业务配置读取
$cfg = $this->runtime->xget('cfg');

// 业务配置修改
$this->runtime->xset('webname', '新网站名称');
$this->runtime->xsave('cfg');
// 或批量保存
$this->runtime->save_changed();

// 删除缓存
$this->runtime->xdelete('key');
```

## 85. 数据库访问规范

### 85.1 LeCMS 没有全局 `db()` 函数

LeCMS 中**不存在**全局函数 `db()`。在非 control 上下文中调用 `db()` 会导致 **Fatal Error**。

```
正确获取 db 对象的路径：

1. control 类中：$this->db（通过 control::__get('db') 懒加载）
2. model 基类子类：$this->db（继承自 model 基类）
3. install.php 中：$this->db（$this 指向 plugin_control 实例）
4. 独立类中：构造函数注入（见下方模式）
5. Hook 文件中：$this->db（Hook 被内联到 control 方法中，$this 可用）
6. Cron/CLI 中：手动 new db_type($config)
```

### 85.2 非 control 类的 db 注入模式

对于工具类、适配器、队列等不继承 control/model 的类，必须通过构造函数注入 db：

```php
<?php
class my_adapter {
    private $db;
    private $site_id;

    public function __construct($site_id = 0, $db = null) {
        $this->site_id = (int)$site_id;
        $this->db = $db;  // db 对象通过构造函数传入
    }

    public function do_something() {
        // 安全使用：检查 db 是否已注入
        if (!$this->db) {
            throw new RuntimeException('my_adapter 需要注入 db 对象');
        }

        $pre = $this->db->tablepre;
        $this->db->query("INSERT INTO `{$pre}my_table` ...");
    }
}

// 调用方（control 中）：
$adapter = new my_adapter($site_id, $this->db);
```

**已采用此模式的插件组件：**

| 插件 | 类名 | 注入方式 |
|------|------|---------|
| ai_search_monitor | report_generator | `new report_generator($site_id, $this->db)` |
| multi_language | translation_engine | `new translation_engine($site_id, $db)` |
| ai_content_factory | ai_api_adapter | `new ai_api_adapter($task['site_id'], $this->db)` |
| enterprise_seo | enterprise_content_generator | `new enterprise_content_generator($site_id, $this->db)` |
| patch_system | patch_manager | `new patch_manager($this->site_id, $this->db)` |
| self_media_sync | sync_queue | `new sync_queue($site_id, $db)` |
| competitor_analysis | analysis_engine | `new analysis_engine($site_id, $db)` |

### 85.3 model 基类方法签名

继承 model 基类的模型必须遵循以下方法签名：

```php
<?php
class my_model extends model {
    // 构造函数必须设置 $this->table 和 $this->pri
    public function __construct() {
        $this->table = 'my_table';
        $this->pri = array('id');         // 主键字段名
        $this->maxid = 'id';              // 自增字段名
    }

    // 创建记录：传入完整数据数组（包含主键以外的所有字段）
    // 返回：新记录的主键值
    public function create($data) {
        // 父类 model::create() 会自动处理 INSERT
        // 数据数组中包含主键信息
        return parent::create($data);
    }

    // 更新记录：传入包含主键的完整数据数组
    // 注意：不是 update($id, $data) 而是 update($data)
    public function update($data) {
        // $data 中必须包含主键字段
        // 如：$data = array('id' => 1, 'name' => 'new_name');
        return parent::update($data);
    }

    // 获取单条记录
    public function get($id) {
        return parent::get($id);
    }
}
```

> [!WARNING]
> **`model::update()` 签名：**
> - **正确**：`update($data)` — `$data` 是包含主键的完整数组
> - **错误**：`update($id, $data)` — 不支持此签名
>
> ```php
> // 正确
> $this->my_model->update(array('id' => 1, 'name' => 'new_name'));
>
> // 错误
> $this->my_model->update(1, array('name' => 'new_name'));
> ```

### 85.4 `$this->db->update()` 方法签名陷阱

`db->update()` 的签名与常见框架（如 Laravel）不同：

```php
<?php
// LeCMS db->update() 实际签名：
// update($key, $data)
// $key: 格式为 "table-column" 的字符串
// $data: SET 的值

// 示例：
$this->db->update("{$tablepre}my_table-updated_at", $new_timestamp);

// 如果需要 WHERE 条件，使用直接 SQL：
$sql = "UPDATE `{$tablepre}my_table`
        SET `name` = :name, `updated_at` = :time
        WHERE `id` = :id";
$this->db->query($sql, array(
    ':name' => $name,
    ':time' => $_ENV['_time'],
    ':id' => $id,
));
```

**WHERE 条件 UPDATE 的标准写法：**

```php
<?php
// 封装为可复用的更新方法
public function update_record($id, $data) {
    if (empty($data)) return false;

    $set = array();
    foreach ($data as $k => $v) {
        $set[] = "`{$k}` = '" . $this->db->escape($v) . "'";
    }

    $sql = "UPDATE `{$this->table}` SET " . implode(', ', $set) . " WHERE `id` = :id";
    return $this->db->query($sql, array(':id' => (int)$id));
}
```

### 85.5 db 对象的 `$db->tablepre` 属性

所有 db 对象（`db_mysql`、`db_pdo_mysql`）都提供 `$db->tablepre` 属性获取当前表前缀：

```php
<?php
// 正确：使用 $db->tablepre
$pre = $this->db->tablepre;
$sql = "SELECT * FROM `{$pre}cms_content` WHERE ...";

// 也可以直接访问配置
$pre = $_ENV['_config']['db']['master']['tablepre'];
```

> [!NOTE]
> `$db->tablepre` 与 `$_ENV['_config']['db']['master']['tablepre']` 是同一个值。
> 在非 control 类中（如适配器、工具类），`$this->db` 为 null 时，
> 可以使用 `$_ENV['_config']` 作为 fallback，但优先通过构造函数注入 db。

### 85.6 常见数据库错误速查

| 错误现象 | 原因 | 解决方案 |
|---------|------|---------|
| `Call to undefined function db()` | 调用了不存在的全局 db() 函数 | 改用 `$this->db` 或构造函数注入 |
| `$this->db->update() 不生效` | update() 签名错误（传了 4 个参数） | 改用直接 SQL UPDATE |
| `$db->fetch_first() 报错` | 使用非 control 类中未定义的 `$db` | 通过构造函数注入或使用 `$this->db` |
| `date() 写入 INT 列后查询异常` | DATETIME 字符串与 INT UNSIGNED 列不匹配 | 使用 `$_ENV['_time']` |
| `Undefined variable: db` | install.php 中使用 `$db` 而非 `$this->db` | 统一使用 `$this->db` |
| `Call to undefined method model::update($id, $data)` | model 基类 update() 只接受一个数组参数 | 改为 `$this->update(array('id' => $id, ...))` |

### 86. 插件开发常见陷阱

基于实际插件（如 site_manager）开发中遇到的错误，总结以下高频陷阱：

**86.1 模型类名陷阱**

| 错误 | 正确 | 说明 |
|------|------|------|
| `class site_manager_model extends model` | `class site_manager extends model` | 类名去掉 `_model` 后缀 |
| `core::model('site_manager_model')` | `core::model('site_manager')` | 框架自动去掉 `_model` 后缀查找文件 |
| 手动 `require_once` 模型文件 | 删除 require_once，框架自动加载 | 避免双重加载导致 "Cannot declare class" |

**86.2 模板 Include 路径陷阱**

```php
// {inc:} 标签解析规则：
// {inc:header.htm}     → 查找插件根目录下的 header.htm
// {inc:admin/header.htm} → 解析为 admin/inc-header.htm，只在插件根目录查找

// ❌ 错误：将 header.htm 放在 plugin/site_manager/admin/inc-header.htm
// 框架不会递归子目录，找不到文件

// ✅ 正确：将 header.htm 放在 plugin/site_manager/header.htm
// 模板中引用 {inc:header.htm}
```

**86.3 安全头陷阱**

```php
// ❌ 错误：模型文件没有安全头
<?php
class site_manager extends model {
}

// ✅ 正确：所有 PHP 文件第一行必须有安全头
<?php
defined('ROOT_PATH') or exit;
class site_manager extends model {
```

**86.4 文件组织陷阱**

```
get_original_file() 查找顺序（无 admin/ 子目录！）：
  1. plugin/{p}/APP_NAME/{文件名}
  2. plugin/{p}/{文件名}                    ← 根目录
  3. plugin/{p}/control/{文件名}
  4. plugin/{p}/model/{文件名}              ← 模型放这里能查到
  5. plugin/{p}/block/{文件名}

所以：
  - 控制器：严禁放 admin/（找不到），必须放根目录   ← 关键！
  - 模板：  严禁放 admin/（找不到），必须放根目录   ← 关键！
  - 模型：  可以放 model/ 子目录（第4步能查到）     ← 保留现状即可
  - Hook：  可以放 hook/ 子目录或根目录             ← 两种都支持
```

| 问题 | 错误 | 正确 |
|------|------|------|
| 控制器 | `plugin/x/admin/xxx_control.class.php` | `plugin/x/xxx_control.class.php` |
| 模板 | `plugin/x/admin/xxx.htm` | `plugin/x/xxx.htm` |
| 模型 | 同下（放 model/ 也合法） | `plugin/x/model/xxx_model.class.php` |

> [!WARNING]
> **admin/ 子目录是框架盲区**：get_original_file 不查找 admin/。控制器和模板放在 admin/ 下会导致找不到文件（报"模板文件不存在"或"控制器不存在"）。所有启用插件的 admin/ 子目录已统一清理为根目录平铺。

**86.4-bis `{inc:}` 自动加 `inc-` 前缀**

```
框架 process_inc() 自动转换：
  {inc:header.htm}       → 查找 inc-header.htm
  {inc:footer.htm}       → 查找 inc-footer.htm
  {inc:admin/header.htm} → 查找 admin/inc-header.htm

系统 fallback 模板（无需插件提供）：
  view/default/inc-header.htm   ← {inc:header.htm} 的 fallback
  view/default/inc-footer.htm   ← {inc:footer.htm} 的 fallback

错误：在插件根目录创建 header.htm/footer.htm（不会被用到，框架找的是 inc-header.htm）
正确：直接用 {inc:header.htm}/{inc:footer.htm}，系统模板自动 fallback
```

**86.5 模板标签语法陷阱**

LeCMS 模板引擎（XiunoPHP tpl）的标签必须带冒号，缺少冒号时标签不识别，原样输出到浏览器。

| 标签 | ❌ 错误写法 | ✅ 正确写法 |
|------|-----------|-----------|
| loop | `{loop sites $site}` | `{loop:$sites $site}` |
| if | `{if $status==1}` | `{if:$status==1}` |
| if | `{if empty($arr)}` | `{if:empty($arr)}` |
| elseif | `{elseif $a==1}` | `{elseif:$a==1}` |
| 变量访问 | `{$site.name}` | `{$site['name']}` |

```html
<!-- ❌ 错误：缺少冒号，输出原始标签到页面 -->
{loop sites $site}
{if $site['status']==1}启用{/if}
{if empty(sites)}暂无数据{/if}

<!-- ✅ 正确 -->
{loop:$sites $site}
{if:$site['status']==1}启用{/if}
{if:empty($sites)}暂无数据{/if}
```

**86.6 `assign()` 引用传递陷阱**

```php
// control::assign() 签名：assign($k, &$v) — 第二个参数是引用传递
// 不能直接传函数返回值，PHP 不允许引用临时表达式

// ❌ 错误：直接传函数调用结果
$this->assign('json', json_encode($data));
$this->assign('themes', $this->get_available_themes());
$this->assign('total', count($sites));

// ✅ 正确：先赋值给变量，再传递
$sites_json = json_encode($data);
$this->assign('sites_json', $sites_json);
$themes = $this->get_available_themes();
$this->assign('themes', $themes);
$total = count($sites);
$this->assign('total', $total);
```

```
报错信息：Only variables should be passed by reference
原因：assign() 内部使用引用传递 &$v，PHP 不允许引用临时表达式
```

**86.7 后台页面布局陷阱**

```
LeCMS 后台有两种页面布局风格，根据页面类型选择：

  列表页（数据表格）— 使用 layuimini 布局：
  {inc:header.htm}
  <div class="layuimini-container">
      <div class="layuimini-main">
          <fieldset class="table-search-fieldset"><legend>标题</legend>搜索表单</fieldset>
          <table class="layui-hide" id="data-table" lay-filter="..."></table>
      </div>
  </div>

  表单页（添加/编辑）— 使用 layui-card 布局：
  {inc:header.htm}
  <div class="layui-card">
      <div class="layui-card-body">
          <form id="form" class="layui-form" action="?site-{$_GET['action']}-ajax-1" method="post">
              ...
          </form>
      </div>
  </div>

  错误：表单页也使用 layuimini-container 布局（与 le_links 不一致）
```

> [!TIP]

**86.8 表单提交方式陷阱**

```
LeCMS 后台表单统一使用 AJAX 提交，提交成功后自动关闭标签页：

  错误方式（传统表单提交 + 跳转）：
  <form action="?site-create_post" method="post">
      <button class="layui-btn" lay-submit>创建</button>
      <a href="?site-index">返回列表</a>
  </form>

  正确方式（AJAX 提交 + 自动关闭标签页）：
  <form id="form" class="layui-form" action="?site-{$_GET['action']}-ajax-1" method="post">
      <button class="layui-btn" lay-submit lay-filter="form">创建</button>
  </form>

  <script>
  layui.use(['form', 'layer', 'miniTab'], function () {
      var layer = layui.layer, form = layui.form, miniTab = layui.miniTab;

      form.on('submit(form)', function () {
          adminAjax.postform('#form', function (data) {
              var json = toJson(data);
              var icon = json.err == 0 ? 1 : 5;
              layer.msg(json.msg, {icon: icon});
              if (json.err == 0) {
                  setTimeout(function(){
                      miniTab.reloadIframe('index.php?site-index');
                      miniTab.deleteCurrentByIframe();
                  }, 1500);
              }
          });
          return false;
      });
  </script>
```

> [!WARNING]
> 表单页不需要"返回列表"按钮。AJAX 提交成功后，`miniTab.deleteCurrentByIframe()` 会自动关闭当前标签页。

**86.9 控制器方法分裂陷阱**

```
LeCMS 后台控制器统一使用一个方法处理 GET（显示表单）和 POST（处理提交）：

  错误方式（两个方法）：
  public function create() { ... 显示表单 ... }
  public function create_post() { ... 处理提交 ... }

  正确方式（一个方法，内部判断）：
  public function create() {
      if (form_submit()) {
          // POST：处理提交
          $this->message(0, '创建成功');
      }
      // GET：显示表单
      $this->assign('themes', $themes);
      $this->display();
  }
```

```php
// 完整示例（对齐 le_links 模式）：
public function create() {
    if(form_submit()) {
        $site_name = trim(R('site_name', 'P'));

    }

    $this->assign('themes', $themes);
    $this->display('site_create.htm');
}
```

**86.11 Smarty 语法陷阱**

LeCMS 模板引擎是 XiunoPHP，不支持 Smarty/Twig 语法。以下常见外来语法需要全面转换：

| Smarty/Twig | XiunoPHP | 说明 |
|-------------|----------|------|
| `{foreach $arr as $v}` | `{loop:$arr $v}` | 循环标签 |
| `{foreach $arr as $k $v}` | `{loop:$arr $v $k}` | 键值循环 |
| `{/foreach}` | `{/loop}` | 循环结束 |
| `{$var.key}` | `{$var['key']}` | 点号→数组 |
| `{$var.key\|filter}` | `{$var['key']}` | 过滤器不支持 |
| `{$var\|escape}` | `{$var}` | 过滤器不支持 |
| `{$var.key\|default:0}` | `{php}echo isset($var['key'])?...{/php}` | 默认值用 PHP |
| `{@last}` | 不支持 | 改用 `{php}` 块 |
| `{$x==1?'是':'否'}` | `{@$x==1?'是':'否'}` | 三元用 `{@expr}` |

```
❌ 错误示例:
{foreach $report.data.stats as $stat}
    {$stat.name|escape}: {$stat.value|default:0|round:1}
{/foreach}

✅ 正确转换:
{loop:$report['data']['stats'] $stat}
    {$stat['name']}: {$stat['value']}
{/loop}
```

> [!WARNING]
> 多层点号 `{$a.b.c}` 需逐级展开为 `{$a['b']['c']}`。嵌套数据结构建议在控制器端处理为简单数组后再传模板。
