## 42. 插件架构与加载流程

### 42.1 插件加载流程

```
1. 系统初始化 (core::init_start)
    ↓
2. 加载框架 (xiunophp.php)
    ↓
3. 加载核心类 (core.class.php)
    ↓
4. 扫描插件目录 (PLUGIN_PATH = lecms/plugin/)
    ↓
5. 解析每个插件的 conf.php
    ↓
6. 读取 plugin.inc.php 中的启用状态
    ↓
7. 按 rank 排序已启用插件
    ↓
8. 编译控制器/模型时注入 Hook
    ↓
9. 运行时执行编译后的代码
```

### 42.2 插件配置解析

```php
// core.class.php 中的 get_plugins()
public static function get_plugins($force = 0) {
    static $plugins = array();
    if(!empty($plugins) && !$force) return $plugins;

    if(!is_dir(PLUGIN_PATH)) return array();

    // 扫描插件目录
    $plugin_dirs = get_dirs(PLUGIN_PATH);

    // 加载插件配置
    $plugin_arr = is_file(CONFIG_PATH.'plugin.inc.php') ?
        (array)include(CONFIG_PATH.'plugin.inc.php') : array();

    foreach($plugin_dirs as $dir) {
        // 读取插件配置
        $cfg = is_file(PLUGIN_PATH.$dir.'/conf.php') ?
            (array)include(PLUGIN_PATH.$dir.'/conf.php') : array();

        // 支持多语言配置
        if(isset($_ENV['_config']['admin_lang']) &&
           is_file(PLUGIN_PATH.$dir.'/conf_'.$_ENV['_config']['admin_lang'].'.php')) {
            $cfg = (array)include(PLUGIN_PATH.$dir.'/conf_'.$_ENV['_config']['admin_lang'].'.php');
        }

        $cfg['rank'] = isset($cfg['rank']) ? (int)$cfg['rank'] : 100;

        // 分类插件
        if(empty($plugin_arr[$dir])) {
            $plugins['not_install'][$dir] = $cfg;
        } elseif(empty($plugin_arr[$dir]['enable'])) {
            $plugins['disable'][$dir] = $cfg;
        } else {
            $plugins['enable'][$dir] = $cfg;
        }
    }

    // 按 rank 排序
    _array_multisort($plugins['enable'], 'rank');
    _array_multisort($plugins['disable'], 'rank');
    _array_multisort($plugins['not_install'], 'rank');

    return $plugins;
}
```

## 43. 插件目录结构详解

### 43.1 目录结构总览

每个插件都是一个独立的目录，位于 `plugin/` 目录下。完整的插件目录结构如下：

**模式一：平铺模式（推荐，对齐 `le_links`）**

```
plugin/{插件名}/
├── conf.php                      # 插件配置（必须）
├── install.php                   # 安装脚本（可选）
├── uninstall.php                 # 卸载脚本（可选）
├── {插件名}_control.class.php    # 控制器（可选，平铺在根目录）
├── {插件名}_model.class.php      # 模型（可选，平铺在根目录）
├── header.htm                    # 后台头部模板（可选，供 {inc:header.htm} 引用）
├── {控制名}_{动作}.htm           # 页面模板（可选，平铺在根目录）
├── block_{名称}.lib.php          # Block 函数库（可选）
├── lang_zh-cn.php                # 前台语言包（可选）
├── lang_en.php                   # 前台语言包英文版（可选）
├── lang_zh-cn_admin.php          # 后台语言包（可选）
├── lang_en_admin.php             # 后台语言包英文版（可选）
├── hook/                         # Hook 文件目录（可选）
│   ├── xxx_before.php
│   └── xxx_after.php
├── static/                       # 静态资源（可选）
│   ├── css/
│   │   └── style.css
│   └── js/
│       └── common.js
└── view/                         # 前台模板覆盖（可选）
    └── xxx.htm
```

**模式二：子目录模式**

```
plugin/{插件名}/
├── conf.php
├── install.php
├── lang_zh-cn.php
├── lang_en.php
├── lang_zh-cn_admin.php
├── lang_en_admin.php
├── hook/                         # Hook 文件目录（可选）
│   ├── xxx_before.php
│   └── xxx_after.php
├── block/                        # Block 模块（可选）
│   └── block_xxx.lib.php
├── control/                      # 前台控制器（可选）
│   └── xxx_control.class.php
├── model/                        # 前台模型（可选）
│   └── xxx_model.class.php
├── admin/                        # 后台模块（可选）
│   ├── control/
│   │   └── xxx_control.class.php
│   ├── view/
│   │   └── xxx.htm
│   └── hook/
│       └── xxx_after.php
├── lecms/                        # LeCMS 专用文件（可选，优先级高于 control/model/block）
│   ├── control/
│   │   └── xxx_control.class.php
│   ├── model/
│   │   └── xxx_model.class.php
│   └── block/
│       └── block_xxx.lib.php
└── static/                       # 静态资源（可选）
    ├── css/
    └── js/
```

> [!TIP]
> **推荐使用平铺模式**。框架在编译控制器/模型/模板时，查找顺序为：插件根目录 → `admin/` 子目录 → `control/` 子目录。将文件平铺在插件根目录可避免路径查找问题，且与 `le_links` 等系统插件保持一致。

### 43.2 各目录作用说明

| 目录/文件 | 说明 | 是否必须 |
|-----------|------|----------|
| `conf.php` | 插件元数据和配置 | 必须 |
| `install.php` | 安装时执行的脚本（建表、初始化数据等） | 可选 |
| `uninstall.php` | 卸载时执行的清理脚本 | 可选 |
| `hook/` | 放置 Hook 文件，用于注入核心代码 | 可选 |
| `block/` | 放置 Block 类文件，提供前台数据调用标签 | 可选 |
| `control/` | 放置前台控制器，处理前台请求 | 可选 |
| `model/` | 放置前台数据模型 | 可选 |
| `view/` | 覆盖系统模板或提供插件模板 | 可选 |
| `lecms/` | LeCMS 框架专用目录，优先级高于 control/model/block | 可选 |
| `admin/` | 后台功能模块 | 可选 |
| `static/` | CSS、JS 等静态资源 | 可选 |
| `lang_*.php` | 多语言包文件 | 可选 |

### 43.3 文件命名规范

| 文件类型 | 命名规范 | 示例 |
|----------|---------|------|
| 控制器 | `{名称}_control.class.php` | `sitemap_control.class.php` |
| 模型 | `{名称}_model.class.php` | `site_manager_model.class.php` |
| Block | `block_{名称}.lib.php` | `block_links.lib.php` |
| 安装脚本 | `install.php` | - |
| 卸载脚本 | `uninstall.php` | - |
| 语言包 | `lang_{语言码}.php` | `lang_zh-cn.php` |
| 后台语言包 | `lang_{语言码}_admin.php` | `lang_zh-cn_admin.php` |

**模型类名规则（必须遵守）：**
- 文件名：`{名称}_model.class.php`
- 类名：`{名称}`（**去掉 `_model` 后缀**）
- 示例：文件 `site_manager_model.class.php` → 类名 `class site_manager extends model`
- 示例：文件 `links_model.class.php` → 类名 `class links extends model`
- 框架约定：`core::model('site_manager')` 自动映射到文件 `site_manager_model.class.php` 中的 `site_manager` 类
- **错误示例**：类名 `site_manager_model` → 与框架自动加载冲突，触发 "Cannot declare class" 致命错误

| 类型 | 特点 | 典型插件 | 关键文件 |

## 45. 插件配置文件 conf.php

`conf.php` 是每个插件必须存在的配置文件，返回一个 PHP 数组，包含插件的元数据和配置信息。

### 45.1 配置项说明

```php
return array(
    // 基础信息
    'name'        => '插件名称',           // 显示名称（必须）
    'brief'       => '插件简介',           // 简短描述（必须）
    'description' => '详细描述...',        // 详细说明（可选）
    'version'     => '1.0.0',             // 当前版本号（必须）
    'cms_version' => '3.0.0',            // 兼容的 CMS 最低版本（必须）
    'update'      => '2022-12-16',        // 最后更新日期（必须）

    // 作者信息
    'author'      => '作者名',             // 作者名称（必须）
    'authorurl'   => 'https://...',       // 作者网站（可选）

    // 功能配置
    'setting'     => '',                  // 设置页URL（留空=无设置页）
    'rank'        => 100,                 // 加载优先级（越小越先加载）
);
```

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `name` | string | - | 插件显示名称，在后台插件列表中展示 |
| `brief` | string | - | 插件简要介绍，通常一句话 |
| `description` | string | - | 详细描述，可包含换行 |
| `version` | string | - | 插件版本号，语义化版本 |
| `cms_version` | string | - | 插件兼容的 LeCMS 最低版本 |
| `update` | string | - | 最后更新日期，格式 YYYY-MM-DD |
| `author` | string | - | 作者名称 |
| `authorurl` | string | - | 作者网站或个人主页 |
| `setting` | string | `''` | 设置页面的 URL 路径，留空表示插件没有设置页面 |
| `rank` | int | `100` | 插件加载优先级，数值越小越先加载 |

### 45.2 多语言配置

插件支持多语言配置，通过在插件根目录放置不同语言版本的 `conf.php` 来实现：

```php
// conf.php (默认)
return array('name' => 'My Plugin');

// conf_en.php (英文版)
return array('name' => 'My Plugin');

// conf_zh-cn.php (中文版)
return array('name' => '我的插件');
```

系统会根据后台设置的语言自动选择对应的配置文件：
```php
// core.class.php 中的加载逻辑
$admin_lang = $_ENV['_config']['admin_lang'];  // 如 'zh-cn'
$conf_file = PLUGIN_PATH.$dir.'/conf_'.$admin_lang.'.php';
if(is_file($conf_file)) {
    $cfg = (array)include($conf_file);
}
```

## 46. 插件状态管理

### 46.1 plugin.inc.php 状态文件

插件的启用/禁用状态存储在 `conf/plugin.inc.php` 文件中，该文件由系统自动管理：

```php
<?php
return array(
    // 已安装并启用的插件
    'le_links' => array(
        'enable' => 1,                    // 1=启用, 0=禁用
        'install_time' => 1670000000,     // 安装时间戳
    ),

    // 已安装但禁用的插件
    'le_rand_pic' => array(
        'enable' => 0,
        'install_time' => 1670000000,
    ),

    // 未安装的插件不会出现在此文件中
);
```

**状态说明：**

| 状态 | enable 值 | 说明 |
|------|-----------|------|
| 已安装并启用 | `1` | 插件已安装，Hook 和功能正常生效 |
| 已安装但禁用 | `0` | 插件已安装但不加载，Hook 不生效 |
| 未安装 | 不包含 | 插件文件存在但未安装，不加载 |

### 46.2 安装/卸载脚本

**install.php 正确模板：**
```php
<?php
// plugin/{插件名}/install.php

// 文件头必须使用 ROOT_PATH（不是 IN_ADMIN，不是 IN_APP）
defined('ROOT_PATH') || exit;

// 获取表前缀
$tablepre = $_ENV['_config']['db']['master']['tablepre'];

// 使用 $this->db 执行 SQL（install.php 在 plugin_control::install() 中被 include，
// $this 指向 plugin_control 实例，$this->db 可用）
$sql = "CREATE TABLE IF NOT EXISTS `{$tablepre}my_plugin_data` (
    `id` int(10) unsigned NOT NULL AUTO_INCREMENT,
    `name` varchar(255) NOT NULL DEFAULT '',
    `value` text NOT NULL,
    `created_at` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '创建时间',
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4";

$this->db->query($sql);

// 写入默认数据
$now = $_ENV['_time'];
$this->db->query("INSERT INTO `{$tablepre}my_plugin_data` (`name`, `created_at`)
    VALUES ('default', {$now})");

// 注意：install.php 末尾不要写 return $ret; 或其他 return 语句
// 原因：install.php 被 include 调用，return 值无法被接收，且会触发 PHP parse error
```

**uninstall.php 正确模板：**
```php
<?php
// plugin/{插件名}/uninstall.php

defined('ROOT_PATH') || exit;

$tablepre = $_ENV['_config']['db']['master']['tablepre'];

// 清理数据（通常只删数据不删表结构，保留数据以便重新安装）
$this->db->query("DELETE FROM `{$tablepre}my_plugin_data` WHERE 1");

// 注意：同样不要写 return 语句
```

> [!WARNING]
> **常见错误与正确写法对照：**
>
> | 错误写法 | 正确写法 | 说明 |
> |---------|---------|------|
> | `defined('IN_ADMIN')` | `defined('ROOT_PATH')` | 安全头必须使用 ROOT_PATH |
> | `defined('IN_APP')` | `defined('ROOT_PATH')` | IN_APP 不是 LeCMS 标准常量 |
> | `return $ret;` | 无 return | include 上下文无法接收 return 值 |
> | `return $ret1 && $ret2;` | 无 return | 同上 |
> | `$db->query($sql)` | `$this->db->query($sql)` | install.php 中 $db 未定义，必须用 `$this->db` |
> | `time()` | `$_ENV['_time']` | 时间戳列使用 INT UNSIGNED，统一用 `$_ENV['_time']` |
> | `date('Y-m-d H:i:s')` 写入 INT 列 | `$_ENV['_time']` | INT UNSIGNED 列存 Unix 时间戳整数 |
>
> [!TIP]
> **install.php 执行上下文：**
> - 被 `plugin_control::install()` 方法 `include` 调用
> - `$this` 指向 `plugin_control` 实例
> - `$this->db` 可用（通过 `control::__get('db')` 懒加载）
> - `$_ENV['_config']` 已初始化
> - 不能 return 值，所有操作通过副作用完成（建表、插数据）

### 46.3 插件生命周期

```
安装:  后台点击安装 → 执行 install.php → 写入 plugin.inc.php
       ↓
启用:  enable = 1 → 加载 conf.php → 按 rank 排序 → 注入 Hook
       ↓
运行:  编译时注入 Hook → 运行时执行编译后代码
       ↓
禁用:  enable = 0 → 不加载 Hook → 插件功能停止（配置保留）
       ↓
卸载:  后台点击卸载 → 执行 uninstall.php → 清除 plugin.inc.php 记录
```

**生命周期各阶段说明：**

| 阶段 | 操作 | 数据保留 |
|------|------|---------|
| 安装 | 执行 install.php，注册到 plugin.inc.php | 全部保留 |
| 启用 | enable=1，加载 Hook | 全部保留 |
| 禁用 | enable=0，不加载 Hook | 配置保留，Hook 不执行 |
| 卸载 | 执行 uninstall.php，移除注册 | 插件文件保留在磁盘 |

### 46.4 插件数据库访问规范

**核心原则：LeCMS 没有全局 `db()` 函数。**

所有数据库访问必须通过已注入的 `$this->db`（control 上下文）或构造函数参数（非 control 类）。

```
数据库访问方式对照表：

| 上下文 | 正确方式 | 错误方式 |
|--------|---------|---------|
| control 类方法 | `$this->db->query($sql)` | `db()->query($sql)` ✗ |
| model 基类子类 | `$this->db->query($sql)` | `db()->query($sql)` ✗ |
| install.php | `$this->db->query($sql)` | `$db->query($sql)` ✗ |
| uninstall.php | `$this->db->query($sql)` | `$db->query($sql)` ✗ |
| Hook 文件 | `$this->db->query($sql)` | `db()->query($sql)` ✗ |
| 独立工具类 | 构造函数注入 `$db` | 直接调用 `db()` ✗ |
| Cron 脚本 | `new db_type($config)->db` | `db()->query($sql)` ✗ |
```

**非 control 类的数据库注入模式：**

```php
<?php
// 工具类/适配器/队列等非 control 类

class my_tool {
    private $db;      // 必须声明 db 属性
    private $site_id;

    // 构造函数接收 db 对象（默认为 null 兼容无 db 场景）
    public function __construct($site_id = 0, $db = null) {
        $this->site_id = (int)$site_id;
        $this->db = $db;
    }

    public function do_something() {
        // 安全访问：检查 db 是否注入
        if (!$this->db) {
            return false;  // 或抛异常
        }

        $tablepre = $this->db->tablepre;
        $this->db->query("INSERT INTO `{$tablepre}my_table` ...");
    }
}

// 调用方（control 中）：
$tool = new my_tool($site_id, $this->db);
$tool->do_something();
```

**Hook/Cron 文件中初始化 db 的标准模式：**

```php
<?php
// Hook 或 Cron 文件中需要数据库访问时

$tablepre = $_ENV['_config']['db']['master']['tablepre'];
$db_type = 'db_' . $_ENV['_config']['db']['type'];
$db = new $db_type($_ENV['_config']['db']);
$db = $db->db ?? $db;  // 兼容不同版本

// 然后使用 $db 执行查询
$rows = $db->fetch_all("SELECT * FROM `{$tablepre}my_table` ...");
```

> [!WARNING]
> **`$this->db->update()` 签名陷阱：**
>
> LeCMS 的 `db->update()` 方法签名与常见框架不同：
> ```php
> // LeCMS 实际签名：update($key, $data)
> // $key 格式为 "table-column"，$data 为 SET 值
> $this->db->update("{$tablepre}my_table-updated_at", $new_value);
> ```
>
> **不是** Laravel/ThinkPHP 风格的 `update($table, $data, $where, $params)`。
>
> 需要 WHERE 条件时，使用直接 SQL：
> ```php
> // 正确：直接写 UPDATE SQL
> $sql = "UPDATE `{$tablepre}my_table` SET `name` = :name WHERE `id` = :id";
> $this->db->query($sql, array(':name' => $name, ':id' => $id));
> ```

## 47. 插件系统详细分析

> 本节基于 LeCMS_Analysis.md 补充，对插件系统的核心机制进行深度解析。

### 47.1 插件发现与注册

**插件发现流程**:

```
core::get_plugins()
  │
  ├── 1. 扫描插件目录: PLUGIN_PATH = lecms/plugin/
  │   └── get_dirs() 获取所有子目录
  │
  ├── 2. 读取插件配置: plugin.inc.php
  │   └── 获取每个插件的 enable 状态
  │
  ├── 3. 遍历每个插件目录
  │   ├── 读取 conf.php（插件元数据）
  │   ├── 支持多语言: conf_{lang}.php
  │   └── 设置默认 rank = 100
  │
  ├── 4. 分类插件状态
  │   ├── not_install: 未在 plugin.inc.php 中注册
  │   ├── disable: enable = 0
  │   └── enable: enable = 1
  │
  └── 5. 按 rank 排序（升序，数字越小越优先）
      └── _array_multisort($plugins['enable'], 'rank')
```

**plugin.inc.php 状态文件格式**:

```php

    'le_links' => array(
        'enable' => 1,
        'install_time' => 1670000000,
    ),

        'install_time' => 1670000000,
    ),

    // 未安装的插件不会出现在此文件中

```

### 47.2 启用/禁用/排序机制

**启用/禁用**:

| 操作 | 实现方式 | 效果 |
|------|---------|------|
| 启用 | `plugin.inc.php` 中 `enable = 1` | Hook 文件在编译时注入到目标文件 |
| 禁用 | `plugin.inc.php` 中 `enable = 0` | Hook 文件不注入，插件功能完全停止 |
| 全局禁用 | `config.inc.php` 中 `plugin_disable = 1` | 跳过所有插件查找，提升性能 |

**排序（rank）机制**:

```php
// get_plugins() 中的排序逻辑
$cfg['rank'] = isset($cfg['rank']) ? (int)$cfg['rank'] : 100;

// 按 rank 升序排列
_array_multisort($plugins['enable'], 'rank');
```

| rank 值 | 加载顺序 | 适用场景 |
|---------|---------|---------|
| 0-50 | 最先加载 | 基础设施插件（如编辑器、安全防护） |
| 50-100 | 中间加载 | 通用功能插件 |
| 100+ | 最后加载 | 业务特定插件 |

**rank 的实际影响**:
- 决定插件 Hook 的注入顺序
- 决定 `get_original_file()` 中插件的查找顺序（rank 小的先查找）
- 用于解决插件之间的依赖关系

### 47.3 Hook 注入机制深度解析

**编译时注入流程**:

```
process_hook($matches)
  │
  ├── 1. 检查插件是否被全局禁用
  │   └── $_ENV['_config']['plugin_disable'] == 1 → 返回空
  │
  ├── 2. 获取所有已启用插件（按 rank 排序）
  │   └── core::get_plugins()['enable']
  │
  ├── 3. 遍历每个已启用插件
  │   ├── 查找: plugin/{插件名}/{hook名称}
  │   └── 查找: plugin/{插件名}/hook/{hook名称}
  │
  ├── 4. 对找到的 Hook 文件执行 clear_code()
  │   ├── 去除 <?php exit;?> 标记
  │   ├── 去除 <?php ... ?> 标签
  │   ├── 去除 defined('ROOT_PATH') || exit; 安全检查
  │   └── 返回纯 PHP 代码
  │
  └── 5. 将所有 Hook 代码拼接到结果中
      └── 替换原文件中的 // hook xxx 注释行
```

**Hook 文件位置对照**:

| 位置 | 路径示例 | 说明 |
|------|---------|------|
| 插件根目录 | `plugin/le_links/user.login.php` | 直接放在插件根目录 |
| Hook 子目录 | `plugin/le_links/hook/user.login.php` | 放在 hook/ 子目录中 |

**编译前后对比**:

```php
// ==================== 编译前（源文件） ====================

function custom_login() {
    // hook user.login
    echo "默认登录逻辑";
}

// ==================== 编译后（runcache/misc.func.php） ====================
function custom_login() {
    // === 插件A的 user.login Hook 代码 ===
    echo "插件A的登录增强逻辑";
    // === 结束 ===

    // === 插件B的 user.login Hook 代码 ===
    echo "插件B的登录日志记录";
    // === 结束 ===

    echo "默认登录逻辑";

```

### 47.6 风险与治理

**风险 1: Hook 冲突**

| 风险描述 | 影响 | 解决方案 |
|---------|------|---------|
| 同一 hook 点多次注入 | 代码重复执行，可能导致逻辑错误 | 使用 rank 控制顺序，注意插件间协调 |
| Hook 代码中存在同名函数 | PHP 致命错误 | Hook 文件中的函数必须加唯一前缀 |
| Hook 执行顺序不确定 | 依赖顺序的插件可能出错 | 明确设置 rank 值，文档化依赖关系 |

**风险 2: 命名污染**

| 风险描述 | 影响 | 解决方案 |
|---------|------|---------|
| 全局函数与核心冲突 | 核心功能异常 | 所有函数加插件名前缀 |
| 全局变量覆盖 | 数据混乱 | 使用 `$插件名_变量名` 格式 |
| CSS/JS 类名冲突 | 前端样式混乱 | CSS 类名加插件名前缀 |

**风险 3: 兼容性**

| 风险描述 | 影响 | 解决方案 |
|---------|------|---------|
| 框架升级后 Hook 点变更 | 插件失效 | 插件标注兼容版本，升级后验证 |
| 数据库表结构变更 | 数据读写异常 | 使用 install.php 中的升级逻辑 |
| 模板标签变更 | 模板渲染异常 | 关注框架更新日志 |

**治理建议**:

1. **插件版本管理**: 在 `conf.php` 中明确声明 `cms_version` 兼容范围
2. **代码审查**: 插件发布前审查 Hook 代码和命名规范
3. **依赖声明**: 在 `conf.php` 的 `description` 中声明插件依赖
4. **测试覆盖**: 插件应包含基本的功能测试用例
5. **日志记录**: 使用 `log::le_log()` 记录插件关键操作

## 48. 时间戳规范与常见陷阱

### 48.1 统一使用 `$_ENV['_time']` 而非 `time()`

LeCMS 使用 **INT UNSIGNED**（10 位整数）存储时间戳，而非 DATETIME 字符串：

```php
<?php
// 正确：使用 $_ENV['_time']
$now = $_ENV['_time'];
$this->db->query("INSERT INTO `{$tablepre}my_table` (`created_at`) VALUES ({$now})");

// 错误：不要使用 time() 或 date('Y-m-d H:i:s')
$this->db->query("INSERT INTO `{$tablepre}my_table` (`created_at`) VALUES ('" . date('Y-m-d H:i:s') . "')");
// ↑ DATETIME 字符串与 INT UNSIGNED 列类型不匹配，导致查询异常
```

**时间戳列类型对照：**

| 列类型 | 存储格式 | 写入方式 | 适用场景 |
|--------|---------|---------|---------|
| `INT UNSIGNED` | Unix 时间戳整数 | `$_ENV['_time']` | LeCMS 标准时间戳列 |
| `DATETIME` | `YYYY-MM-DD HH:MM:SS` | `date('Y-m-d H:i:s')` | 少数插件的兼容列 |

**核心模型中的时间戳列（全部为 INT UNSIGNED）：**
- `cms_content.dateline` — 内容发布时间
- `user.regdate` / `user.lastlogin` — 用户注册/登录时间
- `category.dateline` — 分类创建时间
- `runtime.time` — 缓存过期时间

> [!TIP]
> `$_ENV['_time']` 在 `core::init_start()` 中一次性设置，值为 `time()` 的整数结果。
> 使用统一变量而非直接调用 `time()` 的好处：便于测试时 mock 时间，确保同一请求中时间一致。

### 48.2 Hook 文件中 `dirname(__FILE__)` 的陷阱

Hook 文件在编译时被内联到 `runcache/` 目录下的缓存文件中。这意味着：

```php
<?php
// ❌ 错误：在 Hook 文件中使用 dirname(__FILE__)
require_once dirname(__FILE__) . '/model/my_model.class.php';
// 编译后 __FILE__ 指向 runcache/ 而非插件目录，路径完全错误

// ✅ 正确：使用 PLUGIN_PATH 常量
require_once PLUGIN_PATH . 'my_plugin/model/my_model.class.php';

// ✅ 正确：使用绝对路径（已知插件目录位置）
require_once ROOT_PATH . 'plugin/my_plugin/model/my_model.class.php';
```

**`__FILE__` / `__DIR__` 在编译后的值：**

| 场景 | `__FILE__` 指向 | 说明 |
|------|----------------|------|
| 原始源码 | `plugin/my_plugin/hook/xxx.php` | 开发时正确 |
| 编译后 runcache | `runcache/lecms_control/base_control.class.php` | **路径完全错误** |

> [!WARNING]
> **例外情况：** `dirname(__FILE__)` 在非 Hook 文件（如 control 文件、model 文件、install.php）中仍然正确，因为这些文件不会被编译内联。只有被 `process_hook()` 处理的 Hook 文件才会被内联。
>
> 非 Hook 文件中的 `dirname(__FILE__)` 可以正常使用，但推荐迁移到 `PLUGIN_PATH` 常量以保持一致性。

### 48.3 Cron/CLI 脚本的数据库初始化

Cron 脚本和 CLI 入口没有 `$this->db`，需要手动初始化：

```php
<?php
// plugin/{插件名}/cron.php

define('ROOT_PATH', true);          // 使用 ROOT_PATH 而非 IN_APP
define('APP_PATH', dirname(__FILE__) . '/../../');
chdir(APP_PATH);
require_once APP_PATH . 'lecms/xiunophp/xiunophp.php';

// 手动初始化数据库连接
$db_type = 'db_' . $_ENV['_config']['db']['type'];
$db = new $db_type($_ENV['_config']['db']);
$db = $db->db ?? $db;  // 兼容不同版本

// 使用 $db 执行查询
$rows = $db->fetch_all("SELECT * FROM `{$tablepre}my_table`");
```

> [!NOTE]
> Cron 脚本中不能使用 `$this->db`，因为没有 control 实例。
> 也不能使用 `db()` 全局函数，因为 LeCMS 没有该函数。

    // 反向查询优化

        $orderway = -$orderway;
        $newstart = $total - $start - $limit;

            $newstart = 0;

                                     $newstart, $limit);

                                     $start, $limit);
    }
}

### 50.3 常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 安装失败 | install.php 语法错误或 SQL 错误 | 启用 DEBUG 模式查看详细错误 |
| Hook 不生效 | 插件未启用或文件名错误 | 检查 plugin.inc.php 中的 enable 状态 |
| 变量未定义 | Hook 中访问了不存在变量 | 使用 isset() 检查后再使用 |
| 编译错误 | Hook 文件有 PHP 语法错误 | 在单独 PHP 文件中测试 Hook 代码 |
| 插件冲突 | 多个插件定义了同名函数 | 使用唯一函数名前缀 |
| 数据不一致 | 卸载脚本未清理数据库 | 在 uninstall.php 中完善清理逻辑 |
| `Call to undefined function db()` | 调用了不存在的全局 db() 函数 | 改用 `$this->db` 或构造函数注入 db 对象 |
| `Undefined variable: db` | install.php 中使用了未定义的 `$db` 变量 | 统一使用 `$this->db`（$this 指向 plugin_control） |
| `db()->update() 不生效` | update() 签名错误（传了 4 个参数） | LeCMS 的 update() 签名不同，改用直接 SQL UPDATE |
| `date() 写入 INT 列后查询异常` | DATETIME 字符串与 INT UNSIGNED 列类型不匹配 | 使用 `$_ENV['_time']` 写入 INT UNSIGNED 列 |
| `return $ret` 导致解析错误 | install.php 被 include 调用，不能 return | 移除所有 return 语句 |
| `dirname(__FILE__)` 路径错误 | Hook 被编译内联到 runcache/，__FILE__ 指向错误 | 使用 `PLUGIN_PATH` 常量 |
| `IN_ADMIN / IN_APP 未定义` | 使用了非标准的安全头常量 | 统一使用 `defined('ROOT_PATH') || exit` |

### 50.4 插件开发常见陷阱（基于 site_manager 实战经验）

以下陷阱基于实际插件开发中遇到的错误总结，每个陷阱都包含错误现象、根因分析和正确做法。

**陷阱 1：模型类名带 `_model` 后缀**

| 项目 | 错误 | 正确 |
|------|------|------|
| 文件名 | `site_manager_model.class.php` | `site_manager_model.class.php`（不变） |
| 类名 | `class site_manager_model extends model` | `class site_manager extends model` |
| 框架映射 | `core::model('site_manager')` → 找不到 `site_manager_model` 类 | `core::model('site_manager')` → 自动加载 `site_manager_model.class.php` 中的 `site_manager` 类 |

```
错误现象：Fatal error: Cannot declare class site_manager_model, because the name is already in use
根因：框架自动加载（core::model('site_manager')）与控制文件手动 require_once 同时加载了同一个类
```

**陷阱 2：手动 require_once 与框架自动加载重复**

```php
// ❌ 错误：控制文件顶部手动 require 模型
require_once ROOT_PATH . 'plugin/site_manager/model/site_manager_model.class.php';

// ✅ 正确：框架自动加载，无需手动 require
// control::__get('site_manager') 会自动调用 core::model('site_manager')
// 框架会根据约定找到 site_manager_model.class.php 并加载其中的 site_manager 类
$this->site_manager->get_list();  // 直接使用即可
```

**陷阱 3：模型文件缺少安全头**

```php
// ❌ 错误：没有安全头
<?php
class site_manager extends model {
}

// ✅ 正确：第一行必须有安全头
<?php
defined('ROOT_PATH') or exit;

class site_manager extends model {
}
```

**陷阱 4：`{inc:}` 模板包含路径解析机制**

```
框架解析规则：
{inc:header.htm}     → 在插件根目录查找 header.htm
{inc:admin/header.htm} → 解析为 admin/inc-header.htm，只在插件根目录查找（不递归子目录！）

查找顺序（core::get_original_file）：
  1. plugin/{插件名}/{文件名}        ← 插件根目录
  2. plugin/{插件名}/admin/{文件名}  ← admin 子目录
  3. plugin/{插件名}/control/{文件名} ← control 子目录
  4. plugin/{插件名}/model/{文件名}  ← model 子目录
  5. plugin/{插件名}/block/{文件名}  ← block 子目录
  6. view/{主题}/{文件名}            ← 主题目录（最后的 fallback）
```

```php
// ❌ 错误：模板引用 admin/header.htm，但文件不在插件根目录的 admin/ 子目录下
// {inc:admin/header.htm} → 查找 admin/inc-header.htm（在插件根目录下）
// 框架不会递归到 plugin/site_manager/admin/ 查找！

// ✅ 正确方式 1：将 header.htm 放在插件根目录，引用 {inc:header.htm}
// plugin/site_manager/header.htm
// plugin/site_manager/site_index.htm → {inc:header.htm}

// ✅ 正确方式 2：简单插件不需要 header/footer，直接写纯内容
// plugin/le_links/links_index.htm → 直接写 HTML 内容，无 {inc:} 引用
```

**陷阱 5：控制器和模板严禁放在 `admin/` 子目录**

```
框架 get_original_file() 查找顺序：
  1. plugin/{p}/APP_NAME/{文件名}
  2. plugin/{p}/{文件名}                    ← 插件根目录
  3. plugin/{p}/control/{文件名}
  4. plugin/{p}/model/{文件名}
  5. plugin/{p}/block/{文件名}
  没有 admin/ 子目录的查找步骤！

所以控制器和模板放在 plugin/{p}/admin/ 下，框架永远找不到！→ 报 "模板文件不存在" 或 "控制器不存在"

错误做法: plugin/site_manager/admin/site_control.class.php
错误做法: plugin/ai_search_monitor/admin/dashboard.htm
正确做法: plugin/site_manager/site_control.class.php（平铺在根目录）
正确做法: plugin/ai_search_monitor/dashboard.htm（平铺在根目录）

例外：model/ 子目录是安全的（步骤 4 会查找）
```

**陷阱 6：`{inc:}` 自动加 `inc-` 前缀**

```
框架 process_inc() 对不含 / 的文件名自动加 inc- 前缀：

  {inc:header.htm}       → 实际查找 inc-header.htm
  {inc:footer.htm}       → 实际查找 inc-footer.htm
  {inc:admin/header.htm} → 查找 admin/inc-header.htm

系统入口模板:
  view/default/inc-header.htm  ← {inc:header.htm} 的 fallback
  view/default/inc-footer.htm  ← {inc:footer.htm} 的 fallback

错误做法：在插件根目录创建 header.htm（不会被用到，框架找的是 inc-header.htm）
正确做法：直接使用 {inc:header.htm}，系统模板提供 fallback
```

**陷阱 7：模板变量未传递导致空值**

```php
// ❌ 错误：create() 方法没有传递 $themes 变量
public function create() {
    $this->display();  // 模板中 {loop:$themes $t} 输出空
}

// ✅ 正确：先 assign 再 display
public function create() {
    $themes = $this->get_available_themes();
    $this->assign('themes', $themes);
    $this->display();
}
```

**陷阱 8：模板标签语法缺少冒号**

```html
<!-- ❌ 错误：缺少冒号，框架不识别，标签原样输出到浏览器 -->
{loop sites $site}
{if $site['status']==1}启用{/if}
{if empty(sites)}

<!-- ✅ 正确：loop 和 if 必须带冒号 -->
{loop:$sites $site}
{if:$site['status']==1}启用{/if}
{if:empty($sites)}
```

```
标签语法对照表：

| 标签   | 错误写法（不识别）    | 正确写法             |
|--------|----------------------|---------------------|
| loop   | {loop sites $site}   | {loop:$sites $site} |
| if     | {if $status==1}      | {if:$status==1}     |
| if     | {if empty($arr)}     | {if:empty($arr)}    |
| elseif | {elseif $a==1}       | {elseif:$a==1}      |
| 变量   | {$site.name}         | {$site['name']}     |
| 三元   | {$x==1?'是':'否'}    | {@$x==1?'是':'否'}  |
```

**陷阱 9：Smarty 语法不兼容 XiunoPHP**

LeCMS 模板引擎是 XiunoPHP，不支持 Smarty 语法。需要全面转换：

```
Smarty                    → XiunoPHP
{foreach $arr as $v}      → {loop:$arr $v}
{foreach $arr as $k $v}   → {loop:$arr $v $k}
{/foreach}                → {/loop}
{$var.key}                → {$var['key']}
{$var.key|filter}         → {$var['key']}
{$var|escape}             → {$var}
{@last}                   → 不支持，改用 {php} 或循环计数
{$var.key|default:0}      → {php}echo isset($var['key']) ?...{/php}
```

**陷阱 10：`assign()` 只能传变量，不能传函数返回值**

```php
// control::assign() 签名：assign($k, &$v) — 第二个参数是引用传递
// 不能直接传函数返回值

// ❌ 错误：直接传函数调用结果
$this->assign('json', json_encode($data));
$this->assign('themes', $this->get_available_themes());

// ✅ 正确：先赋值给变量，再传递
$json = json_encode($data);
$this->assign('json', $json);
$themes = $this->get_available_themes();
$this->assign('themes', $themes);
```

```
报错信息：Only variables should be passed by reference
原因：assign() 内部使用引用传递 &$v，PHP 不允许引用临时表达式
```

**陷阱 15：db 层没有 `fetch()` 方法，也没有参数绑定**

```
db_pdo_mysql 提供的方法（完整清单）：
  query($sql)                    ← 执行 SQL，无参数绑定
  fetch_first($sql)              ← 取第一条（关联数组）
  fetch_all($sql)                ← 取全部
  exec($sql)                     ← 执行并返回影响行数
  insert($table, $data)          ← 插入
  update($key, $data)            ← 更新

没有 fetch() 方法！没有 find() 方法！没有 escape() 方法！
不支持 :param 或 ? 占位符！
```

```php
// ❌ 错误 1：调用不存在的 fetch() 方法 → Call to undefined method
$row = $this->db->fetch($sql, array(':id' => 1));

// ✅ 正确：改用 fetch_first()
$row = $this->db->fetch_first($sql);

// ❌ 错误 2：fetch_all/fetch_first 第二参数传绑定参数数组（第二参数是连接对象！）
$this->db->fetch_all($sql, array(':site_id' => 1));  // → errorInfo() on array 崩溃

// ✅ 正确：参数内联进 SQL
$site_id = (int)$site_id;
$this->db->fetch_all("SELECT * FROM ... WHERE site_id = {$site_id}");

// ❌ 错误 3：SQL 里写 :param / ? 占位符
$this->db->query("DELETE FROM t WHERE id = :id", array(':id' => $id));

// ✅ 正确：字符串用 addslashes() 转义，整数用 (int) 强转
$id = (int)$id;
$this->db->query("DELETE FROM t WHERE id = {$id}");
```

> [!WARNING]
> **字符串 SQL 内联转义必须用 `addslashes()`**，不能用 `safe_str()`！
> `safe_str()` 是白名单过滤（只保留数字字母中文），会删除 `-`、`.`、`/`、`:` 等字符，
> 破坏语言代码（`zh-cn` → `zhcn`）、URL、邮箱等值。
> 正确：`$x = addslashes($var); $sql = "... WHERE col = '{$x}'";`

```
参数化调用 vs 正确方式对照：

| 错误调用 | 正确方式 |
|---------|---------|
| $this->db->fetch($sql, $p) | $this->db->fetch_first($sql) + 内联参数 |
| $this->db->fetch_all($sql, $p) | $this->db->fetch_all($sql) + 内联参数 |
| $this->db->query($sql, $p) | $this->db->query($sql) + 内联参数 |
| $model->find("sql", $p) | $model->find_fetch($where数组, ...) |
| $model->find_fetch("col = :v", $p) | $model->find_fetch(array('col' => $v)) |
| $this->db->fetch("SELECT COUNT(*)...", $p) | fetch_first + SELECT COUNT(*) AS cnt + $row['cnt'] |
| $this->db->escape($x)（不存在） | addslashes($x) |
```

> [!WARNING]
> **`$this->db->escape()` 不存在**：db_pdo_mysql 没有 escape() 方法。凡是调用它的地方都会报 "Call to undefined method db_pdo_mysql::escape()"。SQL 字符串值一律用 `addslashes($x)` 转义。查询条件的 `$where` 数组（`find_fetch` 用）由框架内部安全处理，无需手动转义。
> 
> **查询结果的行数统计**：`fetch_first("SELECT COUNT(*) AS cnt ...")` 返回关联数组，取值用 `$row['cnt']`；不要用 `$total[0]`（那是 `fetch()` 的返回值模式，框架不存在）。

**陷阱 16：`class_exists()` 触发框架自动加载会抛异常**

```
LeCMS 注册了 core::autoload_handler。调用 class_exists('spider_pool')（不带第二个参数 false）
会触发自动加载，找不到类时抛出 Exception("类 xxx 不存在") 而不是返回 false！

// ❌ 错误：class_exists() 触发 autoload，找不到类直接抛异常崩溃
if (!class_exists('spider_pool')) {
    require_once ...;
}

// ✅ 正确：第二个参数 false 禁用自动加载
if (!class_exists('spider_pool', false) && file_exists(...)) {
    require_once ...;
}
if (class_exists('spider_pool', false)) {
    $pool = spider_pool::instance();
}
```

**陷阱 12：表单提交方式错误（传统跳转 vs AJAX）**

```
LeCMS 后台表单统一使用 AJAX 提交，提交成功后自动关闭标签页：

  错误方式（传统表单提交 + 跳转）：
  <form action="?site-create_post" method="post">
      <button class="layui-btn" lay-submit>创建</button>
      <a href="?site-index" class="layui-btn layui-btn-primary">返回列表</a>
  </form>

  正确方式（AJAX 提交 + 自动关闭标签页）：
  <form id="form" class="layui-form" action="?site-{$_GET['action']}-ajax-1" method="post">
      <button class="layui-btn" lay-submit lay-filter="form">创建</button>
  </form>

  <script>
  layui.use(['form', 'layer', 'miniTab'], function () {
      var layer = layui.layer, form = layui.form, miniTab = layui.miniTab;

      form.on('submit(form)', function () {
          adminAjax.postform('#form', function (data) {
              var json = toJson(data);
              var icon = json.err == 0 ? 1 : 5;
              layer.msg(json.msg, {icon: icon});
              if (json.err == 0) {
                  setTimeout(function(){
                      miniTab.reloadIframe('index.php?site-index');
                      miniTab.deleteCurrentByIframe();
                  }, 1500);
              }
          });
          return false;
      });
  });
  </script>
```

> [!TIP]
> 表单页不需要"返回列表"按钮。AJAX 提交成功后，`miniTab.deleteCurrentByIframe()` 会自动关闭当前标签页，用户回到列表页。

**陷阱 13：控制器方法分裂（GET/POST 分两个方法）**

```
LeCMS 后台控制器统一使用一个方法处理 GET（显示表单）和 POST（处理提交）：

  错误方式（两个方法）：
  public function create() { ... 显示表单 ... }
  public function create_post() { ... 处理提交 ... }

  正确方式（一个方法，内部判断）：
  public function create() {
      if (form_submit()) {
          // POST：处理提交
          $this->message(0, '创建成功');
      }
      // GET：显示表单
      $this->assign('themes', $themes);
      $this->display();
  }
```

```php
// 完整示例（对齐 le_links 模式）：
public function create() {
    if(form_submit()) {
        $site_name = trim(R('site_name', 'P'));
        $domain = trim(R('domain', 'P'));

        if(empty($site_name) || empty($domain)) {

            'site_name' => $site_name,
            'domain' => $domain,
            'theme' => 'default',

        $this->message(0, '站点创建成功');  // 不跳转，AJAX 处理
    }

    $themes = $this->get_available_themes();
    $this->assign('themes', $themes);
    $this->display('site_create.htm');
}
```
