## 6. 启动流程详解

### 6.1 完整请求生命周期总览

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                           完整请求生命周期                                     │
├──────┬───────────────────────────────────────────────────────────────────────┤
│ 阶段  │ 说明                                                               │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ①    │ 用户通过浏览器发起 HTTP 请求                                         │
│      │ GET /article/php-tutorial.html HTTP/1.1                              │
│      │ Host: aimuchen100.com                                              │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ②    │ Nginx 接收请求，进行 URL 重写                                       │
│      │ if (!-e $request_filename) {                                        │
│      │     rewrite ^/(.+) /index.php?rewrite=$1 last;                     │
││      │ }                                                                  │
│      │ 转换结果: /index.php?rewrite=article/php-tutorial.html              │
│      │ 注意: $_GET['rewrite'] = 'article/php-tutorial.html'               │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ③    │ PHP-FPM 执行 /index.php（唯一入口）                                  │
│      │ - 定义 ROOT_PATH, APP_NAME, APP_PATH                                │
│      │ - 检查 config.inc.php 是否存在                                      │
│      │ - require xiunophp.php                                              │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ④    │ xiunophp.php 框架初始化                                              │
│      │ - PHP 版本检查 (5.4.0 < PHP < 8.2.0)                               │
│      │ - 定义 12 个路径常量                                                │
│      │ - include config.inc.php → $_ENV['_config']                         │
│      │ - 可选: include route.inc.php                                       │
│      │ - 设置 DEBUG 模式                                                   │
│      │ - 加载核心文件 (DEBUG 或合并模式)                                    │
│      │ - 定义 IS_AJAX, HTTP 常量                                           │
│      │ - session_start()                                                   │
│      │ - core::init_start() ← 进入核心初始化                               │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ⑤    │ core::init_start() — 7步初始化                                        │
│      │ ├── debug::init_start()      ← 调试系统初始化                         │
│      │ ├── core::open_ob_start()    ← GZIP 输出缓冲启动                     │
│      │ ├── core::init_set()         ← 时区/自动加载/GPC/HTTP头              │
│      │ ├── core::init_misc()        ← 加载 misc.func.php + Hook处理         │
│      │ ├── core::init_lang()        ← 加载前后台语言包                      │
│      │ ├── core::init_get()         ← URL 解析 → $_GET[control/action]     │
│      │ └── core::init_control()     ← 控制器加载+实例化+Action执行         │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ⑥    │ 控制器执行阶段                                                        │
│      │ - get_original_file() 查找原始控制器文件                             │
│      │ - process_all() 编译 (继承解析 + Hook注入 + 写入缓存)               │
│      │ - include 缓存文件                                                   │
│      │ - new $control_control()                                             │
│      │ - $obj->$action() 执行 Action 方法                                   │
│      │ - Action 内部: $this->model() → 加载模型                             │
│      │ - Action 内部: $this->view() → 渲染模板                             │
│      │ - 输出经过 ob_gzip() 压缩的内容                                      │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ⑦    │ 响应返回                                                             │
│      │ - ob_gzip() 回调函数处理输出缓冲区                                    │
│      │ - 可选 GZIP 压缩                                                     │
│      │ - 发送 HTTP 响应                                                     │
│      │ - 浏览器渲染页面                                                     │
├──────┼───────────────────────────────────────────────────────────────────────┤
│ ⑧    │ 清理阶段                                                             │
│      │ - debug::debug_info() 输出调试信息 (仅 DEBUG > 1)                   │
│      │ - $_ENV['_sqls'] 记录所有 SQL 查询                                  │
│      │ - $_ENV['_include'] 记录所有自动加载的类                             │
│      │ - 内存/时间统计                                                      │
└──────┴───────────────────────────────────────────────────────────────────────┘
```

> **关键数据流转**: `HTTP Request → Nginx重写 → index.php → xiunophp.php → core::init_start() → init_control() → Action → View → HTTP Response`

### 6.2 index.php 入口文件逐行解析

文件位置: `d:\phpstudy_pro\WWW\aimuchen100.com\lecms\index.php`（共约21行）

```php
<?php
// ─────────────────────────────────────────────────────────────────
// 第1行: 代码压缩开关（预留功能，当前版本未使用）
// 0 = 关闭压缩, 1 = 开启压缩（对 PHP 源码进行压缩）
// ─────────────────────────────────────────────────────────────────
define('CODE_COMPRESS', 0);

// ─────────────────────────────────────────────────────────────────
// 第2行: 定义网站根目录
// $_SERVER['SCRIPT_FILENAME'] 返回 index.php 的物理绝对路径
// dirname() 获取其父目录
// 示例: /var/www/aimuchen100.com/
// ─────────────────────────────────────────────────────────────────
define('ROOT_PATH', dirname($_SERVER['SCRIPT_FILENAME']).'/');

// ─────────────────────────────────────────────────────────────────
// 第3行: 定义应用名称
// 所有路径常量都以 APP_NAME 为前缀构建
// 修改此常量可以多站点共用框架
// ─────────────────────────────────────────────────────────────────
define('APP_NAME', 'lecms');

// ─────────────────────────────────────────────────────────────────
// 第4行: 定义应用目录
// 结合 ROOT_PATH 和 APP_NAME
// 示例: /var/www/aimuchen100.com/lecms/
// ─────────────────────────────────────────────────────────────────
define('APP_PATH', ROOT_PATH.APP_NAME.'/');

// ─────────────────────────────────────────────────────────────────
// 第5-6行: 配置完整性检查
// 如果 config.inc.php 不存在，说明尚未安装
// 输出一段 JS 重定向到 install 目录
// 注意: 使用 <script> 而非 header()，因为此时 header 尚未可用
// ─────────────────────────────────────────────────────────────────
if(!is_file(APP_PATH.'config/config.inc.php'))
    exit('<script>location="./install/"</script>');

// ─────────────────────────────────────────────────────────────────
// 第7行: 定义框架目录
// XiunoPHP 框架位于 lecms/xiunophp/ 下
// 框架提供核心类库: core, debug, model, view, control 等
// ─────────────────────────────────────────────────────────────────
define('FRAMEWORK_PATH', APP_PATH.'xiunophp/');

// ─────────────────────────────────────────────────────────────────
// 第8行: 加载框架入口文件
// require 而非 include: 文件不存在时产生致命错误
// xiunophp.php 会接管后续所有初始化工作
// ─────────────────────────────────────────────────────────────────
require FRAMEWORK_PATH.'xiunophp.php';
```

### 6.4 core::init_start() 七步初始化详解

```php
// 文件: xiunophp/lib/core.class.php 第4-12行
public static function init_start() {
    debug::init_start();       // 步骤1: 调试系统初始化
    self::open_ob_start();     // 步骤2: 输出缓冲（GZIP）
    self::init_set();          // 步骤3: 基本设置（时区/自动加载/GPC/HTTP头）
    self::init_misc();         // 步骤4: 加载自定义函数库
    self::init_lang();         // 步骤5: 加载语言包
    self::init_get();          // 步骤6: URL 解析
    self::init_control();      // 步骤7: 控制器执行
}
```

**步骤1: `debug::init_start()` — 调试系统初始化**

- 初始化调试日志记录器
- 设置 SQL 查询计数器 `$_ENV['_sqlnum'] = 0`
- 注册页面执行时间统计

**步骤2: `core::open_ob_start()` — 输出缓冲启动**

```php
// core.class.php 第16-17行
public static function open_ob_start() {
    ob_start(array('core', 'ob_gzip'));
}
```
- `ob_start()` 注册 `core::ob_gzip` 作为输出回调
- 所有后续 `echo`/`print` 输出都被缓存到内存缓冲区
- 脚本结束时（或 `ob_end_flush()` 时），回调函数处理所有缓冲内容
- 如果 GZIP 开启，回调函数会对内容进行 GZIP 压缩

**步骤3: `core::init_set()` — 基本设置**

- 设置时区
- 注册 SPL 自动加载器
- GPC 安全过滤
- 初始化全局变量
- 发送 HTTP 缓存头

**步骤4: `core::init_misc()` — 自定义函数加载**

- 查找 `misc.func.php`（支持插件覆盖）
- 编译 Hook 标记
- 写入 `runcache/misc.func.php`
- `include` 加载

**步骤5: `core::init_lang()` — 语言包加载**

- 区分前台/后台
- 加载框架语言包 + LeCMS 语言包
- 支持 Cookie 语言切换
- 合并到 `$_SERVER['lang']` 数组

**步骤6: `core::init_get()` — URL 解析**

- 伪静态模式: 调用 `parseurl_control()` 委托给自定义路由控制器
- 普通模式: 解析 `$_GET['u']` 或 `PATH_INFO` 或 `QUERY_STRING`
- 设置 `$_GET['control']` 和 `$_GET['action']`
- 安全过滤（只允许 `\w+` 字符）

**步骤7: `core::init_control()` — 控制器执行**

- 查找控制器文件（支持插件覆盖）
- 编译控制器（继承解析 + Hook 注入）
- 写入缓存
- `include` + 实例化 + 执行 Action

### 6.5 生产环境代码合并机制详解

当 `DEBUG = 0` 时，框架不会分别加载 13 个文件，而是将它们合并为一个 `_lecms.php` 文件。这是 LeCMS 重要的性能优化手段。

**合并流程:**

```
13个源文件                     runcache/_lecms.php
┌─────────────────┐           ┌─────────────────────────────────────┐
│ base.func.php   │           │ <?php defined('ROOT_PATH')||exit;   │
│   (去掉注释)     │ ────────→ │ [base.func.php 纯代码]               │
├─────────────────┤           │ [core.class.php 纯代码]              │
│ core.class.php  │ ────────→ │ [debug.class.php 纯代码]             │
│   (去掉注释)     │           │ [log.class.php 纯代码]               │
├─────────────────┤           │ [model.class.php 纯代码]             │
│ debug.class.php │ ────────→ │ [view.class.php 纯代码]              │
│   (去掉注释)     │           │ [control.class.php 纯代码]           │
│       ...       │           │ [db.interface.php 纯代码]             │
│       ...       │           │ [db_mysql.class.php 纯代码]           │
│       ...       │           │ [cache.interface.php 纯代码]          │
│       ...       │           │ [cache_memcache.class.php 纯代码]    │
│       ...       │           │ [Network__interface.php 纯代码]       │
└─────────────────┘           └─────────────────────────────────────┘
```

**核心原理:**
- `php_strip_whitespace($file)` — PHP 内置函数，移除注释和空白
- `trim(..., "<?ph>\r\n")` — 去除 `<?php` 标签头和尾部换行
- `str_replace('defined(\'ROOT_PATH\') || exit;', '', $s)` — 去除每个源文件的安全检查
- 最终文件头部只保留一个 `defined('ROOT_PATH') || exit;`

**优势:**
- 减少 13 次 `fopen/fread` 操作 → 1 次
- 减少 13 次 PHP 语法解析 → 1 次
- 减少 opcode 缓存的内存占用

**注意事项:**
- 修改框架源码后需要手动删除 `runcache/_lecms.php` 以触发重新合并
- DEBUG 模式下不会合并，方便开发调试
- 合并文件路径: `ROOT_PATH/runcache/_lecms.php`

```php
public static function init_get() {
    // ─────────────────────────────────────────────────────────────────
    // 第124行: 检查是否启用伪静态（自定义 URL 路由）
    // $_ENV['_config']['lecms_parseurl'] 在 config.inc.php 中配置
    // 如果启用，委托给 parseurl_control() 处理
    // parseurl_control() 会加载自定义路由控制器来解析 URL
    // ─────────────────────────────────────────────────────────────────
    if(!empty($_ENV['_config'][APP_NAME.'_parseurl'])) {
        self::parseurl_control();
    } else {
        // ─────────────────────────────────────────────────────────────────
        // 第127-135行: 获取 URL 字符串（三种来源，按优先级）
        // ─────────────────────────────────────────────────────────────────
        // 来源1: $_GET['u'] 参数（Nginx rewrite 后: index.php?u=xxx）
        if(isset($_GET['u'])) {
            $u = $_GET['u'];
            unset($_GET['u']);  // 移除 u 参数，避免干扰后续解析
        }
        // 来源2: PATH_INFO（Apache mod_rewrite 模式）
        elseif(!empty($_SERVER['PATH_INFO'])) {
            $u = $_SERVER['PATH_INFO'];
        }
        // 来源3: QUERY_STRING（最原始的模式，如 index.php?c=article&a=index）
        else {
            $_GET = array();  // 清空 $_GET，后续手动解析
            $u = $_SERVER["QUERY_STRING"];
        }

        // ─────────────────────────────────────────────────────────────────
        // 第138-142行: 清除 URL 后缀
        // url_suffix 配置为 '.html' 时，将 article/index.html → article/index
        // substr() 截取最后 N 个字符进行比对
        // ─────────────────────────────────────────────────────────────────
        $url_suffix = C('url_suffix');
        if($url_suffix) {
            $suf_len = strlen($url_suffix);
            if(substr($u, -($suf_len)) == $url_suffix)
                $u = substr($u, 0, -($suf_len));
        }

        // ─────────────────────────────────────────────────────────────────
        // 第144-147行: 处理带 & 和 = 的参数
        // 将 &page=1&limit=15 转换为 -page-1-limit-15
        // 使后续 explode('-', $u) 能正确解析
        // ─────────────────────────────────────────────────────────────────
        if(strpos($u, '&') !== false && strpos($u, '=') !== false){
            $u = str_replace(array('&','='),'-',$u);
        }

        // ─────────────────────────────────────────────────────────────────
        // 第149-164行: URL 分段解析
        // 使用 - 作为分隔符，将 URL 拆分为数组
        // 数组结构: [control, action, key1, val1, key2, val2, ...]
        // ─────────────────────────────────────────────────────────────────
        $uarr = explode('-', $u);

        // 第1段: control（控制器名）
        if(isset($uarr[0])) {
            $_GET['control'] = $uarr[0];
            array_shift($uarr);  // 移除已使用的元素
        }
        // 第2段: action（方法名）
        if(isset($uarr[0])) {
            $_GET['action'] = $uarr[0];
            array_shift($uarr);
        }
        // 剩余段: 成对解析为 key-value 参数
        $num = count($uarr);
        for($i=0; $i<$num; $i+=2){
            isset($uarr[$i+1]) && $_GET[$uarr[$i]] = $uarr[$i+1];
        }
    }

    // ─────────────────────────────────────────────────────────────────
    // 第167-168行: 安全过滤
    // preg_match('/^\w+$/', ...): 只允许字母、数字、下划线
    // strtolower(): 统一转为小写，确保大小写不敏感
    // 默认值: 'index'（控制器的默认方法名）
    // 恶意 URL 如: article/../../etc/passwd → 被过滤为 'index'
    // ─────────────────────────────────────────────────────────────────
    $_GET['control'] = isset($_GET['control']) && preg_match('/^\w+$/', $_GET['control'])
        ? strtolower($_GET['control']) : 'index';
    $_GET['action'] = isset($_GET['action']) && preg_match('/^\w+$/', $_GET['action'])
        ? strtolower($_GET['action']) : 'index';

    // ─────────────────────────────────────────────────────────────────
    // 第170-174行: 限制访问特殊控制器
    // parseurl: 防止递归调用
    // error404: 防止绕过 404 处理
    // base: 框架内部基础控制器，不应直接访问
    // 以上控制器统一重定向到 error404
    // ─────────────────────────────────────────────────────────────────
    if(in_array($_GET['control'], array('parseurl', 'error404', 'base'))) {
        $_GET['control'] = 'error404';
        $_GET['action'] = 'index';
    }
}
```

```

  ↓ 去除后缀 .html
  ↓ 分段: article, index, 1, 2
  ↓ 结果: control=article, action=index, $_GET['id']=1, $_GET['page']=2
```

```php
public static function parseurl_control() {
    // 路由控制器的文件名
    $controlname = 'parseurl_control.class.php';
    $objfile = RUNTIME_CONTROL.$controlname;

    // 编译并缓存路由控制器
    if(DEBUG || !is_file($objfile)) {
        $controlfile = self::get_original_file($controlname, CONTROL_PATH);
        if(!$controlfile) {
            // 路由控制器不存在，抛出异常
            $_GET['control'] = 'parseurl';
            throw new Exception("访问的 URL 不正确，$controlname 文件不存在");
        }
        self::process_all($controlfile, $objfile, "写入 control 编译文件 $controlname 失败");
    }

    include $objfile;
    $obj = new parseurl_control();
    $obj->index();  // 执行路由解析
}
```

**工作原理:**
- `parseurl_control` 是 LeCMS 的内置控制器，位于 `lecms/control/parseurl_control.class.php`
- 它的 `index()` 方法根据 `$_ENV['_route']` 中的路由规则来解析 URL
- 路由规则格式: `'旧URL' => '新URL'`，例如:
  ```php
  $_ENV['_route']['article-$id'] = 'article/index-$id';
  ```
- 路由控制器将 `/article/123` 解析为 `control=article, action=index, id=123`

### 7.9 process_all() 核心编译方法

文件位置: `xiunophp/lib/core.class.php` 第373-380行

```php
/**
 * 将原始程序代码解析并写入缓存文件中
 * @param string $readfile  原始文件路径
 * @param string $writefile 缓存文件路径
 * @param string $errorstr  写入失败时的错误提示
 */
public static function process_all($readfile, $writefile, $errorstr) {
    // 步骤1: 读取原始文件内容
    $s = file_get_contents($readfile);

    // 步骤2: 递归解析类继承关系
    // 如果类继承了其他控制器/模型，自动插入 include 语句
    $s = self::process_extends($s);

    // 步骤3: 编译时注入 Hook
    // 正则匹配: 以 Tab 开头的注释 // hook xxx.yyy
    // 替换为所有启用插件的 hook 代码
    $s = preg_replace_callback('#\t*\/\/\s*hook\s+([\w\.]+)[\r\n]#', array('core', 'process_hook'), $s);

    // 步骤4: 写入编译缓存
    if(!FW($writefile, $s)) {
        throw new Exception($errorstr);
    }
}
```

### 7.10 process_extends() 递归继承解析

文件位置: `xiunophp/lib/core.class.php` 第387-412行

```php
public static function process_extends($s) {
    // 正则匹配类声明中的 extends 关键字
    // 匹配: class Xxx_control extends Base_control {
    //       $m[1] = 'Base_control'
    if(preg_match('#class\s+\w+\s+extends\s+(\w+)\s*\{#', $s, $m)) {
        // 如果不是继承自 framework 的 control 基类
        if($m[1] != 'control') {
            // 构建父类文件名
            $controlname = $m[1].'.class.php';
            $realfile = CONTROL_PATH.$controlname;

            // ─────────────────────────────────────────────────────────
            // 核心: 父类文件可能不在核心目录，而是在插件目录
            // 使用 get_original_file() 按插件优先级查找
            // ─────────────────────────────────────────────────────────
            if(!is_file($realfile)) {
                $controlfile = core::get_original_file($controlname, CONTROL_PATH);
                if($controlfile) {
                    $realfile = $controlfile;
                }
                unset($controlfile);
            }

            if(is_file($realfile)) {
                // 递归编译父类（父类也可能有自己的父类）
                $objfile = RUNTIME_CONTROL.$controlname;
                self::process_all($realfile, $objfile, "写入继承的类的编译文件 $controlname 失败");
                // 在子类类声明前插入父类 include
                // str_replace_once() 只替换第一次匹配
                $s = str_replace_once($m[0], 'include RUNTIME_CONTROL.\''.$controlname."'; ".$m[0], $s);
            } else {
                // 父类文件不存在，抛出异常
                throw new Exception("您继承的类文件 $controlname 不存在");
            }
        }
    }
    return $s;
}
```

**继承解析示例:**

```
admin/article_control.class.php:

      function index() { ... }
  }

base_control.class.php:
  class base_control extends control {
      function before() { ... }  // 前置方法
  }

编译后:

  class article_control extends base_control extends control {
      function index() { ... }
  }
```

**递归处理:**
- 如果 `base_control` 也继承了 `control`，会递归处理
- 最终形成的 include 链确保了所有父类在子类之前被加载

```php
public static function model($model) {
    // 构建模型文件名
    $modelname = $model.'_model.class.php';

    // 单例缓存: 同一个模型只加载一次
    if(isset($_ENV['_models'][$modelname])) {
        return $_ENV['_models'][$modelname];
    }

    // 编译缓存路径
    $objfile = RUNTIME_MODEL.$modelname;

    // 缓存不存在或 DEBUG 模式时重新编译
    if(DEBUG || !is_file($objfile)) {
        // 查找原始模型文件
        $modelfile = core::get_original_file($modelname, MODEL_PATH);

        if(!$modelfile) {
            // 兼容: 支持从当前应用目录加载模型
            // CURRENT_APP_NAME 允许在不同应用间共享模型
            if( defined('CURRENT_APP_NAME') ){
                $modelfile = core::get_original_file($modelname, ROOT_PATH.CURRENT_APP_NAME.'/model/');
                if(!$modelfile) {
                    throw new Exception(CURRENT_APP_NAME."模型 $modelname 文件不存在");
                }
            }else{
                throw new Exception("模型 $modelname 文件不存在");
            }
        }

        // 编译 Hook 并写入缓存
        $s = file_get_contents($modelfile);
        $s = preg_replace_callback('#\t*\/\/\s*hook\s+([\w\.]+)[\r\n]#', array('core', 'process_hook'), $s);
        if(!FW($objfile, $s)) {
            throw new Exception("写入 model 编译文件 $modelname 失败");
        }
    }

    // 加载编译后的模型
    include $objfile;
    $mod = new $model();
    // 缓存实例，避免重复加载
    $_ENV['_models'][$modelname] = $mod;

    return $mod;
}
```

### 7.12 get_plugins() 插件状态扫描

```php
public static function get_plugins($force = 0) {
    // 静态缓存: 避免每次调用都扫描目录
    static $plugins = array();
    if(!empty($plugins) && !$force) return $plugins;

    // 插件目录不存在，返回空数组
    if(!is_dir(PLUGIN_PATH)) return array();

    // 获取插件目录列表
    $plugin_dirs = get_dirs(PLUGIN_PATH);

    // 读取插件安装配置文件
    // config/plugin.inc.php 返回: ['plugin_name' => ['enable' => 1], ...]
    $plugin_arr = is_file(CONFIG_PATH.'plugin.inc.php') ? (array)include(CONFIG_PATH.'plugin.inc.php') : array();

    foreach($plugin_dirs as $dir) {
        // 读取插件配置文件
        $cfg = is_file(PLUGIN_PATH.$dir.'/conf.php') ? (array)include(PLUGIN_PATH.$dir.'/conf.php') : array();

        // 支持多语言插件配置
        // 如果有后台语言配置，加载对应语言版本
        if( isset($_ENV['_config']['admin_lang']) && is_file(PLUGIN_PATH.$dir.'/conf_'.$_ENV['_config']['admin_lang'].'.php')){
            $cfg = (array)include(PLUGIN_PATH.$dir.'/conf_'.$_ENV['_config']['admin_lang'].'.php');
        }

        // 默认排序权重
        $cfg['rank'] = isset($cfg['rank']) ? (int)$cfg['rank'] : 100;

        // 分类: 未安装 / 已禁用 / 已启用
        if(empty($plugin_arr[$dir])) {
            $plugins['not_install'][$dir] = $cfg;
        } elseif(empty($plugin_arr[$dir]['enable'])) {
            $plugins['disable'][$dir] = $cfg;
        } else {
            $plugins['enable'][$dir] = $cfg;
        }
    }

    // 插件排序规则: rank 升序（数字越小越优先）
    _array_multisort($plugins['enable'], 'rank');
    _array_multisort($plugins['disable'], 'rank');
    _array_multisort($plugins['not_install'], 'rank');

    return $plugins;
}
```

### 7.13 process_hook() Hook 编译时注入

```php
public static function process_hook($matches) {
    $str = "\n";  // 默认返回一个换行（替换掉原 hook 注释行）

    // 插件被禁用时，不注入任何 Hook
    if(!is_dir(PLUGIN_PATH) || !empty($_ENV['_config']['plugin_disable'])) return $str;

    $plugins = core::get_plugins();
    if(empty($plugins['enable'])) return $str;

    // 获取所有已启用插件的名称
    $plugin_enable = array_keys($plugins['enable']);

    foreach($plugin_enable as $p) {
        // 第1个查找位置: plugin/{插件名}/{hook名称}
        // 这是标准的 Hook 文件位置
        $file = PLUGIN_PATH.$p.'/'.$matches[1];
        if( is_file($file) ){
            $s = file_get_contents($file);
            $str .= self::clear_code($s);
        }

        // 第2个查找位置: plugin/{插件名}/hook/{hook名称}
        // 将 Hook 分类存放在 hook 子目录下
        $file = PLUGIN_PATH.$p.'/hook/'.$matches[1];
        if( is_file($file) ){
            $s = file_get_contents($file);
            $str .= self::clear_code($s);
        }
    }

    return $str;
}
```

```php
public static function clear_code($s) {
    $s = trim($s);

    // 移除 PHP 安全退出标记（某些加密文件使用）
    if(substr($s, 0, 11) == '<?php exit;') $s = substr($s, 11);

    // 移除 PHP 开始标签
    if(substr($s, 0, 5) == '<?php') $s = substr($s, 5);

    if(substr($s, 0, 29) == 'defined(\'ROOT_PATH\') || exit;') $s = substr($s, 29);

    // 移除 PHP 结束标签（可选，避免尾部空白输出）
    if(substr($s, -2, 2) == '?>') $s = substr($s, 0, -2);

    return $s;
}
```

### 7.15 辅助方法: ob_gzip() 输出压缩

文件位置: `xiunophp/lib/core.class.php` 第24-42行

```php
public static function ob_gzip($s) {
    // 获取 GZIP 配置
    $gzip = $_ENV['_config']['gzip'];
    // 是否为第一次调用（用于判断是否发送 Content-Encoding 头）
    $isfirst = empty($_ENV['_isgzip']);

    if($gzip) {
        // 情况1: PHP 本身已开启 zlib.output_compression
        if(function_exists('ini_get') && ini_get('zlib.output_compression')) {
            $isfirst && header("Content-Encoding: gzip");
        }
        // 情况2: 手动 GZIP 压缩
        elseif(function_exists('gzencode') && isset($_SERVER["HTTP_ACCEPT_ENCODING"]) && strpos($_SERVER["HTTP_ACCEPT_ENCODING"], "gzip") !== FALSE) {
            $s = gzencode($s, 5);  // 压缩级别 5（平衡速度和压缩率）
            if($isfirst) {
                header("Content-Encoding: gzip");
            }
        }
    } elseif($isfirst) {
        // GZIP 关闭时，明确告知客户端不压缩
        header("Content-Encoding: none");
    }

    // 标记已执行过 GZIP（避免重复发送头）
    $isfirst && $_ENV['_isgzip'] = 1;

    return $s;
}
```

**GZIP 压缩流程:**
1. `ob_start()` 注册 `ob_gzip` 回调
2. 所有输出（echo/print）被暂存到缓冲区
3. 脚本结束时（或 `ob_end_flush()`），回调函数处理全部内容
4. 如果 GZIP 开启，对内容进行 `gzencode()` 压缩
5. 发送 `Content-Encoding: gzip` 响应头
6. 客户端（浏览器）自动解压显示

## 8. 自动加载机制

### 8.1 SPL 自动注册机制深入解析

LeCMS 使用 PHP 的 **SPL（Standard PHP Library）自动加载** 机制，通过 `spl_autoload_register()` 注册自定义加载函数，实现类的自动加载。

#### 8.1.1 SPL 自动加载工作原理

```
PHP 执行流程:
  遇到 new db_pdo_mysql()       ← 类未定义
       ↓
  PHP 检查: 类是否已加载？
       ↓ NO
  PHP 遍历所有已注册的 __autoload / spl_autoload_register 回调
       ↓
  调用 core::autoload_handler('db_pdo_mysql')
       ↓
  加载 db_pdo_mysql.class.php
       ↓
  class_exists('db_pdo_mysql', false) 验证
       ↓
  返回 true → 类定义已加载 → new 成功
```

#### 8.1.2 spl_autoload_register() 详解

```php
spl_autoload_register(array('core', 'autoload_handler'));
```

**参数说明:**

| 参数 | 值 | 说明 |
|------|-----|------|
| callable | `array('core', 'autoload_handler')` | 静态方法回调 |
|  throw | 默认 true | 加载失败时抛出异常 |
|  prepend | 默认 false | 是否插入到队列头部 |

**关键特性:**

1. **支持多个加载器**: 可以注册多个回调函数，按注册顺序执行
   ```php
   spl_autoload_register('loader1');
   spl_autoload_register('loader2');  // loader1 失败后尝试 loader2
   ```

2. **不区分大小写**: PHP 类名查找默认不区分大小写（取决于 OS）

3. **命名空间支持**: LeCMS 通过 `str_replace('\\', DIRECTORY_SEPARATOR, $classname)` 支持

4. **性能优化**: `class_exists($classname, false)` 第二个参数为 `false`，表示不触发自动加载（避免无限递归）

#### 8.1.3 注册时机

```php
// xiunophp.php 第138行
date_default_timezone_set($_ENV['_config']['zone']);
```

- 在 `init_set()` 中注册，此时核心类（core, debug, model, view, control）已经通过 `include` 加载

### 8.2 autoload_handler() 完整源码与类名前缀路由表

文件位置: `xiunophp/lib/core.class.php` 第103-120行

```php
public static function autoload_handler($classname) {
    // 支持命名空间: 将 \ 转换为目录分隔符
    // 例如: Network\Http → ext/network/Network/Http.class.php
    $classname = str_replace('\\', DIRECTORY_SEPARATOR, $classname);

    // 第1级路由: 数据库驱动
    // 前缀: db_
    // 路径: xiunophp/db/
    // 后缀: .class.php
    // 示例: db_pdo_mysql → xiunophp/db/db_pdo_mysql.class.php
    if(substr($classname, 0, 3) == 'db_') {
        include FRAMEWORK_PATH.'db/'.$classname.'.class.php';
    }
    // 第2级路由: 缓存驱动
    // 前缀: cache_
    // 路径: xiunophp/cache/
    // 后缀: .class.php
    // 示例: cache_redis → xiunophp/cache/cache_redis.class.php
    elseif(substr($classname, 0, 6) == 'cache_') {
        include FRAMEWORK_PATH.'cache/'.$classname.'.class.php';
    }
    // 第3级路由: 扩展类库
    // 无前缀
    // 路径: xiunophp/ext/
    // 后缀: .class.php
    // 示例: form → xiunophp/ext/form.class.php
    elseif(is_file(FRAMEWORK_PATH.'ext/'.$classname.'.class.php')) {
        include FRAMEWORK_PATH.'ext/'.$classname.'.class.php';
    }
    // 第4级路由: 网络类库
    // 无前缀
    // 路径: xiunophp/ext/network/
    // 后缀: .php（注意不是 .class.php）
    // 示例: Network__interface → xiunophp/ext/network/Network__interface.php
    elseif(is_file(FRAMEWORK_PATH.'ext/network/'.$classname.'.php')) {
        include FRAMEWORK_PATH.'ext/network/'.$classname.'.php';
    } else {
        // 所有路由都失败
        // 如果定义了 VENDOR 常量（兼容第三方库），静默失败
        if(!defined('VENDOR')){
            throw new Exception("类 $classname 不存在");
        }
    }

    // DEBUG 模式: 记录自动加载的类
    DEBUG && $_ENV['_include'][] = $classname.' 类';

    // 验证类是否加载成功
    return class_exists($classname, false);
}
```

#### 8.2.1 完整类名前缀路由表

| 优先级 | 类名前缀 | 查找路径 | 文件名后缀 | 触发条件 | 示例 |
|--------|---------|---------|-----------|---------|------|
| 1 | `db_*` | `xiunophp/db/` | `.class.php` | 前缀匹配 | `db_pdo_mysql` → `db_pdo_mysql.class.php` |
| 2 | `cache_*` | `xiunophp/cache/` | `.class.php` | 前缀匹配 | `cache_memcache` → `cache_memcache.class.php` |
| 3 | 无前缀 | `xiunophp/ext/` | `.class.php` | 文件存在检查 | `form` → `form.class.php` |
| 4 | 无前缀 | `xiunophp/ext/network/` | `.php` | 文件存在检查 | `Network__interface` → `Network__interface.php` |
| 5 | 控制器 | `APP_PATH/control/` | 由 init_control 处理 | 不通过此路由 | `article_control` |
| 6 | 模型 | `APP_PATH/model/` | 由 model() 处理 | 不通过此路由 | `article_model` |

> **注意**: 控制器和模型类不由 `autoload_handler()` 自动加载，而是通过 `init_control()` 和 `model()` 方法专门处理（因为它们需要编译和 Hook 注入）。

#### 8.2.2 路由匹配流程示例

```
请求: new db_pdo_mysql()
  1. 检查前缀 'db_' (前3位) → 匹配！
  2. 加载: xiunophp/db/db_pdo_mysql.class.php

请求: new form()
  1. 检查前缀 'db_' → 不匹配
  2. 检查前缀 'cache_' → 不匹配
  3. 检查文件 xiunophp/ext/form.class.php → 存在！加载
  4. 返回 true

请求: new Network__interface()
  1. 检查前缀 'db_' → 不匹配
  2. 检查前缀 'cache_' → 不匹配
  3. 检查文件 xiunophp/ext/Network__interface.class.php → 不存在
  4. 检查文件 xiunophp/ext/network/Network__interface.php → 存在！加载

请求: new custom_class()
  1-4. 全部不匹配
  5. VENDOR 未定义 → throw new Exception("类 custom_class 不存在")
```

#### 8.2.3 SPL 自动加载最佳实践

1. **注册顺序很重要**: 先注册的加载器先执行
2. **返回 boolean**: 返回 `true` 表示加载成功，`false` 继续下一个加载器
3. **避免递归**: `class_exists($class, false)` 第二个参数为 `false`，防止触发自动加载
4. **异常处理**: 在加载器内部 catch 异常，避免影响其他加载器
5. **注销**: `spl_autoload_unregister(array('core', 'autoload_handler'))` 可注销

## 9. 插件文件查找优先级

### 9.1 核心设计原则

> **插件优先原则**: 插件的文件可以完全覆盖核心文件，且优先级高于主题。

这是 LeCMS 插件系统的核心设计理念。通过 `get_original_file()` 方法，框架在查找任何文件（控制器、模型、视图、函数库、语言包）时，都会先搜索插件目录，再搜索核心目录。

### 9.2 get_original_file() 完整源码逐行解析

文件位置: `xiunophp/lib/core.class.php` 第462-497行

```php
/**
 * 获取原始文件路径（插件优先）
 * 支持 block / control / model / view（统一设计思路）
 * @param string $filename 文件名（如 article_control.class.php）
 * @param string $path     核心文件目录（如 CONTROL_PATH）
 * @return string          找到返回完整路径，未找到返回 FALSE
 */
public static function get_original_file($filename, $path) {
    // ─────────────────────────────────────────────────────────────────
    // 前置检查: 插件功能未被禁用
    // $_ENV['_config']['plugin_disable'] 为 true 时跳过插件查找
    // 可以用于性能优化或安全限制
    // ─────────────────────────────────────────────────────────────────
    if(empty($_ENV['_config']['plugin_disable'])) {
        // 获取所有插件（已启用/已禁用/未安装）
        $plugins = self::get_plugins();

        // 仅处理已启用的插件
        if(isset($plugins['enable']) && is_array($plugins['enable'])) {
            // 提取插件名称数组
            $plugin_enable = array_keys($plugins['enable']);

            // 遍历所有已启用插件（按 rank 排序，rank 小的先遍历）
            foreach($plugin_enable as $p) {

                // ─────────────────────────────────────────────────────────
                // 优先级1: plugin/{插件名}/lecms/{文件名}
                // 用途: 插件针对 LeCMS 应用的特定文件覆盖
                // 示例: plugin/myplugin/lecms/article_control.class.php
                // 适用: 当插件需要完全替换 LeCMS 的某个控制器/模型时
                // ─────────────────────────────────────────────────────────
                if(is_file(PLUGIN_PATH.$p.'/'.APP_NAME.'/'.$filename)) {
                    return PLUGIN_PATH.$p.'/'.APP_NAME.'/'.$filename;
                }

                // ─────────────────────────────────────────────────────────
                // 优先级2: plugin/{插件名}/{文件名}
                // 用途: 插件根目录的文件
                // 示例: plugin/myplugin/article_control.class.php
                // 适用: 通用插件文件，不限定应用
                // ─────────────────────────────────────────────────────────
                if(is_file(PLUGIN_PATH.$p.'/'.$filename)) {
                    return PLUGIN_PATH.$p.'/'.$filename;
                }

                // ─────────────────────────────────────────────────────────
                // 优先级3: plugin/{插件名}/control/{文件名}
                // 用途: 插件目录下的控制子目录
                // 示例: plugin/myplugin/control/article_control.class.php
                // 适用: 插件内部按类型组织的文件
                // ─────────────────────────────────────────────────────────
                if(is_file(PLUGIN_PATH.$p.'/control/'.$filename)) {
                    return PLUGIN_PATH.$p.'/control/'.$filename;
                }

                // ─────────────────────────────────────────────────────────
                // 优先级4: plugin/{插件名}/model/{文件名}
                // 用途: 插件目录下的模型子目录
                // 示例: plugin/myplugin/model/article_model.class.php
                // 适用: 插件替换核心模型
                // ─────────────────────────────────────────────────────────
                if(is_file(PLUGIN_PATH.$p.'/model/'.$filename)) {
                    return PLUGIN_PATH.$p.'/model/'.$filename;
                }

                // ─────────────────────────────────────────────────────────
                // 优先级5: plugin/{插件名}/block/{文件名}
                // 用途: 插件目录下的 block 子目录
                // 示例: plugin/myplugin/block/sidebar_block.class.php
                // 适用: 插件替换 Block 组件
                // ─────────────────────────────────────────────────────────
                if(is_file(PLUGIN_PATH.$p.'/block/'.$filename)) {
                    return PLUGIN_PATH.$p.'/block/'.$filename;
                }
            }
        }
    }

    // ─────────────────────────────────────────────────────────────────
    // 第6步（最终回退）: 核心目录
    // 如果所有插件目录都没有找到，返回核心文件路径
    // 路径由调用方传入（如 CONTROL_PATH, MODEL_PATH, VIEW_PATH）
    // ─────────────────────────────────────────────────────────────────
    if(is_file($path.$filename)) {
        return $path.$filename;
    }

    // 文件不存在
    return FALSE;
}
```

### 9.4 5级优先级对照表

| 优先级 | 查找路径模板 | 适用场景 | 示例 |
|--------|------------|---------|------|
| 1 | `plugin/{插件名}/lecms/{文件名}` | 应用级别覆盖 | `plugin/seo/lecms/article_control.class.php` |
| 2 | `plugin/{插件名}/{文件名}` | 插件根目录 | `plugin/seo/article_control.class.php` |
| 3 | `plugin/{插件名}/control/{文件名}` | 控制器分类 | `plugin/seo/control/article_control.class.php` |
| 4 | `plugin/{插件名}/model/{文件名}` | 模型分类 | `plugin/seo/model/article_model.class.php` |
| 5 | `plugin/{插件名}/block/{文件名}` | Block 分类 | `plugin/seo/block/sidebar_block.class.php` |
| 6 | `{核心路径}/{文件名}` | 核心文件（回退） | `lecms/control/article_control.class.php` |

**关键规则:**
- 插件内部按 1→2→3→4→5 顺序查找
- 多个插件时按 rank 升序排列，rank 小的插件优先
- 找到就立即返回（first-match 策略）
- 所有插件都找不到时，才回退到核心路径

### 9.5 实际应用示例

**场景: 插件覆盖 article 控制器**

假设有两个插件: `seo` (rank=10) 和 `ads` (rank=20)

文件结构:
```
plugin/seo/
├── lecms/
│   └── article_control.class.php      ← 优先级1
├── article_control.class.php          ← 优先级2
├── control/
│   └── article_control.class.php      ← 优先级3
└── conf.php

plugin/ads/
├── control/
│   └── article_control.class.php      ← 优先级3
└── conf.php

lecms/control/
└── article_control.class.php          ← 核心文件
```

查找结果:
1. 先检查 `seo` 插件的5个位置
2. 发现 `seo/lecms/article_control.class.php` 存在
3. 立即返回，不继续检查 `seo` 的其他位置，也不检查 `ads` 插件
4. 编译后的控制器来自 `seo/lecms/article_control.class.php`

**实际效果:**
- `seo` 插件完全接管了 `article` 控制器的逻辑
- 核心的 `article_control.class.php` 完全不执行
- 修改核心文件不会生效（插件优先级更高）

| **键名系统** | 统一的 Key-Value 存储模型 | `pri2key()` / `arr2key()` |
| **模型懒加载** | 通过 `core::model()` 自动加载其他模型 | `__get('other_model')` |

## 11. 调试与日志系统详细说明

> **源码位置**: `lecms/xiunophp/lib/debug.class.php`、`lecms/xiunophp/lib/log.class.php`

### 11.1 调试系统（debug.class.php）

调试系统由 `debug` 类实现，提供错误处理、异常处理和调试信息输出三大功能。

#### 11.1.1 初始化流程

```php
class debug {
    public static function init_start() {
        if(DEBUG) {
            error_reporting(E_ALL | E_STRICT);
            register_shutdown_function(array('debug', 'shutdown_handler'));
        } else {
            error_reporting(0);
        }
        function_exists('ini_set') && ini_set('display_errors', DEBUG ? 'On' : 'Off');
        set_error_handler(array('debug', 'error_handler'));
        set_exception_handler(array('debug', 'exception_handler'));
    }
}
```

#### 11.1.2 错误类型映射（14 种）

| 错误类型 | 值 | 说明 | 处理方式 |
|---------|-----|------|---------|
| `E_ERROR` | 1 | 运行时致命错误 | 记录日志 + 友好提示 |
| `E_WARNING` | 2 | 运行时非致命警告 | 记录日志 + 友好提示 |
| `E_PARSE` | 4 | 语法错误 | 记录日志 + 友好提示 |
| `E_NOTICE` | 8 | 运行时通知 | 仅记录日志 |

| `E_CORE_WARNING` | 32 | PHP 启动时初始化警告 | 记录日志 + 友好提示 |
| `E_COMPILE_ERROR` | 64 | 编译时致命错误 | 记录日志 + 友好提示 |

#### 11.1.3 致命错误处理（shutdown_handler）

```php
public static function shutdown_handler() {
    if(empty($_ENV['_exception'])) {
        if($e = error_get_last()) {
            $message = $e['message'];
            $file = $e['file'];
            $line = $e['line'];
            if(R('ajax', 'R')) {
                echo json_encode(array('error' => "[致命错误] : $message File: $file [$line]"));
            }else{
                self::sys_error('[致命错误] : '.$message, $file, $line);
            }
        }
    }
}
```

**触发条件**: 内存耗尽、调用未定义函数、类不存在等致命错误。

### 11.2 日志系统（log.class.php）

> **源码位置**: `lecms/xiunophp/lib/log.class.php`

#### 11.2.1 日志写入方法

| 方法 | 功能 | 文件输出 |
|------|------|---------|
| `log::write($s, $file)` | 通用日志写入，根据配置开关决定是否写入 | `log/{file}.php` |
| `log::trace($s)` | 跟踪调试（仅 DEBUG 模式），记录执行路径与耗时 | `$_ENV['_trace']` |
| `log::trace_save($file)` | 保存跟踪记录到文件 | `log/{file}.php` |
| `log::le_log($s, $file)` | LeCMS 业务日志，按月归档 | `log/YYYYMM/{file}.php` |

**log::write() 日志开关对应关系**:

| 日志类型 | 文件名 | 配置开关 | 说明 |
|---------|--------|---------|------|
| 错误日志 | `php_error.php` | `php_error` | 记录所有错误 |
| 404 日志 | `php_error404.php` | `php_error404` | 记录 404 访问 |

**log::le_log() 按月归档机制**:

```php
$day = date('Ym', $time);       // 按月份分目录: 202607
$logpath = LOG_PATH.'/'.$day;    // log/202607/
!is_dir($logpath) AND mkdir($logpath, 0777, true);  // 自动创建目录
```

#### 11.2.2 日志文件格式

**通用日志格式** (`log::write`):
```
<?php exit;?>2026-07-25 15:30:00  127.0.0.1  /index.php?index-index  [运行错误] : xxx
```
格式: `<?php exit;?> {时间}  {IP}  {URL}  {内容}`

**LeCMS 业务日志格式** (`log::le_log`):
```
<?php exit;?>	2026-07-25 15:30:00	127.0.0.1	/index.php?user-login	用户登录成功
```
使用 Tab 分隔各字段，通过 `<?php exit;?>` 防止日志文件被直接访问。

#### 11.2.3 日志目录结构

```
log/
  php_error.php          ← 错误日志（根目录）
  php_error404.php       ← 404 日志（根目录）
  php_trace.php          ← 跟踪日志（根目录）
  202604/                ← 按月份分目录
    error.php
    user_login.php
  202605/
    error.php
  202606/
    error.php
  202607/
    error.php
```

#### 11.2.4 日志清理

```php
// 方法1: 后台工具清理
// 后台 → 工具 → 清空日志

// 方法2: 代码清理
```
