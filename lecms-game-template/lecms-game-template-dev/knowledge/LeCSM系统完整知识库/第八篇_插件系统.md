## 42. 插件架构与加载流程

### 42.1 插件加载流程

```
1. 系统初始化 (core::init_start)
    ↓
2. 加载框架 (xiunophp.php)
    ↓
3. 加载核心类 (core.class.php)
    ↓
4. 扫描插件目录 (PLUGIN_PATH = lecms/plugin/)
    ↓
5. 解析每个插件的 conf.php
    ↓
6. 读取 plugin.inc.php 中的启用状态
    ↓
7. 按 rank 排序已启用插件
    ↓
8. 编译控制器/模型时注入 Hook
    ↓
9. 运行时执行编译后的代码
```

### 42.2 插件配置解析

```php
// core.class.php 中的 get_plugins()
public static function get_plugins($force = 0) {
    static $plugins = array();
    if(!empty($plugins) && !$force) return $plugins;

    if(!is_dir(PLUGIN_PATH)) return array();

    // 扫描插件目录
    $plugin_dirs = get_dirs(PLUGIN_PATH);

    // 加载插件配置
    $plugin_arr = is_file(CONFIG_PATH.'plugin.inc.php') ?
        (array)include(CONFIG_PATH.'plugin.inc.php') : array();

    foreach($plugin_dirs as $dir) {
        // 读取插件配置
        $cfg = is_file(PLUGIN_PATH.$dir.'/conf.php') ?
            (array)include(PLUGIN_PATH.$dir.'/conf.php') : array();

        // 支持多语言配置
        if(isset($_ENV['_config']['admin_lang']) &&
           is_file(PLUGIN_PATH.$dir.'/conf_'.$_ENV['_config']['admin_lang'].'.php')) {
            $cfg = (array)include(PLUGIN_PATH.$dir.'/conf_'.$_ENV['_config']['admin_lang'].'.php');
        }

        $cfg['rank'] = isset($cfg['rank']) ? (int)$cfg['rank'] : 100;

        // 分类插件
        if(empty($plugin_arr[$dir])) {
            $plugins['not_install'][$dir] = $cfg;
        } elseif(empty($plugin_arr[$dir]['enable'])) {
            $plugins['disable'][$dir] = $cfg;
        } else {
            $plugins['enable'][$dir] = $cfg;
        }
    }

    // 按 rank 排序
    _array_multisort($plugins['enable'], 'rank');
    _array_multisort($plugins['disable'], 'rank');
    _array_multisort($plugins['not_install'], 'rank');

    return $plugins;
}
```

## 43. 插件目录结构详解

### 43.1 目录结构总览

每个插件都是一个独立的目录，位于 `plugin/` 目录下。完整的插件目录结构如下：

```
plugin/{插件名}/
├── conf.php                      # 插件配置（必须）
├── install.php                   # 安装脚本（可选）
├── uninstall.php                 # 卸载脚本（可选）
├── lang_zh-cn.php                # 前台语言包（可选）
├── lang_en.php                   # 前台语言包英文版（可选）
├── lang_zh-cn_admin.php          # 后台语言包（可选）
├── lang_en_admin.php             # 后台语言包英文版（可选）
├── hook/                         # Hook 文件目录（可选）
│   ├── xxx_before.php
│   └── xxx_after.php
├── block/                        # Block 模块（可选）
│   └── block_xxx.lib.php
├── control/                      # 前台控制器（可选）
│   └── xxx_control.class.php
├── model/                        # 前台模型（可选）
│   └── xxx_model.class.php
├── view/                         # 前台模板覆盖（可选）
│   └── xxx.htm
├── lecms/                        # LeCMS 专用文件（可选）
│   ├── control/
│   │   └── xxx_control.class.php
│   ├── model/
│   │   └── xxx_model.class.php
│   └── block/
│       └── block_xxx.lib.php
├── admin/                        # 后台模块（可选）
│   ├── control/
│   │   └── xxx_control.class.php
│   ├── view/
│   │   └── xxx.htm
│   └── hook/
│       └── xxx_after.php
└── static/                       # 静态资源（可选）
    ├── css/
    │   └── style.css
    └── js/
        └── common.js
```

### 43.2 各目录作用说明

| 目录/文件 | 说明 | 是否必须 |
|-----------|------|----------|
| `conf.php` | 插件元数据和配置 | 必须 |
| `install.php` | 安装时执行的脚本（建表、初始化数据等） | 可选 |
| `uninstall.php` | 卸载时执行的清理脚本 | 可选 |
| `hook/` | 放置 Hook 文件，用于注入核心代码 | 可选 |
| `block/` | 放置 Block 类文件，提供前台数据调用标签 | 可选 |
| `control/` | 放置前台控制器，处理前台请求 | 可选 |
| `model/` | 放置前台数据模型 | 可选 |
| `view/` | 覆盖系统模板或提供插件模板 | 可选 |
| `lecms/` | LeCMS 框架专用目录，优先级高于 control/model/block | 可选 |
| `admin/` | 后台功能模块 | 可选 |
| `static/` | CSS、JS 等静态资源 | 可选 |
| `lang_*.php` | 多语言包文件 | 可选 |

### 43.3 文件命名规范

| 文件类型 | 命名规范 | 示例 |
|----------|---------|------|
| 控制器 | `{名称}_control.class.php` | `sitemap_control.class.php` |
| 模型 | `{名称}_model.class.php` | `stat_model.class.php` |
| Block | `block_{名称}.lib.php` | `block_links.lib.php` |
| 安装脚本 | `install.php` | - |
| 卸载脚本 | `uninstall.php` | - |
| 语言包 | `lang_{语言码}.php` | `lang_zh-cn.php` |
| 后台语言包 | `lang_{语言码}_admin.php` | `lang_zh-cn_admin.php` |

## 44. 五种插件类型详解

| 类型 | 特点 | 典型插件 | 关键文件 |
|------|------|---------|---------|
| **Tool** | 后台工具菜单 | le_batch_reg_user | conf.php + hook/admin_tool_control_after.php + 模板 |
| **Block** | 前台数据调用标签 | le_links | conf.php + block_xxx.lib.php |
| **Hook** | 修改核心行为 | le_rand_pic | conf.php + hook/*.php |
| **Control** | 独立控制器 | tool_sitemaps_pro | conf.php + xxx_control.class.php + 模板 |

## 45. 插件配置文件 conf.php

`conf.php` 是每个插件必须存在的配置文件，返回一个 PHP 数组，包含插件的元数据和配置信息。

### 45.1 配置项说明

```php
return array(
    // 基础信息
    'name'        => '插件名称',           // 显示名称（必须）
    'brief'       => '插件简介',           // 简短描述（必须）
    'description' => '详细描述...',        // 详细说明（可选）
    'version'     => '1.0.0',             // 当前版本号（必须）
    'cms_version' => '3.0.0',            // 兼容的 CMS 最低版本（必须）
    'update'      => '2022-12-16',        // 最后更新日期（必须）

    // 作者信息
    'author'      => '作者名',             // 作者名称（必须）
    'authorurl'   => 'https://...',       // 作者网站（可选）

    // 功能配置
    'setting'     => '',                  // 设置页URL（留空=无设置页）
    'rank'        => 100,                 // 加载优先级（越小越先加载）
);
```

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `name` | string | - | 插件显示名称，在后台插件列表中展示 |
| `brief` | string | - | 插件简要介绍，通常一句话 |
| `description` | string | - | 详细描述，可包含换行 |
| `version` | string | - | 插件版本号，语义化版本 |
| `cms_version` | string | - | 插件兼容的 LeCMS 最低版本 |
| `update` | string | - | 最后更新日期，格式 YYYY-MM-DD |
| `author` | string | - | 作者名称 |
| `authorurl` | string | - | 作者网站或个人主页 |
| `setting` | string | `''` | 设置页面的 URL 路径，留空表示插件没有设置页面 |
| `rank` | int | `100` | 插件加载优先级，数值越小越先加载 |

### 45.2 多语言配置

插件支持多语言配置，通过在插件根目录放置不同语言版本的 `conf.php` 来实现：

```php
// conf.php (默认)
return array('name' => 'My Plugin');

// conf_en.php (英文版)
return array('name' => 'My Plugin');

// conf_zh-cn.php (中文版)
return array('name' => '我的插件');
```

系统会根据后台设置的语言自动选择对应的配置文件：
```php
// core.class.php 中的加载逻辑
$admin_lang = $_ENV['_config']['admin_lang'];  // 如 'zh-cn'
$conf_file = PLUGIN_PATH.$dir.'/conf_'.$admin_lang.'.php';
if(is_file($conf_file)) {
    $cfg = (array)include($conf_file);
}
```

## 46. 插件状态管理

### 46.1 plugin.inc.php 状态文件

插件的启用/禁用状态存储在 `conf/plugin.inc.php` 文件中，该文件由系统自动管理：

```php
<?php
return array(
    // 已安装并启用的插件
    'le_links' => array(
        'enable' => 1,                    // 1=启用, 0=禁用
        'install_time' => 1670000000,     // 安装时间戳
    ),

    // 已安装但禁用的插件
    'le_rand_pic' => array(
        'enable' => 0,
        'install_time' => 1670000000,
    ),

    // 未安装的插件不会出现在此文件中
);
```

**状态说明：**

| 状态 | enable 值 | 说明 |
|------|-----------|------|
| 已安装并启用 | `1` | 插件已安装，Hook 和功能正常生效 |
| 已安装但禁用 | `0` | 插件已安装但不加载，Hook 不生效 |
| 未安装 | 不包含 | 插件文件存在但未安装，不加载 |

### 46.2 安装/卸载脚本

**安装脚本 (install.php)：**
```php
<?php
// plugin/{插件名}/install.php

// 执行数据库操作
$sql = "CREATE TABLE IF NOT EXISTS `{tabla_prefix}my_plugin_data` (
    `id` int(10) unsigned NOT NULL AUTO_INCREMENT,
    `name` varchar(255) NOT NULL DEFAULT '',
    `value` text NOT NULL,
    PRIMARY KEY (`id`)

// 执行 SQL
$pdo = new DbPdo();
$pdo->exec($sql);

// 初始化默认配置
// ...
```

**卸载脚本 (uninstall.php)：**
```php

// plugin/{插件名}/uninstall.php

// 清理数据库表（谨慎操作，通常只删数据不删表结构）
// $pdo->exec("DROP TABLE IF EXISTS `{tabla_prefix}my_plugin_data`");

// 清理配置数据
// $kv->delete('my_plugin_config');

```

### 46.3 插件生命周期

```
安装:  后台点击安装 → 执行 install.php → 写入 plugin.inc.php
       ↓
启用:  enable = 1 → 加载 conf.php → 按 rank 排序 → 注入 Hook
       ↓
运行:  编译时注入 Hook → 运行时执行编译后代码
       ↓
禁用:  enable = 0 → 不加载 Hook → 插件功能停止（配置保留）
       ↓
卸载:  后台点击卸载 → 执行 uninstall.php → 清除 plugin.inc.php 记录
```

**生命周期各阶段说明：**

| 阶段 | 操作 | 数据保留 |
|------|------|---------|
| 安装 | 执行 install.php，注册到 plugin.inc.php | 全部保留 |
| 启用 | enable=1，加载 Hook | 全部保留 |
| 禁用 | enable=0，不加载 Hook | 配置保留，Hook 不执行 |
| 卸载 | 执行 uninstall.php，移除注册 | 插件文件保留在磁盘 |

## 47. 插件系统详细分析

> 本节基于 LeCMS_Analysis.md 补充，对插件系统的核心机制进行深度解析。

### 47.1 插件发现与注册

**插件发现流程**:

```
core::get_plugins()
  │
  ├── 1. 扫描插件目录: PLUGIN_PATH = lecms/plugin/
  │   └── get_dirs() 获取所有子目录
  │
  ├── 2. 读取插件配置: plugin.inc.php
  │   └── 获取每个插件的 enable 状态
  │
  ├── 3. 遍历每个插件目录
  │   ├── 读取 conf.php（插件元数据）
  │   ├── 支持多语言: conf_{lang}.php
  │   └── 设置默认 rank = 100
  │
  ├── 4. 分类插件状态
  │   ├── not_install: 未在 plugin.inc.php 中注册
  │   ├── disable: enable = 0
  │   └── enable: enable = 1
  │
  └── 5. 按 rank 排序（升序，数字越小越优先）
      └── _array_multisort($plugins['enable'], 'rank')
```

**plugin.inc.php 状态文件格式**:

```php
<?php
return array(
    // 已安装并启用的插件
    'le_links' => array(
        'enable' => 1,
        'install_time' => 1670000000,
    ),

    // 已安装但禁用的插件
    'le_rand_pic' => array(
        'enable' => 0,
        'install_time' => 1670000000,
    ),

    // 未安装的插件不会出现在此文件中
);
```

### 47.2 启用/禁用/排序机制

**启用/禁用**:

| 操作 | 实现方式 | 效果 |
|------|---------|------|
| 启用 | `plugin.inc.php` 中 `enable = 1` | Hook 文件在编译时注入到目标文件 |
| 禁用 | `plugin.inc.php` 中 `enable = 0` | Hook 文件不注入，插件功能完全停止 |
| 全局禁用 | `config.inc.php` 中 `plugin_disable = 1` | 跳过所有插件查找，提升性能 |

**排序（rank）机制**:

```php
// get_plugins() 中的排序逻辑
$cfg['rank'] = isset($cfg['rank']) ? (int)$cfg['rank'] : 100;

// 按 rank 升序排列
_array_multisort($plugins['enable'], 'rank');
```

| rank 值 | 加载顺序 | 适用场景 |
|---------|---------|---------|
| 0-50 | 最先加载 | 基础设施插件（如编辑器、安全防护） |
| 50-100 | 中间加载 | 通用功能插件 |
| 100+ | 最后加载 | 业务特定插件 |

**rank 的实际影响**:
- 决定插件 Hook 的注入顺序
- 决定 `get_original_file()` 中插件的查找顺序（rank 小的先查找）
- 用于解决插件之间的依赖关系

### 47.3 Hook 注入机制深度解析

**编译时注入流程**:

```
process_hook($matches)
  │
  ├── 1. 检查插件是否被全局禁用
  │   └── $_ENV['_config']['plugin_disable'] == 1 → 返回空
  │
  ├── 2. 获取所有已启用插件（按 rank 排序）
  │   └── core::get_plugins()['enable']
  │
  ├── 3. 遍历每个已启用插件
  │   ├── 查找: plugin/{插件名}/{hook名称}
  │   └── 查找: plugin/{插件名}/hook/{hook名称}
  │
  ├── 4. 对找到的 Hook 文件执行 clear_code()
  │   ├── 去除 <?php exit;?> 标记
  │   ├── 去除 <?php ... ?> 标签
  │   ├── 去除 defined('ROOT_PATH') || exit; 安全检查
  │   └── 返回纯 PHP 代码
  │
  └── 5. 将所有 Hook 代码拼接到结果中
      └── 替换原文件中的 // hook xxx 注释行
```

**Hook 文件位置对照**:

| 位置 | 路径示例 | 说明 |
|------|---------|------|
| 插件根目录 | `plugin/le_links/user.login.php` | 直接放在插件根目录 |
| Hook 子目录 | `plugin/le_links/hook/user.login.php` | 放在 hook/ 子目录中 |

**编译前后对比**:

```php
// ==================== 编译前（源文件） ====================
// misc.func.php
function custom_login() {
    // hook user.login
    echo "默认登录逻辑";
}

// ==================== 编译后（runcache/misc.func.php） ====================
function custom_login() {
    // === 插件A的 user.login Hook 代码 ===
    echo "插件A的登录增强逻辑";
    // === 结束 ===

    // === 插件B的 user.login Hook 代码 ===
    echo "插件B的登录日志记录";
    // === 结束 ===

    echo "默认登录逻辑";
}
```

### 47.6 风险与治理

**风险 1: Hook 冲突**

| 风险描述 | 影响 | 解决方案 |
|---------|------|---------|
| 同一 hook 点多次注入 | 代码重复执行，可能导致逻辑错误 | 使用 rank 控制顺序，注意插件间协调 |
| Hook 代码中存在同名函数 | PHP 致命错误 | Hook 文件中的函数必须加唯一前缀 |
| Hook 执行顺序不确定 | 依赖顺序的插件可能出错 | 明确设置 rank 值，文档化依赖关系 |

**风险 2: 命名污染**

| 风险描述 | 影响 | 解决方案 |
|---------|------|---------|
| 全局函数与核心冲突 | 核心功能异常 | 所有函数加插件名前缀 |
| 全局变量覆盖 | 数据混乱 | 使用 `$插件名_变量名` 格式 |
| CSS/JS 类名冲突 | 前端样式混乱 | CSS 类名加插件名前缀 |

**风险 3: 兼容性**

| 风险描述 | 影响 | 解决方案 |
|---------|------|---------|
| 框架升级后 Hook 点变更 | 插件失效 | 插件标注兼容版本，升级后验证 |
| 数据库表结构变更 | 数据读写异常 | 使用 install.php 中的升级逻辑 |
| 模板标签变更 | 模板渲染异常 | 关注框架更新日志 |

**治理建议**:

1. **插件版本管理**: 在 `conf.php` 中明确声明 `cms_version` 兼容范围
2. **代码审查**: 插件发布前审查 Hook 代码和命名规范
3. **依赖声明**: 在 `conf.php` 的 `description` 中声明插件依赖
4. **测试覆盖**: 插件应包含基本的功能测试用例
5. **日志记录**: 使用 `log::le_log()` 记录插件关键操作

defined('ROOT_PATH') || exit;

function block_links($conf) {

public function list_arr($where, $orderby, $orderway, $start, $limit, $total) {
    // 反向查询优化
    if($start > 1000 && $total > 2000 && $start > $total/2) {
        $orderway = -$orderway;
        $newstart = $total - $start - $limit;
        if($newstart < 0) {
            $limit += $newstart;
            $newstart = 0;
        }
        $list_arr = $this->find_fetch($where, array($orderby => $orderway),
                                     $newstart, $limit);

                                     $start, $limit);
    }
