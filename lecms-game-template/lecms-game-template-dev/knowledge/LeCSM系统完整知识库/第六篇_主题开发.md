## 30. 主题切换机制

### 30.1 主题变量与环境变量

LeCMS 通过全局环境变量 `$_ENV['_theme']` 控制当前激活的主题：

```php
// 获取当前主题名称
$_ENV['_theme']  // 例: 'default', 'my_theme'

// 默认主题
$_ENV['_theme'] = 'default';
```

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `$_ENV['_theme']` | `'default'` | 当前前台主题名称 |
| `$_ENV['_view_diy']` | `FALSE` | 是否启用 DIY 模板功能 |

主题切换通常在以下场景触发：
- 后台「主题管理」页面手动切换
- 代码中直接赋值：`$_ENV['_theme'] = 'my_theme';`
- 移动端自动切换（见 30.3 节）

### 30.2 模板路径与编译路径

根据当前主题，系统动态生成两条关键路径：

**模板搜索路径（源文件）：**
```
VIEW_PATH . $_ENV['_theme'] . '/'
// 例: lecms/view/my_theme/
```

**编译缓存路径（PHP 文件）：**
```
RUNTIME_PATH . 'lecms_view/' . $_ENV['_theme'] . ','
// 例: lecms/runcache/lecms_view/my_theme,
```

路径中各常量的典型值：
```php
VIEW_PATH     // lecms/view/           - 模板源文件根目录
RUNTIME_PATH  // lecms/runcache/       - 编译缓存根目录
```

编译后的文件命名格式：
```
runcache/lecms_view/{主题名},{模板名}.php
// 例: runcache/lecms_view/my_theme,index_index.php
```

### 30.3 移动端自动切换

LeCMS 支持根据设备类型自动切换主题，需同时满足两个条件：

```php
// 条件1: 后台开启移动端视图功能
$_ENV['_config']['open_mobile_view'] = 1;

// 条件2: 当前请求来自移动设备
is_mobile()  // 通过 User-Agent 检测
```

检测逻辑（`core.class.php` 中）：
```php
if($_ENV['_config']['open_mobile_view'] && is_mobile()) {
    $_ENV['_theme'] = $_ENV['_config']['mobile_theme'];  // 移动端主题
}
```

| 配置项 | 说明 |
|--------|------|
| `open_mobile_view` | 是否启用移动端视图（0/1） |
| `mobile_theme` | 移动端主题名称 |

## 31. 模板文件查找优先级

### 31.1 查找流程详解

LeCMS 的 `view.class.php` 中的 `get_tplfile()` 方法定义了模板文件的查找顺序。系统按以下优先级逐级查找模板文件，找到即停止：

```
第 1 级 → 运行缓存中已编译的模板
路径: runcache/lecms_view/{主题名},{模板名}.php
说明: 编译后的 PHP 文件，直接 include

第 2 级 → 当前主题目录下的模板
路径: view/{主题名}/{模板名}.htm
说明: 用户自定义主题的源文件

第 3 级 → 插件目录下的模板（控制台）
路径: plugin/{插件名}/lecms/{模板名}.htm
说明: 插件提供的控制台相关模板

第 4 级 → 插件目录下的模板（通用）
路径: plugin/{插件名}/{模板名}.htm
说明: 插件提供的通用模板

第 5 级 → 默认主题目录下的模板
路径: view/default/{模板名}.htm
说明: 兜底模板，确保系统正常运行
```

**查找伪代码：**
```php
public static function get_tplfile($name) {
    $theme = $_ENV['_theme'];

    // 1. 运行缓存
    $tplfile = RUNTIME_PATH."lecms_view/{$theme},{$name}.php";
    if(is_file($tplfile)) return $tplfile;

    // 2. 当前主题
    $tplfile = VIEW_PATH."{$theme}/{$name}.htm";
    if(is_file($tplfile)) return $tplfile;

    // 3. 插件控制台模板
    foreach($GLOBALS['plugins'] as $plugin_name => $plugin) {
        $tplfile = PLUGIN_PATH."{$plugin_name}/lecms/{$name}.htm";
        if(is_file($tplfile)) return $tplfile;

        // 4. 插件通用模板
        $tplfile = PLUGIN_PATH."{$plugin_name}/{$name}.htm";
        if(is_file($tplfile)) return $tplfile;
    }

    // 5. 默认主题
    $tplfile = VIEW_PATH."default/{$name}.htm";
    if(is_file($tplfile)) return $tplfile;

    return FALSE;
}
```

### 31.2 插件模板覆盖机制

插件可以通过提供同名模板文件来覆盖系统默认模板，这一机制的核心是查找优先级高于默认主题：

```php
// 当系统需要 article_show.htm 时:
// 先查: view/my_theme/article_show.htm
// 再查: plugin/le_seo/article_show.htm   ← 插件可覆盖
// 最后: view/default/article_show.htm
```

**注意事项：**
- 插件模板优先于默认主题，但低于当前激活主题
- 插件提供的模板位于 `plugin/{插件名}/` 目录下
- 如果当前主题已包含该模板，插件模板不会被加载
- 可通过卸载/禁用插件来恢复默认模板

## 32. 前端样式体系

### 32.1 样式框架架构

LeCMS 采用**多框架混合**的前端样式架构：

| 区域 | 框架 | 版本 | 位置 |
|------|------|------|------|
| **后台管理** | Layui + LayuiMini | 2.8.15 | `static/layui/` |
| **前台主题** | Bootstrap | 3.3.7 | `view/*/style/` |
| **编辑器** | UEditor | - | `static/js/umeditor/` |
| **轮播图** | Swiper.js | 8.4.5 | `view/*/script/` |
| **图标** | Font Awesome | 4.7.0 | `static/layui/lib/font-awesome/` |

### 32.4 CSS 类命名规范

LeCMS 采用 **BEM 风格**的变体命名法，以 `lecms-` 为统一前缀：

```css
/* 模块-功能 格式 */
.lecms-navbar           /* 导航栏组件 */
.lecms-navbar-brand     /* 导航栏品牌 */
.lecms-navbar-toggle    /* 导航栏切换按钮 */

.lecms-article-list     /* 文章列表 */
.lecms-article-item     /* 文章列表项 */
.lecms-article-title    /* 文章标题 */

.lecms-comment-form     /* 评论表单 */
.lecms-comment-list     /* 评论列表 */
.lecms-comment-item     /* 评论项 */

.lecms-sidebar          /* 侧边栏 */
.lecms-sidebar-block    /* 侧边栏区块 */

.lecms-pagination       /* 分页组件 */
.lecms-btn              /* 按钮 */
.lecms-form-group       /* 表单组 */
.lecms-modal            /* 模态框 */
```

**命名规则：**
- 前缀：`lecms-`
- 模块名：英文，小写，连字符分隔
- 功能名：英文，小写，连字符分隔
- 完整格式：`lecms-{module}-{function}`

### 32.5 响应式断点

前台基于 Bootstrap 3.3.7 的 12 列栅格系统，响应式断点如下：

| 断点 | 最小宽度 | 设备类型 | 说明 |
|------|----------|---------|------|
| xs | 0px | 手机 | 超小屏幕，默认样式 |
| sm | 768px | 平板 | 小屏幕，`@media (min-width: 768px)` |
| md | 992px | 桌面 | 中等屏幕，`@media (min-width: 992px)` |
| lg | 1200px | 大屏 | 大屏幕，`@media (min-width: 1200px)` |

**栅格系统使用示例：**
```html
<!-- 手机占满，平板占半，桌面占 1/3 -->
<div class="col-xs-12 col-sm-6 col-md-4">
    ...
</div>
```

**隐藏/显示控制：**
```css
/* 手机隐藏，平板以上显示 */
.lecms-sidebar { display: none; }
@media (min-width: 768px) {
    .lecms-sidebar { display: block; }
}
```

## 33. 模板命名规范

LeCMS 采用**下划线分隔**的模板文件命名方式，通过文件名即可判断模板的用途和所属模块。

### 33.1 页面模板

格式：`{control}_{action}.htm`

| 模板文件 | 对应控制器 | 对应方法 | 说明 |
|----------|-----------|----------|------|
| `index_index.htm` | index_control | index() | 首页 |
| `index_tag.htm` | index_control | tag() | 标签页 |
| `article_show.htm` | article_control | show() | 内容详情 |
| `article_model.htm` | article_control | model() | 模型页 |
| `cate_index.htm` | cate_control | index() | 分类列表 |
| `cate_list.htm` | cate_control | list() | 分类内容列表 |
| `tag_list.htm` | tag_control | list() | 标签内容列表 |
| `tag_top.htm` | tag_control | top() | 标签排行 |
| `search_index.htm` | search_control | index() | 搜索入口 |
| `search_list.htm` | search_control | list() | 搜索结果列表 |
| `user_index.htm` | user_control | index() | 用户空间 |
| `user_login.htm` | user_control | login() | 用户登录 |
| `comment_index.htm` | comment_control | index() | 评论分页 |

### 33.2 包含模板

格式：`inc-{名称}.htm`

包含模板（Include Template）用于在多个页面间复用公共片段，通常放置在主题根目录或 `user/` 子目录中。

| 模板文件 | 用途 |
|----------|------|
| `inc-header.htm` | 公共 `<head>` 和顶部导航 |
| `inc-footer.htm` | 公共底部和版权信息 |
| `inc-sidebar.htm` | 侧边栏 |
| `inc-menu.htm` | 用户中心菜单 |

**包含模板引用方式：**
```php
<?php include VIEW_PATH.$_ENV['_theme'].'/inc-header.htm'; ?>
```

## 一、系统概述

### 1.1 模板引擎特性

该CMS系统使用自研的**XiunoPHP模板引擎**，采用编译型模板方式，将模板文件编译为PHP缓存文件后执行。

**核心特点：**
- 编译型模板：模板文件编译为PHP缓存，提升性能
- 标签解析：支持自定义标签语法
- Block模块：可复用的数据块
- Hook支持：模板中支持插件钩子
- 缓存机制：模板缓存和数据缓存分离
- 程序框架：采用懒加载、分布式服务器的设计，每张表都可有自己的DB服务器群和CACHE服务器(群)，单表能承受亿级数据
- 安全高效：基于开源框架XIUNOPHP开发，邀请"乌云漏洞平台"、"被黑站点统计平台"的专业白帽子审计程序代码
- 插件扩展：采用基于开源XIUNOPHP框架的AOP插件机制，性能方面零损耗，可自由扩展程序功能
- 轻量级CMS：简洁精干，注重实用性，主程序只做最核心功能，其它通过插件实现
- SEO优化：内置多种SEO设置，对网站URL路径设置自由度极高
- 后台框架：使用基于Layui编写的一套简洁易用的后台框架layuimini，响应式设计
- MIT协议：您可以自由修改、派生版本、商用而不用担心任何法律风险

### 2.3 静态资源引入

**如何在主题htm文件里面引入css下面的文件？图片、js同理！**

```html
<!-- 引入CSS文件 -->
<link rel="stylesheet" href="{$cfg[tpl]}css/style.css">

<!-- 引入JS文件 -->
<script src="{$cfg[tpl]}js/common.js"></script>

<!-- 引入图片 -->
<img src="{$cfg[tpl]}img/logo.png" alt="Logo">
```

**注意：** inc引入的文件，文件名不能用 `-` ，可以用 `_`

```html
<!-- 正确 -->
{inc:sidebar_tags.htm}

<!-- 错误 -->
{inc:sidebar-tags.htm}
```

## 三、如何创建新主题

### 3.1 创建目录

假如你要建立一套主题，文件夹名abc，名字"abc主题"。

1. 在 `view` 文件夹下建立 `abc` 文件夹

### 3.2 创建 info.ini

建立一个 `info.ini` 文件，用来描述主题：

```ini
#模版信息
name=abc主题
brief=主题的一些特点
version=主题版本号
update=主题开发日期
author=主题作者
authorurl=主题作者的链接
```

### 3.3 创建 show.jpg

建立一个 `show.jpg` 图片，用于后台预览主题，建议 235*160 px。

### 3.4 启用主题

有了这两个文件后，就能在后台 **"插件主题" → "主题管理"** 预览和启用你当前建立的主题啦！

### 35.1 启用 DIY 模式

LeCMS 提供了 DIY（Do It Yourself）模板功能，允许在后台通过可视化方式调整页面模板中 Block 的位置和内容。启用方式：

```php
// 在 conf/conf.php 或运行时设置
$_ENV['_view_diy'] = TRUE;
```

启用后，前台页面会在特定标记位置显示可拖拽编辑的 Block 区块。

### 35.2 Block 标记语法

在模板文件中使用 `block_diy` 属性标记可编辑区域：

```html
<span block_diy="before" block_id="1"></span>
<span block_diy="after" block_id="2"></span>
```

**标记属性说明：**

| 属性 | 值 | 说明 |
|------|----|------|
| `block_diy` | `before` / `after` | 标记位置：在目标元素之前或之后 |
| `block_id` | 数字 | Block 的唯一标识，用于存储位置信息 |

**使用示例：**
```html
<!-- 在文章列表上方插入可拖拽 Block -->
<span block_diy="before" block_id="1"></span>
<div class="lecms-article-list">
    <!-- 文章列表内容 -->
</div>

<!-- 在文章列表下方插入可拖拽 Block -->
<span block_diy="after" block_id="2"></span>
```

### 35.3 可视化编辑

启用 DIY 模式后，后台提供可视化编辑界面：

1. **拖拽排序**：管理员可在后台拖拽调整 Block 的排列顺序
2. **Block 管理**：添加、删除、编辑 Block 内容
3. **位置持久化**：Block 的位置信息存储在数据库中，前端渲染时读取
4. **前端预览**：前台实时反映 Block 排列变化

**注意事项：**
- DIY 标记（`<span block_diy="...">`）仅在 `$_ENV['_view_diy']` 为 `TRUE` 时生效
- 标记本身不产生可见内容，仅作为插入点
- Block 内容由后台管理，与模板文件分离
- 适合用于首页轮播图、广告位、推荐内容等灵活配置区域
