## 二、审计发现（按严重度分级）

### P0 · 致命（直接导致不收录或收录异常）

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| **P0-1** | **sitemap 中 60 条 URL 未做 percent-encode** | `<loc>...char.html?c=林</loc>`（应为 `?c=%E6%9E%97`），占全部 URL 的 **56%** | 违反 sitemap 协议，百度站长平台/校验工具判为无效 URL → **60 个长尾单字落地页无法进入索引** |
| **P0-2** | **工具页内容依赖 JS 渲染（CSR）** | 无 JS 时：字库页仅剩 120 字（**丢失 98%**）、百家姓 62 字（97%）、单字/名字/姓氏页 36 字（94-97%） | 百度爬虫 JS 执行能力弱 → 18 个工具页（流量主力）可能被抓到空壳，不收录或严重降权 |

### P1 · 高（显著影响收录质量与点击率）

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| **P1-1** | **全站 15/15 页面无 canonical** | 审计 15 页全部缺失 | 带参 URL（`char.html?c=X` / `mingzi.html?name=X` / `surname.html?c=X`）易被判为重复页，只收录一个、其余折叠 |
| **P1-2** | **17 个工具页无 H1**（主标题用 `<div class="bh">`） | score / kxzd / baijiaxing / naming / mingzi / shijing 等 H1 数为 0 | 搜索引擎无法识别页面主题，标题层级断裂 |
| **P1-3** | **24 篇文章 `seo_description` 字段全空** | `SELECT COUNT(*) ... = 0` | 所有文章页共用 16 字摘要作为 meta description，搜索结果摘要信息量极低、点击率受损 |
| **P1-4** | **栏目页 description 为 13 字模板文案** | "八字起名相关原创资讯与知识" | 4 个栏目页描述雷同且无信息量 |
| **P1-5** | **工具页 OG 标签缺失** | 8/15 页面无 `og:title` | 社交分享无预览卡片 |

## 三、已实施修复（含前后对比）

### 1. sitemap 协议合规（P0-1）

`gen_sitemap.py` 对中文参数加 `quote(c, safe='')`，重新生成：

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 未编码非 ASCII URL | 60 条 | **0 条** |
| 抽样可达性 | 6/12 失败 | **13/13 成功** |

### 2. canonical 全站注入（P1-1）

main.7.js 新增 `injectCanonical()`，字符串方式剔除 sharecode——**刻意不用 URLSearchParams**，因为它会把 PHP 的无等号 query `?show--cid-1-id-1.html` 错误重序列化成 `...html=`，导致 canonical 与实际 URL 不一致。

验证：首页 `/`、文章 `/index.php?show--cid-4-id-21.html`、单字 `char.html?c=%E6%9F%8F`、名字 `mingzi.html?name=...` 各自独立且正确。

### 3. H1 补齐（P1-2）

17 个工具页 `<div class="bh">` → `<h1 class="bh">`（CSS 已含 `.ink-banner h1` 同款规则，**零视觉变化**）；`naming.html`（带 id 属性）与 `shijing` 单独处理；`mingzi` 详情页补 JS 渲染的 H1。

### 4. 静态内容层注入（P0-2 缓解）

为 18 个工具页在 `.page-body` 后注入**不依赖 JS** 的内容区块（H2 使用说明 2 段 + H2 相关推荐 6 条链接）：

| 页面 | 无 JS 可见文字（前 → 后） | 提升 |
|------|--------------------------|------|
| 字库页 | 120 → **365 字** | +204% |
| 百家姓 | 62 → **274 字** | +342% |
| 起名页 | 300 → **519 字** | +73% |
| 打分页 | 449 → **678 字** | +51% |

同时每个页面在无 JS 时都具备 **H1 + 12-16 条可爬行链接**，保证爬虫能识别主题并继续发现全站。

### 5. TDK 与 OG 重写（P1-3/4/5）

- 20 个工具页：重写 title / description / keywords，补 OG 四件套
- 24 篇文章：撰写专业 `seo_description`，**从 0 条填充到 24/24，长度 71-93 字（平均 86 字）**
- 4 个栏目：撰写 `seo_description`，**从 13 字提升到 57 字**

> 关键排查点：栏目 description 写入数据库后一度未生效，追踪发现 LECMS 栏目数据走 `runtime` 缓存（`lecms_runtime` 表 `cate_1..4`），清除后重建即生效。

|------|--------|--------|
| canonical 覆盖 | 0 / 15 | **15 / 15** |
| H1 存在性 | 9 / 15 | **15 / 15** |
| OG 覆盖 | 7 / 15 | **15 / 15** |
| 文章 meta description | 16-25 字 | **71-93 字**（24/24 达标） |

## 四、剩余风险与后续方案

### 1. 动态参数落地页的收录（P2-2，最高优先级）

`char.html?c=X`（60 个高频字在 sitemap 中）、`surname.html?c=X`（408 姓氏）、`mingzi.html?name=X` 的内容完全由参数决定，**无法预写静态内容**。

方案（按推荐度排序）：

| 方案 | 说明 | 成本 |
|------|------|------|
| **A. 预渲染（prerender）** | 服务端识别爬虫 UA（Baiduspider / Googlebot）时返回渲染后的完整 HTML，普通用户仍走原页面 | 中，需在 PHP 入口或反代层加 UA 判断 + 快照缓存 |
| B. 静态化高频参数页 | 为 sitemap 中的 60 个高频字 + Top 100 姓氏生成静态 HTML | 中，需构建脚本 |
| C. 依赖 sitemap + 内链 | 现状：已提交 sitemap，且站内大量链接指向这些页面 | 低，但百度可能只抓到空壳 |

**建议先做 A**，覆盖面最广。

### 2. 首屏性能（P2-1）

- JS 555KB → 建议 `shuowen.7.js`（全量说文库）与 `strokes-full.7.js` 改为**按需懒加载**（目前 `loadShuowenFull` 已经是懒加载，可确认是否首屏仍加载了其余大文件）
- 确认线上是否启用 gzip/brotli 与静态资源缓存头

### 3. meta description 补齐（P2-3）

首页与 18 个工具页描述为 44-58 字，建议补至 70-95 字，与文章页保持一致的信息密度。

## 五、提高收录的行动计划

### 立即可做（0-1 周）

1. **提交 sitemap**：百度搜索资源平台 + Google Search Console 各提交一次 `sitemap.xml`
2. **主动推送**：百度「普通收录」API 推送本次新增/更新的 URL（24 篇文章 + 60 单字页 + 21 工具页）
3. **验证索引**：`site:` 语法 + 站长平台索引覆盖率报告，确认工具页是否被收录

### 短期（2-4 周）

4. **实施 prerender**（方案 A），重点覆盖 char / surname / mingzi 三类参数页
5. **补齐剩余 description**，统一信息密度
6. **内容持续更新**：每周新增 2-3 篇长文（800 字以上），新内容发布后即从相关工具页引用 1-2 处

### 中期（1-3 月）

7. **监控搜索表现**：建立索引量、展现量、点击率的周度记录；重点观察工具页是否被收录
8. **关键词布局复盘**：检查是否有多页竞争同一关键词（如 shici 与 poems 标题接近），必要时差异化
9. **外链与品牌**：起名类内容天然有分享属性，配合 OG 卡片提升社交传播

## 六、审计结论

**当前状态**：技术基础已从「有多处致命缺陷」修复到「符合主流收录要求」——sitemap 合规、canonical 完备、H1 与 OG 齐全、24 篇文章具备高质量独立描述、工具页具备静态可抓取内容。

**最大剩余风险**：`char / surname / mingzi` 三类动态参数页仍依赖 JS 渲染，是下一阶段决定「工具页能否被百度收录」的关键变量，建议优先实施预渲染方案。

**优先级排序**：P0 已解决 → 提交与推送（立即）→ prerender（2-4 周）→ 性能与描述补齐（并行）。
