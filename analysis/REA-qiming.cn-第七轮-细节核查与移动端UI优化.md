## 一、移动端 UI 发现的问题与优化（本轮重点）

### 1. 🔴 Header 移动端拥挤混乱（已修复）
- **现象**：热门字/名直达链（柏/棋/梓晴/宇轩）在 375px 下换行成两行撑爆 header，
  LOGO 副标题"智能起名 · 内容平台"也折行，顶部区域杂乱。
- **修复**：移动端隐藏 `.hot-quick` 热链与 LOGO 副标题、header 高度 66→52px 紧凑单行
  （原站移动端 header 同样只有 LOGO + 搜索，无热链）。

### 2. 🔴 详情页 hero 布局塌陷（已修复，重大）
- **现象**：strip-hero 在移动端仍是桌面"文字 1fr + 字形 150px"双列——文字列仅 191px，
  导致标题折成 3-4 行（"意/义"单字悬挂）、两个按钮挤成竖排。
- **根因**：又是 860px 媒体查询（文件前部）被后置基础定义（371 行）层叠覆盖，
  与第六轮发现的 `.layout` 是同一类 bug；本轮一并修复 `.strip-hero` 与 `.col-side`。
- **修复**：760px 断点内强制单列居中。修复后标题 2 行、按钮并排等宽（166px×2）。

### 3. 🔴 名字详情六维评分条被压扁（已修复）
- **现象**：双列评分在 375px 下每列仅 ~160px，进度条短至 30px。
- **修复**：移动端改单列，进度条全宽（约 200px），可读性大幅提升。

### 4. 🔴 百家姓/字库卡片密度过低（已修复）
- **现象**：百家姓卡片移动端单列全宽，一屏只显示 1-2 个姓。
- **修复**：百家姓 3 列紧凑网格（排名换行显示）、汉字字库 2 列，一屏可见 6-9 项。

### 5. iOS 规范细节（已优化）
- 表单输入框 font-size 15→16px（**防 iOS Safari 聚焦自动放大**）
- CTA 按钮并排等宽 + nowrap、rel-chars 关联字触摸目标 42→44px
- 详情页大字号名字 44→38px、attr-table 行距压缩、tool-intro 内边距收紧
